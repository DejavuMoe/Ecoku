# 工作原理

这一页解释 Ecoku 的几个核心规则：评论怎样归到文章下、回复怎样组织、访客身份怎样保存，以及哪些数据会公开。部署和接入时遇到的大部分「为什么」都能在这里找到答案。

## 站点与页面 key {#page-key}

每条评论属于某个站点里的某个页面，由两个值确定：

| 值 | 来自 | 例子 |
| --- | --- | --- |
| 站点 ID `siteId` | 在后台登记网站时设定 | `blog` |
| 页面 key `pageKey` | 接入代码传入，通常是文章路径 | `/posts/hello-world/` |

同一站点下页面 key 相同的页面共用一个评论区。页面 key 是站内路径，最长 512 个字符，不要写成完整 URL，也不要带 `?` 或 `#`，否则评论区能显示，但提交评论会被拒绝。

::: warning 页面 key 定下来就不要改
评论按页面 key 保存。改了博客的永久链接格式，旧文章生成的页面 key 跟着变，原来的评论就不显示了（数据还在）。把接入代码改回原来的生成方式，评论就会回来。
:::

## 讨论串与分页 {#threads}

评论是一棵树：根评论下有回复，回复下还能再回复。

- 根评论算第 0 层，回复最多到第 16 层。第 16 层的评论没有「回复」按钮。
- 缩进到第 3 层为止。从第 3 层起，昵称后显示 `@被回复者`，指向它回复的那条评论。
- 有回复的评论旁边有 `[-]`，点击折叠整个分支。

分页只按根评论分：每页若干条根评论（默认 10 条），连同下面的全部回复一起显示。

单次读取有上限：200 条评论、16 层、1 MiB 响应；统计时同一页面最多检查 10,000 条。超过时评论区显示加载失败，而不是只显示一部分。一般博客碰不到这些上限；碰到时减小每页根评论数，或在自定义前端里使用 [逐层读取接口](./api#cursor)。

## 删除 {#deletion}

| | 墓碑删除 | 彻底删除 |
| --- | --- | --- |
| 结果 | 清空昵称、邮箱、网址和正文，保留位置 | 从数据库移除 |
| 条件 | 任意评论 | 只限没有任何回复的墓碑 |
| 下面的回复 | 照常显示 | — |

两种都不能撤销。操作方法见 [处理评论](../admin/comments)。

## 访客身份 {#visitor-identity}

| 字段 | 必填 | 公开 |
| --- | --- | --- |
| 昵称 | 必填，最多 80 个字符 | 公开 |
| 邮箱 | 默认必填，可改为选填 | 不公开，只用于通知 |
| 网址 | 默认选填，只接受 `http(s)://` | 公开，显示为昵称上的链接 |

点某条评论的「回复」时，缺少的身份信息就在这个回复框里补填，不会跳回顶部的评论框。

发布成功后，浏览器会在本地记住这组身份 7 天：

- 保存在 IndexedDB 中，用不可导出的 AES-GCM 密钥加密，不写入 Cookie、localStorage 或 URL；
- 按 Ecoku 服务地址和站点 ID 分开保存；
- 过期或不可用时，评论框回到空白，不影响发言；
- 清除浏览器的网站数据就能清除它。

## 博主身份 {#blogger}

博主通过在昵称栏填口令发言，服务端认出口令后用站点设置的博主信息保存这条评论，并写入博主标记。标记在保存时确定，之后不再重新计算。设置方法见 [博主身份](../admin/blogger)。

## 纯文本

评论正文和昵称一律按纯文本显示：HTML 原样显示为文字，不渲染 Markdown，网址不自动变成链接，换行保留。

唯一的例外是 [Smoji 表情](../integration/smoji)：站点启用后，符合格式和图片来源规则的 `![smoji:名称](图片地址)` 显示为图片。

访客网址只出现在昵称的链接上，带 `rel="nofollow ugc noopener noreferrer"`。

## 保存和公开的数据 {#data}

| | 内容 |
| --- | --- |
| 数据库保存 | 站点 ID、页面 key、文章标题、父评论、昵称、邮箱、网址、正文、博主标记、删除时间、创建和更新时间 |
| 公开接口返回 | 评论 ID、站点 ID、页面 key、父评论 ID、昵称、网址、正文、是否博主、是否已删除、时间 |
| 不保存 | 访客 IP、User-Agent、地理位置 |

邮箱不会出现在任何公开接口里。连接 IP 只在内存中短暂用于限流，重启即清空，日志里也没有。

访客浏览器只在两种情况下直接连接第三方：启用了 Turnstile 或 Cap 时加载验证组件；启用了 Smoji 时从清单和图片所在的服务器加载资源。

## 来源检查与限流 {#origins}

每个站点在后台登记「允许来源」。浏览器从其他来源读取评论会被拒绝，提交评论必须带有已登记的来源，所以评论区只能用在你登记过的网站上。

提交、读取、删除和后台登录都按 IP 限流，默认每分钟 5 次提交、60 次读取。放在反向代理后面时要配置 [`trusted_proxies`](../self-hosting/reverse-proxy#trusted-proxies)，否则所有访客共用一个额度。

## 时间与时区

评论时间显示为 `YYYY-MM-DD HH:mm`，时区由 Compose 里的 `TZ` 决定，见 [时区与后台语言](../self-hosting/docker#timezone)。鼠标悬停在时间上可以看到时区。
