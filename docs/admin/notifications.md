# 通知

有新评论时，Ecoku 可以发邮件或 Telegram 消息给你；访客的评论被人回复时，Ecoku 会发邮件告诉这位访客。在后台「通知」页设置，对所有站点生效。

<div class="page-meta">
<div>

**你会完成**

- 新评论发到你的邮箱或 Telegram
- 访客被回复时收到邮件

</div>
<div>

**开始之前**

- `app/config.yaml` 里填了 `notifications.instance_public_url`
- 服务器能连上 SMTP 端口（465 / 587）或 `api.telegram.org`

</div>
</div>

## 电子邮件 {#email}

在「通知」页填写 SMTP 信息：

| 字段 | 说明 |
| --- | --- |
| SMTP 服务器 | 例如 `smtp.example.com` |
| 端口 / 加密方式 | 465 配 `SSL/TLS`，587 配 `STARTTLS`。不支持不加密的连接。 |
| 用户名 | 留空则不做 SMTP 认证 |
| 密码 | 必填。保存后不再显示，留空表示不修改。 |
| 发件人地址 | 邮件的 From。很多服务商要求和登录账号一致。 |
| 通知收件人 | 接收新评论通知的邮箱，可以填多个 |

点「发送测试邮件」，它直接用表单里的值发信，不需要先保存。收到后再保存。

邮件主题是这样的：

- 「您在 [站点名称] 上有新评论：[文章标题]」
- 「您在 [站点名称] 上有新回复：[文章标题]」
- 给访客的：「你在 [站点名称] 的评论收到了回复：[文章标题]」

邮件里有文章标题、时间、评论人、正文和文章链接，回复通知还附上被回复的评论。发件人显示名是站点名称。

## Telegram {#telegram}

Telegram 只通知你，不通知访客。

<div class="steps">

### 创建机器人

找 [@BotFather](https://t.me/BotFather) 创建一个机器人，拿到 Bot Token。

### 让机器人能给你发消息

私聊的话，先给机器人发一条消息。群组或频道要把它拉进去，频道还要设为管理员。

### 填写并测试

在后台填入 Token 和接收方的数字 ID（个人是一串数字，群组和频道通常以 `-100` 开头；不支持 `@用户名`）。点「发送测试消息」，收到后保存。

</div>

## 什么时候发 {#when}

「博主」指用 [博主口令](./blogger) 发布的评论。

| 谁做了什么 | 通知你 | 邮件通知被回复的访客 |
| --- | :---: | :---: |
| 访客发表评论 | ✓ | — |
| 访客回复访客 | ✓ | ✓ |
| 访客回复你 | ✓ | — |
| 你发表或回复 | — | 回复访客时 ✓ |

被回复的访客没留邮箱、自己回复自己，或者邮件渠道没启用时，不给访客发邮件。

## 发送与重试

通知不在提交评论时同步发送，而是进入队列，后台每 3 秒取一批。邮件服务器暂时连不上，不影响访客发评论。

- 每个收件人单独发送、单独重试。
- 失败后间隔 2、4、8 … 128 分钟重试，最多 8 次。
- 地址不存在、被拒收、机器人被移出这类永久错误不再重试。
- 极少数情况下（进程恰好在发出后崩溃）可能重复收到一次。

日志只记录通知编号和错误类型，不记录收件地址、评论内容或密码。

## 删除评论之后 {#after-deletion}

在后台删除一条评论后：

- 与它有关、还没发出的通知不再发送；
- 以后有人回复它，不会再给它的作者发邮件；
- 已经发出的 Telegram 消息会被改写为「这条评论已被删除，通知内容已移除。」；
- 已经发出的邮件无法撤回。

通知记录保留 30 天，超过后已发出的 Telegram 消息就无法再改写。

## 常见问题 {#troubleshooting}

**启用时提示「请求参数不符合要求，请检查后重试。」**
多半是 `app/config.yaml` 里没填 `notifications.instance_public_url`。填好后重建容器。

**测试邮件超时**
通常是云服务商封了 SMTP 出站端口。在服务器上运行 `nc -vz smtp.example.com 465` 看能否连通，再确认端口和加密方式对得上。

**容器启动失败，日志提示「通知凭据校验失败」**
SMTP 密码等凭据用 `data/ecoku-secrets.json` 里的密钥加密。确认它和数据库来自同一份备份，权限为 `600`。不要删掉它，见 [备份与恢复](../self-hosting/backup#restore)。
