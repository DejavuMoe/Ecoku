# 通知

Ecoku 可以在有新评论时通知博主，在访客的评论被回复时发邮件告诉对方。通知设置在后台「通知」页，对整个实例的所有站点生效。

修改渠道设置后，在底部保存栏点击「保存」。邮件和 Telegram 分别校验、分别保存；一个渠道有错误时，另一个有效渠道仍可保存，尚未保存的修改会留在原页。

| 渠道 | 发给谁 |
| --- | --- |
| 电子邮件（SMTP） | 博主：发往你填写的收件人列表。访客：发往被回复评论留下的邮箱。 |
| Telegram 机器人 | 只发给博主：发往你填写的用户、群组或频道 ID。 |

## 启用前的准备

- `app/config.yaml` 中已填写 `notifications.instance_public_url`，否则无法启用任何渠道，也无法发送测试。
- 新实例会自动在 `data/ecoku-secrets.json` 创建通知加密主密钥。旧实例迁移期间仍可从 `ecoku.env` 读取 `ECOKU_NOTIFICATION_ENCRYPTION_KEY`，迁移完成后可以停服备份并删除它。
- 服务器能访问外部的 SMTP 端口（常见 465 或 587）或 `api.telegram.org`。部分云服务商默认封锁 SMTP 出站端口。

## 什么时候发通知

是否是「博主」，看的是评论保存时记录的博主标记，也就是这条评论是否用[博主口令](./admin#blogger)发布。

| 场景 | 通知博主（邮件 / Telegram） | 邮件通知被回复的访客 |
| --- | :---: | :---: |
| 访客发表根评论 | 发送 | — |
| 访客回复访客 | 发送 | 发送 |
| 访客回复博主 | 发送 | — |
| 博主发表根评论 | 不发送 | — |
| 博主回复访客 | 不发送 | 发送 |
| 博主回复博主 | 不发送 | — |

另外：

- 被回复的访客没有留邮箱，或者回复者与被回复者邮箱相同（自己回复自己），不发访客邮件。
- 被回复的评论在通知发出前已被删除，访客邮件会取消。
- 评论本身在通知发出前被删除，发给博主的邮件和 Telegram 消息也会取消。已经发出的通知见[删除评论之后](#after-deletion)。
- 访客回复通知只在邮件渠道启用时发送，没有单独的开关。关闭邮件渠道后，访客回复通知也不再发送。
- Telegram 不会通知访客。

## 电子邮件

| 字段 | 说明 |
| --- | --- |
| SMTP 服务器 | 如 `smtp.example.com`。 |
| 端口 | 按邮件服务商要求填写，常见为 465（SSL/TLS）或 587（STARTTLS）。 |
| 加密方式 | `SSL/TLS`：连接时即加密；`STARTTLS`：先建立普通连接再升级。不支持不加密的 SMTP。 |
| 用户名 | 可留空，留空时不进行 SMTP 认证。密码仍然必填，不需要认证的服务器可以填任意值。 |
| 密码 | 保存后输入框显示「已设置，输入新值以更换」，留空表示不修改。 |
| 发件人地址 | 邮件的 From 地址。很多服务商要求它与登录账号一致。 |
| 通知收件人 | 接收博主通知的邮箱，每个邮箱一个输入框，可填多个。按 Enter 新增下一项，也可以一次粘贴多行或用逗号分隔的多个地址。 |

「发送测试邮件」用当前表单中的值（密码留空则用已保存的密码）给收件人发一封测试邮件，不需要先保存。失败时页面会给出原因，比如连接超时、认证未通过或 TLS 握手失败。

邮件同时包含纯文本和 HTML 两个版本。HTML 版与评论区、管理后台使用同一套纸墨配色，文字使用收件设备自带的中英文无衬线字体，不加载网络字体；支持深色模式的邮件客户端会自动切换为深色。页眉的 Ecoku 印章作为内嵌图片随邮件一起发送，不从网络加载；邮件客户端不显示图片时，页眉仍有文字「Ecoku」。内容按类型不同：

- 博主收到新评论：文章标题、发布时间、评论人与评论正文，以及「查看原文」链接；
- 博主收到新回复：文章标题、发布时间、被回复的评论、回复人与回复正文，以及「查看原文」链接；
- 访客收到回复：文章标题、回复时间、访客自己的评论、回复正文，以及「查看回复」链接。

时间按容器的 `TZ` 显示，与评论区一致，并注明时区偏移，如 `2026/09/29 10:18 (UTC+8)`。博主本人的评论在昵称后显示站点设置的博主标志。

表情包只在站点已启用表情包、且图片符合站点的图片来源规则时显示为图片。默认使用清单来源，也可以[单独配置图片来源](../integration/smoji#hosting)。图片从资源服务器直接加载，与评论区相同；邮件客户端拦截外部图片时显示为 `[表情：标签]`。其他情况以及纯文本版本中都显示为 `[表情：标签]`。

邮件主题：

- 博主通知：「您在 [站点名称] 上有新评论：[文章标题]」 或 「您在 [站点名称] 上有新回复：[文章标题]」
- 访客回复通知：「你在 [站点名称] 的评论收到了回复：[文章标题]」

文章标题超过 60 个字符时截断；页面没有标题时，主题不追加标题。发件人显示名为站点名称，地址仍是「发件人地址」。邮件带有 `Auto-Submitted: auto-generated` 头，自动回复程序通常不会回信。

## Telegram

1. 在 Telegram 中找 [@BotFather](https://t.me/BotFather) 创建机器人，得到 Bot Token。
2. 让机器人能给你发消息：私聊的话先给机器人发一条消息；群组或频道则把机器人拉进去，频道还需要设为管理员。
3. 查到接收目标的 ID：个人用户是一串数字，如 `123456789`；群组和频道通常以 `-100` 开头，如 `-1001234567890`。
4. 在后台填入 Bot Token 和接收目标 ID（每个 ID 一个输入框，可填多个；只接受数字 ID，不接受 `@用户名`），点击「发送测试消息」确认，再保存。

消息包含站点名称、文章标题、发布时间、评论人或回复人、被回复的原评论（以引用块显示，最多 400 个字符）和正文（最多 1000 个字符），末尾附「查看原文」链接。表情包显示为 `[表情：标签]`。

## 投递方式

通知不会在提交评论时同步发送。评论和它要发的通知在同一个数据库事务里写入一张待发队列，后台任务每 3 秒取出一批发送。所以：

- 邮件服务器暂时连不上，不影响访客发评论。
- 每个收件人单独一条记录、单独重试。一个地址失败不影响其他地址。
- 失败后按 2、4、8、16、32、64、128 分钟的间隔重试，一共尝试 8 次，之后放弃。
- 重试也不会成功的失败直接放弃：收件邮箱不存在或邮件被服务器拒收（SMTP 55x）、Telegram 找不到会话或机器人被移出、拉黑（HTTP 400/403）。Telegram 要求限速（HTTP 429）时，按它给出的等待时间与常规重试间隔中较长的一个推迟，这次仍计入 8 次尝试。
- 已发送、已取消和已放弃的记录保留 30 天，之后自动清理。
- 通知在入队时就确定了发给谁。之后关闭渠道或修改收件人，已经入队的通知仍会按原样投递。
- 进程在「已发出、尚未记录结果」的瞬间崩溃，重启后可能再发一次。极少数情况下会收到重复通知。

日志只记录通知编号、错误类型和次数，不记录收件地址、评论内容或凭据。

## 删除评论之后 {#after-deletion}

在后台删除一条评论后：

- 还没发出的通知不再发送，包括发给博主的邮件和 Telegram 消息。
- 别人对这条评论的回复不会再发邮件给它的作者，队列里记录的该邮箱地址也一并删除。
- 已经发出的 Telegram 消息会被改写为「这条评论已被删除，通知内容已移除。」，只保留站点名称和文章标题。
- 已经发出的邮件无法撤回。

以下情况无法改写已发出的 Telegram 消息：通知发出已超过 30 天，记录已经清理；撤回完成前就彻底删除了这条墓碑；进程在消息发出后、记录结果前崩溃。

## 常见问题 {#troubleshooting}

**启用渠道时保存失败，提示「请求参数不符合要求，请检查后重试。」**：如果表单填写无误，多半是没有填写实例公开网址。在 `app/config.yaml` 中填写 `notifications.instance_public_url` 后重建容器。

**容器无法启动，日志出现 `通知凭据校验失败` 或 `持久密钥文件权限过宽；请设为 600`**：通知加密主密钥在启动时读取，运行中保存设置不会因密钥报错。确认 `data/ecoku-secrets.json` 与数据库来自同一份备份，属主为容器用户，权限为 `600`；不要删除它让程序重新生成，见 [恢复说明](./backup#restore)。旧实例如果仍注入 `ECOKU_NOTIFICATION_ENCRYPTION_KEY`，它的值必须与持久文件中的密钥一致。

**测试邮件超时**：多数是服务器的 SMTP 出站端口被封锁。先在服务器上用 `nc -vz smtp.example.com 465` 确认能连通，再检查端口与加密方式是否匹配（465 对应 SSL/TLS，587 对应 STARTTLS）。
