# v0.3.4

- 发布日期：2026-10-05
- schema：v12（无迁移）
- 镜像：`ghcr.io/dejavumoe/ecoku:v0.3.4`
- npm SDK：`ecoku@0.3.4`

## 变更 {#changes}

- 修复后台首次打开时，未登录的会话检查取消验证配置请求、导致验证码偶发不显示的问题。验证加载期间禁止提交；加载失败后可点击「重试」，保留已填账号密码，重试不会自动登录。
- 评论提交遇到网络中断、超时、无效响应或服务端错误时，保留草稿并提示结果尚未确认，不再误报「尚未提交」，也不会自动重试。
- 可选身份存储不再阻塞首屏评论加载和发布成功反馈；较晚恢复的身份不覆盖用户编辑。公共列表和提交减少重复的站点配置查询，博主口令比较提前排除不符合既有规则的候选值。
- CI 增加 Go 漏洞检查、JavaScript 锁文件依赖审计和 SDK 真实浏览器存储测试；修复文档工具链及 `brace-expansion` 间接依赖的已知漏洞。

## 兼容性 {#compatibility}

- 没有数据库迁移，schema 仍为 v12。Compose 挂载、配置项和环境变量不变。
- 来源检查、配置读取、人机验证和评论写入共享 8 秒处理预算；SDK 的单次请求超时仍为 10 秒。较慢的验证服务可能耗尽预算，详见 [提交评论](../../reference/api#submit-comment)。
- 提交结果未确认不代表评论一定没有保存。先刷新评论列表检查，再决定是否手动重试，避免重复发布。
- 身份保存仍然可选，只在 IndexedDB 中加密保存 7 天，不新增浏览器存储位置。

## 升级 {#upgrade}

1. 停服并 [冷备份](../backup#cold-backup) 数据库、`ecoku-secrets.json`、Compose 和配置文件。
2. 按 [升级步骤](../upgrade#steps) 将镜像改为 `ghcr.io/dejavumoe/ecoku:v0.3.4`，执行 `sudo docker compose pull && sudo docker compose up -d`。
3. 检查容器健康状态；退出后台后重新打开登录页，确认验证正常加载并能登录，再检查评论加载与发布。
4. npm 发布成功后，使用 `pnpm add --save-exact ecoku@0.3.4` 更新独立接入的 SDK 并重新构建网站。容器内置 SDK 随镜像更新；自行托管静态文件时一并替换加载器、SDK 和样式文件。

## 回滚 {#rollback}

schema 没有变化。停服后将镜像改回 `ghcr.io/dejavumoe/ecoku:v0.3.3`，拉取并启动即可，不需要恢复数据库；升级后新增的评论和设置修改会保留。独立安装的 npm SDK 可固定回 `ecoku@0.3.3` 后重新构建网站；回滚会撤回本版的登录和评论提交修复。
