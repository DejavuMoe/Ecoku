# v0.5.3

- 发布日期：2026-10-19
- schema：v12（无迁移）
- 镜像：`ghcr.io/dejavumoe/ecoku:v0.5.3`
- npm SDK：`ecoku@0.5.3`

## 变更 {#changes}

- 管理后台界面打磨，功能不变：桌面顶栏导航居中；评论按「2026 年 10 月 18 日」分组，不再显示星期，英文后台显示为 October 18, 2026。删除确认改为评论下方的卡片，可按 Esc 取消；人机验证方式改为三张并排的选择卡；逐项列表的删除按钮移入输入框。
- 英文与繁体中文后台的评论分页按钮不再显示简体中文。
- 更新测试与文档构建依赖，修复已知依赖漏洞；三语运维、接入与首次登录文档按源码校正。

## 兼容性 {#compatibility}

- 没有新增数据库迁移，schema 仍为 v12。API、配置键、环境变量、Compose 挂载与容器端口不变。
- 服务端与 SDK 运行时代码与 v0.5.2 相同，现有接入保持兼容。后台的变化只在界面上，管理员账户、会话和设置不受影响。
- 从早于 v0.5.2 的版本升级时，另读 [v0.5.2 的首次登录说明](./v0.5.2#compatibility)；早于 v0.5.0 时，再读 [来源冲突与历史数据说明](./v0.5.0#compatibility)。

## 升级 {#upgrade}

按 [升级步骤](../upgrade#steps) 停服并冷备份，将镜像改为 `ghcr.io/dejavumoe/ecoku:v0.5.3`，按通用步骤拉取镜像、重建容器并等待健康。

检查容器健康状态、启动日志、评论加载与提交、后台登录。每个实例都要单独升级，包括为文档示例提供服务的实例。独立安装的 SDK 可在 npm 发布成功后固定到 `ecoku@0.5.3` 并重新构建网站。

## 回滚 {#rollback}

从 v0.5.2 升级的实例，停服后将镜像改回 `ghcr.io/dejavumoe/ecoku:v0.5.2`，拉取并启动。schema 相同，无需恢复数据库，升级后的评论和设置会保留。SDK 可固定回 `ecoku@0.5.2` 后重新构建网站。从更早版本升级的实例须核对对应 schema 和回滚说明。
