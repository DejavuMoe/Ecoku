# v0.2.4

- 发布日期：2026-09-16
- schema：v7 → v8
- 镜像：`git.via.moe/dejavu/ecoku:v0.2.4`

## 变更

- 管理员登录改为 HttpOnly Cookie 加数据库会话。登录后固定 8 小时，刷新或关闭重开浏览器都能恢复，不会续期；退出时服务端撤销会话。登录响应不再返回 token。
- 人机验证在检查博主口令之前进行，没通过验证无法试探口令是否正确。
- 访问日志只记录路由模板，不再写入实际路径。
- 新回复最多 16 层（根评论为第 0 层），第 17 层会被拒绝。已有的深层评论不受影响。

## 兼容性

- schema v8 只新增管理员会话表和过期索引，不改动评论、配置和已有迁移记录。
- 升级后所有管理员需要重新登录。
- `admin.token_ttl_minutes` 只能省略或设为 `480`。旧配置中的其他数值会导致启动失败，请在升级前修改。
- 生产环境的管理后台必须通过 HTTPS 访问，反向代理需保留 `Origin` 请求头和 Cookie。HTTP 只允许用于回环开发地址。
- 挂载、环境变量和密码哈希不变。

## 升级

1. 按[备份与恢复](../backup#cold-backup)停服并做冷备份。
2. 检查 `app/config.yaml` 中的 `admin.token_ttl_minutes`：删除这一行，或改为 `480`。
3. 按[升级步骤](../upgrade#steps)操作，镜像改为 `git.via.moe/dejavu/ecoku:v0.2.4`。首次启动时自动迁移到 v8。
4. 检查：历史评论正常显示；登录后台后刷新、关闭重开浏览器仍保持登录；点击退出后无法继续访问。

## 回滚

升级后数据库已是 v8，v0.2.3 及更早版本无法打开。回滚必须：

1. 停止服务，保留当前的 `data/` 目录以备查；
2. 用升级前的冷备份[恢复](../backup#restore)，备份中的 `compose.yaml` 会带回原来的镜像版本。

备份之后产生的评论和设置修改会丢失。
