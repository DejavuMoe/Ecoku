## v0.2.4 升级兼容性（待发布）

v8 新增 `admin_sessions` 表和到期索引，不改写评论、配置或既有迁移记录。旧登录失效，需重新登录。`admin.token_ttl_minutes` 请省略或设为 480；旧自定义值会阻止启动。挂载、环境变量和密码哈希保持不变。回滚至 v0.2.3 或更早版本，必须先停服并保留当前现场，再恢复升级前完整冷备份及原镜像；仅改旧 tag 不能打开 v8 库。恢复备份会丢失备份后的写入，需由操作者明确接受。

## 升级步骤

1. 按 [备份与恢复](../backup) 停服并制作卷外冷备份，校验归档；包含 `data/`（含 WAL/SHM）、`app/config.yaml`、`ecoku.env` 和原 `compose.yaml`。不要运行中直接复制 SQLite 主文件。
2. 核对 `admin.token_ttl_minutes`：删除该键或设为 480。生产管理端应使用 HTTPS，反代保留 Origin 和 Cookie；HTTP 仅用于白名单回环开发地址。
3. 镜像发布后，将 Compose image 改为 `git.via.moe/dejavu/ecoku:v0.2.4`，运行以下命令。首次启动在原库内事务性升级至 v8，无需手工 SQL。

```bash
sudo docker compose config --quiet
sudo docker compose pull && sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail=100 ecoku
curl --fail --silent --show-error http://127.0.0.1:12123/api/health
```

健康接口只确认进程可响应。检查容器健康状态、历史评论、登录后的刷新/重开恢复，以及主动退出后的拒绝访问。不要在生产制造攻击请求或深链。
