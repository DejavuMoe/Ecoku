# v0.5.4

- 发布日期：2026-10-23
- schema：v12（无迁移）
- 镜像：`ghcr.io/dejavumoe/ecoku:v0.5.4`
- npm SDK：`ecoku@0.5.4`

## 变更 {#changes}

- SDK 刷新时若当前末页已因评论删除而消失，会重新加载仍有效的末页；评论全部删除后恢复第 1 页。导航或销毁前的旧请求不会覆盖当前页面。
- `setPageKey()` 与初始化统一处理文章标题：去除首尾空白，并截取前 200 个 UTF-16 代码单元，避免导航后提交超长标题被拒绝。
- JavaScript 调用缺少 `siteId` 时，SDK 在挂载或发起请求之前报告错误。
- 修复首次管理员设置与并发读取凭据、实例密钥之间的数据竞争，增加对应 race 回归检查。
- 更新 Vite、DOMPurify 与 Go 构建工具链至修复版本。

## 兼容性 {#compatibility}

- 没有新增数据库迁移，schema 仍为 v12。HTTP 接口、配置键、环境变量、Compose 挂载与容器端口不变；管理员账户、实例密钥和已存储评论的格式不变。
- 前端三项修复需要更新 SDK；首次设置的并发修复需要更新服务端镜像。JavaScript 接入必须提供有效的 `siteId`，缺失时会立即报错。
- 从早于 v0.5.2 的版本升级时，另读 [v0.5.2 的首次登录说明](./v0.5.2#compatibility)；早于 v0.5.0 时，再读 [来源冲突与历史数据说明](./v0.5.0#compatibility)。

## 升级 {#upgrade}

按 [升级步骤](../upgrade#steps) 停服并冷备份，将镜像改为 `ghcr.io/dejavumoe/ecoku:v0.5.4`，按通用步骤拉取镜像、重建容器并等待健康。

检查容器健康状态、启动日志、评论加载与提交、后台登录。每个实例都要单独升级，包括为文档示例提供服务的实例。独立安装的 SDK 可在 npm 发布成功后固定到 `ecoku@0.5.4` 并重新构建网站；固定版本的 CDN 接入也需同步更新 SDK 地址。

## 回滚 {#rollback}

从 v0.5.3 升级的实例，停服后将镜像改回 `ghcr.io/dejavumoe/ecoku:v0.5.3`，拉取并启动。schema 相同，无需恢复数据库，升级后的评论和设置会保留。SDK 可固定回 `ecoku@0.5.3` 后重新构建网站。回滚会恢复本版修复前的行为；从更早版本升级的实例须核对对应 schema 和回滚说明。
