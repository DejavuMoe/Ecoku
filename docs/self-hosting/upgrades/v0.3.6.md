# v0.3.6

- 发布日期：2026-10-06
- schema：v12（无迁移）
- 镜像：`ghcr.io/dejavumoe/ecoku:v0.3.6`
- npm SDK：`ecoku@0.3.6`

## 变更 {#changes}

- 公共评论列表跳过叶节点的无效查询，管理列表复用状态统计，保留排序、分页和读取上限。
- 评论删除与通知最终发送协调，发送前重新检查状态；删除父评论后，已发送直接回复的 Telegram 消息会排队移除父引用，保留回复正文。
- 登录配置、管理查询和通知 worker 继承取消信号；补齐 Cap IPv6 地址检查，密钥文件替换失败时保留旧文件。
- 源码启动默认仅监听 `127.0.0.1`；开发演示页固定连接本机 API。
- 优化 Docker 构建阶段和 CI 依赖安装；固定基础镜像 digest，并为双架构发布增加运行检查、SBOM 和漏洞扫描。

## 兼容性 {#compatibility}

- 没有数据库迁移，schema 仍为 v12。Compose 挂载、配置键、环境变量和容器监听方式不变。
- 源码模式不再默认对局域网开放；容器部署继续按现有 Compose 端口和反向代理配置访问。
- 删除可能等待已经开始的通知投递结束，单笔投递期限为 20 秒。已发送邮件不能召回，Telegram 更新异步完成；完整边界见 [删除评论之后](../notifications#after-deletion)。
- HTTP 接口和生产 SDK 保持兼容，独立接入的 `ecoku@0.3.5` 可继续使用。

## 升级 {#upgrade}

1. 停服并 [冷备份](../backup#cold-backup) 数据库、`ecoku-secrets.json`、Compose 和配置文件。
2. 按 [升级步骤](../upgrade#steps) 将镜像改为 `ghcr.io/dejavumoe/ecoku:v0.3.6`，执行 `sudo docker compose pull && sudo docker compose up -d`。
3. 检查容器健康状态、启动日志、评论加载和后台登录。已配置通知的实例同时观察投递和删除后的 Telegram 更新是否正常。
4. 如需统一 SDK 版本，等 npm 发布成功后使用 `pnpm add --save-exact ecoku@0.3.6` 并重新构建网站。容器内置 SDK 随镜像更新。

## 回滚 {#rollback}

schema 没有变化。停服后将镜像改回 `ghcr.io/dejavumoe/ecoku:v0.3.5`，拉取并启动即可，不需要恢复数据库；升级后新增的评论和设置修改会保留。独立安装的 npm SDK 可固定回 `ecoku@0.3.5` 后重新构建网站。

回滚会撤回本版的性能和安全修复。旧版本会取消尚未完成的存活回复引用刷新任务，回滚前应确认需要移除的 Telegram 父引用已经改写完成。
