# v0.6.3

- 发布日期：2026-11-24
- schema：v12（无迁移）
- 镜像：`ghcr.io/dejavumoe/ecoku:v0.6.3`
- npm SDK：`ecoku@0.6.3`

## 变更 {#changes}

- 评论区右下角显示「Powered by Ecoku」，Ecoku 按评论区语言链接到文档站首页。署名在评论列表加载完成后出现，有分页时位于分页下方。默认样式中它比正文更淡，可用 `.ecoku-powered-by` 调整，见 [自定义样式](../../integration/custom-css)。
- 管理后台登录后，每个页面底部居中显示「Powered by Ecoku」与当前版本号，版本号链接到 GitHub 上对应的 Release。登录页不显示版本号。
- 管理端会话接口（`POST /api/admin/login`、`GET /api/admin/session`、`POST /api/admin/initial-setup`）的响应新增 `version` 字段，见 [HTTP 接口](../../reference/api)。

## 兼容性 {#compatibility}

- schema 保持 v12。从 v0.6.2 升级时，沿用现有数据与配置挂载、容器用户和健康探针；配置项不变。
- 评论区新增 `.ecoku-powered-by` 元素，位于评论列表与分页之后。使用 `ecoku.unstyled.css` 或 `data-css-url="none"` 的博客会看到一行无配色的署名，可按需加样式。
- 自行从源码构建、未传入 `ECOKU_VERSION` 的镜像，后台显示 `dev`。
- 从 v0.5.7 或更早版本升级时，先阅读 [distroless 迁移说明](../upgrade#distroless)，同步更换旧 Compose 探针。

## 升级 {#upgrade}

按 [升级步骤](../upgrade#steps) 停服并冷备份，将镜像改为 `ghcr.io/dejavumoe/ecoku:v0.6.3`，再拉取并重建容器。确认状态为 `healthy`，登录后台查看底部版本号为 `v0.6.3`，再检查已发布评论和新评论提交。通过 npm 引入 SDK 的站点，将依赖改为 `ecoku@0.6.3`。

## 回滚 {#rollback}

停止服务，将镜像改回 `ghcr.io/dejavumoe/ecoku:v0.6.2`，再拉取并重建容器。两个版本均使用 schema v12，保留现有数据库与健康探针即可。
