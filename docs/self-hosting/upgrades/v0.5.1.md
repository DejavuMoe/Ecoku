# v0.5.1

- 发布日期：2026-10-16
- schema：v12（无迁移）
- 镜像：`ghcr.io/dejavumoe/ecoku:v0.5.1`
- npm SDK：`ecoku@0.5.1`

## 变更 {#changes}

- 清理服务端未使用的配置辅助函数、未读取的日志路径标记和重复常量别名，保留现有配置兼容行为。
- CI 的 SDK 浏览器测试只安装 Chromium headless shell，保留系统依赖安装、浏览器测试及其余验证步骤。
- 接入文档统一使用服务地址和站点 ID 占位符，并补充 Astro 静态页面与客户端路由示例。

## 兼容性 {#compatibility}

- 没有新增数据库迁移，schema 仍为 v12。API、配置键、环境变量、Compose 挂载、容器端口及日志路径行为不变。
- SDK 版本随服务端发布，运行时代码与 v0.5.0 相同。现有接入代码保持兼容，无需因本次更新调整应用界面或站点设置。
- 若从早于 v0.5.0 的版本升级，先核对 [v0.5.0 兼容性说明](./v0.5.0#compatibility)，尤其是管理来源与站点来源冲突及历史数据处理事项。

## 升级 {#upgrade}

按 [升级步骤](../upgrade#steps) 停服并冷备份，将镜像改为 `ghcr.io/dejavumoe/ecoku:v0.5.1`，执行 `sudo docker compose pull && sudo docker compose up -d`。

检查容器健康状态和启动日志，再确认评论加载、提交与后台登录。每个实例都要单独更新镜像，包括为文档示例提供服务的实例。

独立安装的 SDK 可在 npm 发布成功后固定到 `ecoku@0.5.1` 并重新构建网站；继续使用 v0.5.0 的 SDK 也保持兼容。

## 回滚 {#rollback}

从 v0.5.0 升级的实例，停服后将镜像改回 `ghcr.io/dejavumoe/ecoku:v0.5.0`，拉取并启动即可。schema 相同，无需恢复数据库，升级后的评论与设置会保留。独立安装的 SDK 可固定回 `ecoku@0.5.0` 后重新构建网站。

若从更早版本升级，先核对该版本的 schema 与对应版本的回滚说明。
