# v0.3.3

- 发布日期：2026-10-04
- schema：v12（无迁移）
- 镜像：`ghcr.io/dejavumoe/ecoku:v0.3.3`
- npm SDK：`ecoku@0.3.3`

## 变更 {#changes}

- 执行 [`admin reset-password`](../../reference/cli#admin-reset-password) 后，首次登录设置页预填当前用户名，不再固定填 `admin`。改过用户名的管理员重置密码后直接保存，不会被改回 `admin`。
- 评论区不再为第 16 层评论显示「回复」按钮。服务端以 `422` 拒绝过深的回复时，评论区提示「回复层级已达上限，请回复较上层的评论。」，不再显示笼统的提交错误。
- HTML 加载器支持 [`data-i18n`](../../integration/html)，可以在接入代码中指定评论区语言，覆盖站点设置。加载器自己的失败提示也随之切换语言；没写 `data-i18n` 时按页面的 `<html lang>` 选择，其他情况为简体中文。
- 文档按源码复核：补充站点「评论区语言」字段、`EcokuSite` 站点管理凭据的权限范围，并修正多处与实现不符的描述。

## 兼容性 {#compatibility}

- 没有数据库迁移，schema 仍为 v12。Compose、挂载、配置项和环境变量不变。
- 用临时密码登录时，登录接口与 `GET /api/admin/session` 的响应多一个 `username` 字段；普通会话的响应不变。
- 加载器的失败提示此前固定为简体中文。页面 `<html lang>` 为英语或繁体中文的网站，升级后会看到对应语言的提示。
- 自己托管 `ecoku-loader.js` 的网站，需要把 `ecoku-loader.js` 和 `ecoku.umd.js` 一起换成新版，`data-i18n` 和新的回复行为才会生效；旧版加载器会忽略 `data-i18n`。

## 升级 {#upgrade}

1. 停服并 [冷备份](../backup#cold-backup) 数据库、`ecoku-secrets.json`、Compose 和配置文件。
2. 按 [升级步骤](../upgrade#steps) 将镜像改为 `ghcr.io/dejavumoe/ecoku:v0.3.3`，执行 `sudo docker compose pull && sudo docker compose up -d`。
3. 检查容器健康状态和管理员登录，打开一篇有评论的文章，确认评论区正常加载。
4. npm 发布成功后，使用 `pnpm add --save-exact ecoku@0.3.3` 更新独立接入的 SDK 并重新构建网站。容器内置 SDK 随镜像更新。

## 回滚 {#rollback}

schema 没有变化。停服后将镜像改回 `ghcr.io/dejavumoe/ecoku:v0.3.2`，拉取并启动即可，不需要恢复数据库；升级后新增的评论和设置修改会保留。接入代码中已经加上的 `data-i18n` 会被旧版忽略，不影响加载。
