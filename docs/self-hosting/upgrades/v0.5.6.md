# v0.5.6

- 发布日期：2026-11-09
- schema：v12（无迁移）
- 镜像：`ghcr.io/dejavumoe/ecoku:v0.5.6`
- npm SDK：`ecoku@0.5.6`

## 变更 {#changes}

- 运行时镜像将 musl 升级至 1.2.6-r3、zlib 升级至 1.3.2-r1 及以上，修复 CVE-2026-107891 与 CVE-2026-85091。
- 包含 [v0.5.5](./v0.5.5#changes) 的全部变更：更新 `golang.org/x/net` 至 v0.62.0，修复 Twikoo 导入解析 HTML 时的二次复杂度漏洞（GO-2026-6860）；更新构建与测试依赖；整理通知队列、管理后台会话与 SDK 加载器的内部状态，对外行为不变。v0.5.5 没有发布镜像，本版是其后第一个可部署的镜像。

## 兼容性 {#compatibility}

- 没有新增数据库迁移，schema 仍为 v12。HTTP 接口、配置键、环境变量、Compose 挂载与容器端口不变；通知队列中已有的记录照常投递。
- 安全修复位于服务端镜像，需要更新镜像。SDK 对外行为与 `ecoku@0.5.4` 相同，可按需更新。
- 从早于 v0.5.4 的版本升级时，另读 [v0.5.4 的兼容性说明](./v0.5.4#compatibility)；早于 v0.5.2 时，再读 [v0.5.2 的首次登录说明](./v0.5.2#compatibility)；早于 v0.5.0 时，还需读 [来源冲突与历史数据说明](./v0.5.0#compatibility)。

## 升级 {#upgrade}

按 [升级步骤](../upgrade#steps) 停服并冷备份，将镜像改为 `ghcr.io/dejavumoe/ecoku:v0.5.6`，按通用步骤拉取镜像、重建容器并等待健康。

检查容器健康状态、启动日志、评论加载与提交、后台登录；已启用通知的实例，可发表一条测试评论确认通知照常送达。每个实例都要单独升级，包括为文档示例提供服务的实例。独立安装的 SDK 可在 npm 发布成功后固定到 `ecoku@0.5.6` 并重新构建网站；固定版本的 CDN 接入也需同步更新 SDK 地址。

## 回滚 {#rollback}

从 v0.5.4 升级的实例，停服后将镜像改回 `ghcr.io/dejavumoe/ecoku:v0.5.4`，拉取并启动。schema 相同，无需恢复数据库，升级后的评论和设置会保留。SDK 可固定回 `ecoku@0.5.4` 后重新构建网站。回滚会重新引入本版修复的漏洞；从更早版本升级的实例须核对对应 schema 和回滚说明。
