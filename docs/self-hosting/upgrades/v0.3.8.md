# v0.3.8

- 发布日期：2026-10-09
- schema：v12（无迁移）
- 镜像：`ghcr.io/dejavumoe/ecoku:v0.3.8`
- npm SDK：`ecoku@0.3.8`

## 变更 {#changes}

- Go 工具链与容器构建镜像升级至 `1.27.2`，`golang.org/x/net` 升级至 `v0.60.0`，并同步相关依赖，修复漏洞审计命中的 HTTP/2、HTTP/1、MIME 与 TLS 漏洞。
- 三语文档按源码复核，修正部署、备份、REST API 与接入说明，补齐 HTML 属性取值、`pageKey` 限制和 Twikoo 导入的停服步骤。

## 兼容性 {#compatibility}

- 没有数据库迁移，schema 仍为 v12。Compose 挂载、配置键、环境变量、容器端口和 HTTP 接口不变。
- 管理端与 SDK 运行时代码与 v0.3.7 相同；独立安装的 `ecoku@0.3.7` 可继续使用。
- 从源码构建时，依赖要求最低 Go `1.26.0`，项目通过 `mise.toml` 和 `go.mod` 固定使用 Go `1.27.2`。使用容器的实例无需在宿主机安装 Go。

## 升级 {#upgrade}

按 [升级步骤](../upgrade#steps) 停服并冷备份，将镜像改为 `ghcr.io/dejavumoe/ecoku:v0.3.8`，拉取并启动。

检查容器健康状态、启动日志、评论加载和后台登录；启用了人机验证或通知的实例，同时确认验证与投递正常。容器内置 SDK 随镜像更新；独立安装的 SDK 可在 npm 发布成功后固定到 `ecoku@0.3.8` 并重新构建网站。

## 回滚 {#rollback}

从 v0.3.7 升级的实例，停服后将镜像改回 `ghcr.io/dejavumoe/ecoku:v0.3.7`，拉取并启动即可。schema 相同，无需恢复数据库，升级后的评论与设置会保留。独立安装的 SDK 可固定回 `ecoku@0.3.7` 后重新构建网站。

回滚会重新引入本版修复的 Go 安全漏洞，仅在排查升级问题时临时使用。若从更早版本升级，先核对该版本的 schema 与 [回滚说明](./v0.3.7#rollback)。
