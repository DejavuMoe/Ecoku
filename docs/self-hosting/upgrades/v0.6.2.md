# v0.6.2

- 发布日期：2026-11-23
- schema：v12（无迁移）
- 镜像：`ghcr.io/dejavumoe/ecoku:v0.6.2`
- npm SDK：`ecoku@0.6.2`

## 变更 {#changes}

- 评论区默认样式的回复改为树形连线：第二至第四级回复各由一个圆角拐角从父评论连到自己的作者行，后面还有同级回复时竖线才继续向下，最后一条回复以拐角收尾。更深的回复仍与第四级对齐，以「@昵称」标明回复对象。原先贯穿整条回复的竖向引导线已移除。
- 新增 `--ecoku-thread-*` 变量，用于调整回复缩进与连线，见 [自定义样式](../../integration/custom-css#variables)。

## 兼容性 {#compatibility}

- schema 保持 v12。从 v0.6.1 升级时，沿用现有数据与配置挂载、容器用户和健康探针；配置项、接口与评论 DOM 结构不变。
- 只影响默认样式 `ecoku.css`。使用 `ecoku.unstyled.css` 或 `data-css-url="none"` 的博客，评论区外观不变。
- 如果博客的自定义样式覆盖过回复缩进，或给旧引导线（`.ecoku-comment-row::before`、`--ecoku-guide-offset`）写过样式，升级后请检查评论区显示。
- 从 v0.5.7 或更早版本升级时，先阅读 [distroless 迁移说明](../upgrade#distroless)，同步更换旧 Compose 探针。

## 升级 {#upgrade}

按 [升级步骤](../upgrade#steps) 停服并冷备份，将镜像改为 `ghcr.io/dejavumoe/ecoku:v0.6.2`，再拉取并重建容器。确认状态为 `healthy`，检查后台登录、已发布评论和新评论提交。通过 npm 引入 SDK 的站点，将依赖改为 `ecoku@0.6.2`。

## 回滚 {#rollback}

停止服务，将镜像改回 `ghcr.io/dejavumoe/ecoku:v0.6.1`，再拉取并重建容器。两个版本均使用 schema v12，保留现有数据库与健康探针即可。
