# v0.2.3 升级说明（待发布）

停服冷备份并验证 → 改精确镜像 tag → `sudo docker compose pull && sudo docker compose up -d` → 健康与业务检查、必要时回滚。

准备日期：2026-09-16。等待 master CI 验收及后续 tag 发布；镜像构建成功后再执行升级。

## 主要修复

- 站点保存不再重授历史评论博主身份；口令增加 UTF-8 72 字节校验，已有 bcrypt 哈希继续有效。
- SMTP 全流程支持取消和超时；通知完成写回失败只重试数据库；Telegram 保留完整链接和 HTML 结构。
- Twikoo 乱序导入保留直接父子关系；Unicode 输入、管理请求取消、Loader 重试、Smoji URL/键盘和异步控件收尾修复。
- SPA 可使用 `setPageKey(pageKey, pageTitle)` 更新标题；省略第二参数会清空旧标题。直接 SDK 的外链 CSS 仍需宿主自行加载。

## 升级兼容性

本次审计修复保持 schema v7、挂载路径、环境变量及 bcrypt 哈希格式不变；v0.2.2 可原位升级。不会清理评论、配置、WAL 或备份。配置保存不再回填博主标记，已有标记保留；过去误标无法与口令认证记录自动区分，不批量重写。若发现历史误标，需独立核实并授权数据纠正。通知采用至少一次投递：写回失败时保留本次结果重试写回；若在成功发送后、持久化前崩溃，重启可能重复发送。

## 升级步骤

1. 按 [备份说明](../backup) 停服、创建卷外冷备份并校验。保留 `data/`（含 WAL/SHM）、`app/config.yaml`、`ecoku.env` 与原 `compose.yaml`。
2. 镜像发布后，将 `compose.yaml` 的 image 改为 `git.via.moe/dejavu/ecoku:v0.2.3`。配置、环境变量和挂载保持不变。
3. 执行下列命令，随后确认管理员登录、历史评论、博主身份和通知；真实通知测试须由操作者明确执行。

```bash
sudo docker compose pull && sudo docker compose up -d
sudo docker compose logs --tail=100 ecoku
curl --fail --silent --show-error http://127.0.0.1:12123/api/health
```

## 回滚到 v0.2.2

两版均为 schema v7，通常可在停服后把镜像改回 `git.via.moe/dejavu/ecoku:v0.2.2`，拉取并启动，保留现有数据库及升级后的新评论。但旧版审计缺陷也会恢复。只有确需恢复升级前数据时才使用整套冷备份；先保留当前现场并明确接受备份后写入的丢失，不要自动覆盖数据库。
