# v0.2.8

- 发布日期：2026-10-01
- schema：v9（从 v0.2.7 升级不变）
- 镜像：`git.via.moe/dejavu/ecoku:v0.2.8`

## 变更 {#changes}

- 管理后台的评论按日期分组，删除时在评论旁确认；设置表单改为行式字段，有修改时才显示保存栏，离开未保存的页面前会提示。增加键盘快捷键与窄屏底部导航，管理后台和文档站使用「區」印章标识。
- 站点保存失败时保留未保存的名称、博主口令等草稿；通知和安全设置加载失败时禁用表单并提供重试。
- 官方镜像内置日志、评论区资源、管理后台资源和 SQLite 路径，默认启用管理后台。`*_env` 字段省略时使用标准环境变量名；`admin.allowed_origins` 省略时取 `notifications.instance_public_url` 的来源。具体取值见[配置参考](../../reference/configuration)。
- 部署模板精简：`app/config.yaml` 只需填写 `notifications.instance_public_url`；`ecoku.env` 不再重复设置镜像已有的 `GIN_MODE`；Compose 使用 Docker 守护进程的日志设置。

## 兼容性 {#compatibility}

- 从 v0.2.7 升级不执行数据库迁移，schema 仍为 v9。评论区与 SDK、HTTP 接口、Compose 挂载和已有配置键保持不变。
- 旧的完整配置文件与 Compose `logging` 设置仍可使用，无需删减。显式配置优先于默认值；管理员凭据、通知加密密钥与数据目录继续使用原值。
- 容器目录与管理后台开关的默认值由镜像中的 `ECOKU_RUNTIME=container` 启用；源码运行保留原来的目录与开关默认值。
- v0.2.7 不支持新的精简配置；如果升级时删掉了原来的显式配置，回滚前需要恢复完整配置。

## 升级 {#upgrade}

1. 按[备份与恢复](../backup#cold-backup)停服并做冷备份，保留原来的 `compose.yaml`、`app/config.yaml` 和 `ecoku.env`。
2. 按[升级步骤](../upgrade#steps)操作，镜像改为 `git.via.moe/dejavu/ecoku:v0.2.8`。现有部署可以继续使用原配置，无需替换成精简模板。
3. 健康检查通过后，确认评论区能加载、发布，管理后台能登录，评论删除与站点、通知设置保存正常。

## 回滚 {#rollback}

回到 v0.2.7 时 schema 相同，可以保留当前数据库及升级后产生的评论和设置修改：

1. 停止服务；如果采用了精简 `app/config.yaml`，先恢复升级前的完整配置。
2. 把镜像改回 `git.via.moe/dejavu/ecoku:v0.2.7`，按[升级步骤](../upgrade#steps)拉取、启动并检查。

v0.2.6 及更早版本无法打开 schema v9 数据库。回到这些版本时，必须[恢复](../backup#restore)对应旧 schema 的冷备份，备份之后的评论和设置修改会丢失。
