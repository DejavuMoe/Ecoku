# v0.2.9

- 发布日期：2026-10-02
- schema：v9 → v10
- 镜像：`git.via.moe/dejavu/ecoku:v0.2.9`

## 变更 {#changes}

- 新部署不再填写管理员密码哈希和两把密钥。首次启动创建 `admin`、随机临时密码和持久密钥文件；临时密码打印在启动日志中，首次登录必须改密，用户名可以保留 `admin`。
- 新增持久管理员账户表及 `admin reset-password` 命令。首次改密会话只能查看会话、退出和完成设置；完成后进入现有站点创建流程。
- 修复后台 favicon、Chrome 表单虚线、通知字段错误排版、父评论表情标记、删除列表跳位、跳转高亮、重复提示和会话过期提示。文档首页统一使用「區」标识。
- 新 Compose 不再要求 `ecoku.env` 或日志目录挂载；日志默认写入标准输出。

## 兼容性 {#compatibility}

- 从 v0.2.8 升级时在原数据库增加 `admin_accounts`，保留站点、评论、通知、人机验证、队列和已发布迁移记录。没有向下迁移。
- 首次升级保留旧 Compose、YAML 和环境变量。原用户名、bcrypt 哈希和密钥会导入持久状态；旧管理员不需要强制改密。
- 旧端口、数据库路径、静态目录、文件日志、YAML 站点及管理密钥仍有兼容入口；`admin.enabled: false` 会被忽略，后台始终启用。旧会话时长仍只接受 480 分钟或省略。
- 持久密钥位于数据库同目录的 `ecoku-secrets.json`，标准挂载下为 `data/ecoku-secrets.json`。文件必须是普通文件，Linux 权限为 600；不可丢失或随意替换通知加密主密钥。

## 升级 {#upgrade}

1. 保留原配置和所有旧密钥，停服并[冷备份](../backup#cold-backup)。旧实例的归档还必须包含 `ecoku.env`；自定义数据库路径须备份其实际位置。
2. 按[升级步骤](../upgrade#steps)将现有 Compose 的镜像改成 `git.via.moe/dejavu/ecoku:v0.2.9`，拉取并启动；本次先不替换为新用户模板。
3. 确认健康接口、原管理员登录、站点数量、历史评论、通知和人机验证设置正常，持久密钥文件已生成。
4. 如需采用精简配置，按[旧配置迁移](../upgrade#legacy-config)再次停服备份后移除旧管理员环境变量。需要保留 `TZ` 或 `EcokuSite` 的环境变量时，继续使用对应的环境注入方式。旧数据库路径和文件日志挂载须等到确认不再使用时再移除。

## 回滚 {#rollback}

v0.2.8 不能打开 schema v10。停止服务，按[恢复说明](../backup#restore)恢复升级前的完整数据库、原 Compose、配置与 `ecoku.env`，再使用 v0.2.8 启动。只改镜像 tag 不足以回滚；冷备份之后产生的评论和设置会丢失。
