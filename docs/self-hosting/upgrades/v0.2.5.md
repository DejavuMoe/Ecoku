# v0.2.5 升级说明

停服冷备份并验证 → 改精确镜像 tag → `sudo docker compose pull && sudo docker compose up -d` → 健康检查与回滚。

发布日期：2026-09-26。

评论区默认样式改为「纸与墨」，默认 `--ecoku-*` 变量可由宿主直接覆盖，`data-theme="auto"` 跟随宿主明暗；Turnstile 服务端验证拒绝 HTTP 重定向。

## 主要变更

- 评论区默认样式：身份字段为横线填写栏，正文直接写在发表卡片上；只保留一个实心主按钮，表情、预览、取消与排序为文字按钮；圆角 6px / 3px；时间、折叠、字数与页码使用等宽字体；博主标志、链接悬停与表单错误使用朱砂强调色。Cap 保留官方 260×58px 几何，外框圆角跟随 Ecoku 变量。
- 默认 `--ecoku-*` 变量以零优先级声明，在 `.ecoku-comments` 上写同名变量即可覆盖；新增强调色、错误色、圆角、阴影、等宽字体与字号变量，见[自定义 CSS](../../integration/custom-css)。
- `data-theme="auto"` 不再固定 `color-scheme`，站点手动切换明暗且与系统设置不一致时，评论区不再反色。
- 触屏设备上的评论输入框不小于 16px，避免 iOS 聚焦时放大页面。
- Turnstile Siteverify 收到 HTTP 重定向时按验证服务不可用处理，继续失败关闭。

## 升级兼容性

schema 保持 v8，不新增迁移；配置键、环境变量、Compose 挂载与密码哈希不变，v0.2.4 可原位升级。评论区 DOM 类名、文案以及 SDK 与加载器接口不变。

接入站点请留意：

- 使用默认注入样式或 `/client/ecoku.css` 的站点，评论区外观随镜像更新。已有覆盖 CSS 可能与新默认值叠加，升级后请在浅色和深色下检查评论区；原先为压过默认样式而写的高优先级规则，可以改成在 `.ecoku-comments` 上声明变量。
- `data-css-url` 指向自行托管的样式或设为 `none` 的站点，外观不变。
- `/client/` 资源缓存一小时，升级后浏览器可能短时间内仍使用旧样式。

## 升级步骤

1. 按 [备份与恢复](../backup) 停服并制作卷外冷备份，校验归档；包含 `data/`（含 WAL/SHM）、`app/config.yaml`、`ecoku.env` 和原 `compose.yaml`。
2. 将 Compose image 改为 `git.via.moe/dejavu/ecoku:v0.2.5`，运行以下命令。

```bash
sudo docker compose config --quiet
sudo docker compose pull && sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail=100 ecoku
curl --fail --silent --show-error http://127.0.0.1:12123/api/health
```

3. 打开接入站点的文章页，在浅色和深色下确认评论区、回复框与验证组件显示正常。

## 回滚到 v0.2.4

两版均为 schema v8。通常可停服后把镜像改回 `git.via.moe/dejavu/ecoku:v0.2.4`，拉取并启动，保留现有数据库与升级后的新评论；评论区样式与 Turnstile 重定向修复随之回退。只有确需恢复升级前数据时才使用整套冷备份：先保留当前现场，并明确接受备份后写入的丢失，不要自动覆盖数据库。
