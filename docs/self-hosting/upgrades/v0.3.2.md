# v0.3.2

- 发布日期：2026-10-04
- schema：v12（无迁移）
- 镜像：`ghcr.io/dejavumoe/ecoku:v0.3.2`
- npm SDK：`ecoku@0.3.2`

## 变更 {#changes}

- 后台的站点、通知和安全设置改用带边框的输入框，减少横线与下划线。允许来源、通知收件人和 Telegram 接收目标改为逐项输入：按 Enter 新增下一项，可一次粘贴多行；有误的项在下方提示，来源缺少协议或带有路径时可一键改正，重复项保存时合并。
- 通知邮件页眉改用「區」印章。印章作为内嵌图片随邮件发送，不从网络加载。
- SDK 的 `i18n` 参数同时决定评论区文字、`lang` 属性和 Cap 验证组件的语言，不再被站点语言覆盖。英语与繁体中文评论区在未完成人机验证时给出对应提示。
- 后台刷新后保持 `ECOKU_ADMIN_LOCALE` 设定的语言，英语与繁体中文界面补齐此前未翻译的文案；进入后台时不再出现焦点框。

## 兼容性 {#compatibility}

- 没有数据库迁移，schema 仍为 v12。Compose、挂载、配置项和环境变量不变。
- 站点接口的 `i18n` 只接受 `zh-CN`、`zh-Hant`、`en`（及 `zh-TW`、`en-US` 等地区写法），其他值返回 `400`；此前会被改成 `zh-CN`。用脚本调用管理接口时，请检查传入的值。
- `ECOKU_ADMIN_LOCALE` 无效时照常启动，后台使用 `zh-CN`，并在启动日志中提示。
- 通知邮件的 HTML 部分改为 `multipart/related`，每封邮件多带一个 2.5 KB 的内嵌 PNG。纯文本版本不变。
- 接入时传入 `i18n` 的网站，评论区的 `lang` 属性和 Cap 组件语言会随之改变。

## 升级 {#upgrade}

1. 停服并 [冷备份](../backup#cold-backup) 数据库、`ecoku-secrets.json`、Compose 和配置文件。
2. 按 [升级步骤](../upgrade#steps) 将镜像改为 `ghcr.io/dejavumoe/ecoku:v0.3.2`，执行 `sudo docker compose pull && sudo docker compose up -d`。
3. 检查容器健康状态、管理员登录、站点与通知设置；发送一封测试邮件，确认页眉印章正常显示。
4. npm 发布成功后，使用 `pnpm add --save-exact ecoku@0.3.2` 更新独立接入的 SDK 并重新构建网站。容器内置 SDK 随镜像更新。

## 回滚 {#rollback}

schema 没有变化。停服后将镜像改回 `ghcr.io/dejavumoe/ecoku:v0.3.1`，拉取并启动即可，不需要恢复数据库；升级后新增的评论和设置修改会保留。
