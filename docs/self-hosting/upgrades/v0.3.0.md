# v0.3.0

- 发布日期：2026-10-03
- schema：v10 → v11
- 镜像：`git.via.moe/dejavu/ecoku:v0.3.0`
- GHCR 镜像：`ghcr.io/dejavumoe/ecoku:v0.3.0`
- npm SDK：`ecoku@0.3.0`

## 变更 {#changes}

- Smoji 新增选填的「图片来源」。可以自行托管工作台导出的 JSON，继续从指定 CDN 加载图片；评论、预览、后台及邮件统一使用这一来源规则。
- GitHub Actions 发布 GHCR 双架构镜像、npm SDK 和附带 SDK 包与校验和的 GitHub Release。SDK 版本与项目 tag 一致；Woodpecker 继续发布文档和原有 Forgejo 镜像。
- 完整 YAML 模板集中说明默认值、可选值和示例；Compose 显式设置 `TZ: Asia/Shanghai`。文档保留原有布局，采用后台纸墨配色，统一代码高亮与行内排版，并修复默认搜索翻译。

## 兼容性 {#compatibility}

- 在原数据库的 `sites` 表增加 `smoji_image_origin`，默认空字符串；保留账号、站点、评论、队列和通知配置。没有向下迁移。
- 未填写「图片来源」的站点保持清单同源校验；填写后只允许指定的一个图片来源。远程 JSON 不能扩大允许范围。
- 现有 Compose、YAML 和管理员凭据继续有效，无需重新生成密码或密钥。v0.2.8 及更早实例仍按 [旧配置迁移](../upgrade#legacy-config) 操作。
- 新增 GHCR 发布不会自动修改现有部署的镜像来源。npm 与镜像分别发布，下载前确认对应发布任务成功。

## 升级 {#upgrade}

1. 停服并 [冷备份](../backup#cold-backup) 数据库、同目录的 `ecoku-secrets.json`、Compose 和配置；仍使用 `ecoku.env` 时一起备份。
2. 按 [升级步骤](../upgrade#steps) 将镜像改为 `git.via.moe/dejavu/ecoku:v0.3.0`，执行 `sudo docker compose pull && sudo docker compose up -d`。如主动切换 GHCR，可使用上方同版本地址。
3. 检查健康接口、管理员登录、历史评论和通知；确认 schema v11 迁移成功。
4. 需要分开托管 Smoji 时，按 [清单与图片托管](../../integration/smoji#hosting) 填写「图片来源」并测试选择器、预览与评论显示。
5. 使用 npm SDK 的网站在 npm 发布成功后安装 `ecoku@0.3.0`，重新构建网站。实例托管的 UMD 接入继续随容器更新。

## 回滚 {#rollback}

v0.2.9 不能打开 schema v11。停止服务，按 [恢复说明](../backup#restore) 恢复升级前的数据库、持久密钥、Compose 和配置，再启动原镜像；不能只改镜像 tag。恢复备份会丢失备份之后新增的评论和设置。使用 npm SDK 的网站也应恢复升级前的依赖和构建产物。
