# v0.2.0

停服冷备份 → 修改精确镜像 tag → `sudo docker compose pull && sudo docker compose up -d` → 健康与业务检查。

本版本主要是文档、接入示例与 API 参考的事实校正和完善（2026-09-12）。

## 升级影响

- SQLite 保持 **schema v7**，没有数据库迁移。
- 环境变量、Compose 挂载、端口、容器权限和运行时数据格式不变。
- 公开评论列表的预算、游标分页、读取限流和状态码说明已与 v0.1.9 实现对齐。

## 升级操作

1. 在隔离环境检查页面、评论列表、回复和管理端。
2. 停服并备份 `data/`、`app/config.yaml`、`ecoku.env` 与原 `compose.yaml`。
3. 将 `compose.yaml` 的 `image` 改为 `git.via.moe/dejavu/ecoku:v0.2.0`，不要修改其他配置。
4. 执行：

   ```bash
   sudo docker compose config --quiet
   sudo docker compose pull && sudo docker compose up -d
   sudo docker compose ps
   sudo docker compose logs --tail=100 ecoku
   curl --fail --silent --show-error http://127.0.0.1:12123/api/health
   ```

5. 确认健康接口、真实评论列表、排序、分页、回复和管理端正常。

## 回滚到 v0.1.9

停服后恢复精确 `v0.1.9` 镜像 tag，拉取并启动。两版均为 schema v7，通常无需恢复数据库；若确认数据异常，再按冷备份流程恢复整库。
