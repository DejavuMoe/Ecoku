# v0.5.7

- 发布日期：2026-11-12
- schema：v12（无迁移）
- 镜像：`ghcr.io/dejavumoe/ecoku:v0.5.7`
- npm SDK：`ecoku@0.5.7`

## 变更 {#changes}

- 公开读取使用独立的 SQLite 只读连接池，复用数据库未变化时的列表、站点和人机验证配置结果；评论列表支持 `ETag` 与条件请求，减少重复读取。
- HTML 加载器按 SDK 内容哈希请求资源，并在下载 SDK 的同时预取第一页评论。
- 修复排序、翻页、同页刷新和回复提交交错时丢失草稿、恢复旧排序或不显示新评论的问题；保留同页刷新的折叠状态，清空正文时同步更新预览。
- 管理后台的时间与日期分组使用实例 `TZ`；恢复会话时，语言与时区配置加载失败会自动重试。
- 更新 SQLite 驱动、构建和测试工具链；文档固定流程图改用本地 SVG，移除 Mermaid 运行时与依赖。

## 兼容性 {#compatibility}

- 没有新增数据库迁移，schema 仍为 v12。SQLite 驱动更换不改变数据库结构；配置键、环境变量、Compose 挂载和容器端口不变。
- `GET /api/admin/login-config` 新增 `timeZone`。默认时区仍为 `Asia/Shanghai`；已配置其他 `TZ` 的实例，后台时间和按日分组会按该时区显示。
- 回复框有草稿时，同页刷新结果会暂存到回复关闭后再显示，包括发送根评论后的刷新。发送前已有的列表请求会被提交成功后的刷新替换，刷新沿用尚未完成的页码与排序选择。
- 镜像内置更新后的 SDK。通过 npm 或固定版本 CDN 独立接入的网站，需要另外更新至 `ecoku@0.5.7` 才能获得客户端修复；现有 HTML 接入 markup 无需修改。
- 从早于 v0.5.4 的版本升级时，另读 [v0.5.4 的兼容性说明](./v0.5.4#compatibility)；早于 v0.5.2 时，再读 [首次登录说明](./v0.5.2#compatibility)；早于 v0.5.0 时，还需核对 [来源冲突与历史数据说明](./v0.5.0#compatibility)。

## 升级 {#upgrade}

按 [升级步骤](../upgrade#steps) 停服并冷备份，将镜像改为 `ghcr.io/dejavumoe/ecoku:v0.5.7`，再拉取镜像、重建容器并等待健康。

检查评论加载与提交、写回复时刷新和切换排序、后台登录及时间显示。已启用通知的实例，再确认通知投递。每个实例都要单独升级，包括文档示例背后的服务端。独立使用 npm SDK 的网站固定到 `ecoku@0.5.7` 后重新构建；固定版本 CDN 接入同步更新 SDK 地址。

## 回滚 {#rollback}

从 v0.5.6 升级的实例，停服后将镜像改回 `ghcr.io/dejavumoe/ecoku:v0.5.6`，拉取并启动。schema 相同，无需恢复数据库，升级后的评论和设置会保留。独立 SDK 可固定回 `ecoku@0.5.6` 后重新构建网站。回滚会失去本版的时序修复、时区显示和读取优化；从更早版本升级的实例须核对对应 schema 和回滚说明。
