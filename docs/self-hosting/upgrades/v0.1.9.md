# v0.1.9

停服冷备份 → 修改精确镜像 tag → `sudo docker compose pull && sudo docker compose up -d` → 健康检查与回滚准备。

本页为 v0.1.9 正式版本升级说明（2026-08-31）。部署前请确认 tag 对应的镜像发布流程已成功完成；文档中的版本号不代表镜像已经可拉取。

## 从 v0.1.8 升级的影响

- SQLite 保持 **schema v7**，本版不新增迁移。不删除或重建数据库、评论、设置、WAL 或备份；更早版本仍需依次执行既有迁移。
- Compose 挂载、UID/GID `10001:10001`、端口、日志出口、环境变量和密钥不变。不用替换生产配置模板或清空数据目录。
- 新增可选 `rate_limit.comment_list`，省略时默认 **60**，沿用 `window_seconds`（默认 60 秒）。旧配置可以直接启动。查看[配置参考](../configuration)。
- 公开列表的成功响应继续兼容现有 SDK，但完整线程有 **200 个节点、16 层后代、1 MiB JSON** 的上限；统计探针预算为同站点/页面 **10,000 条 ID/父关系**。超限返回 **422**，不静默截断；减小根 `pageSize` 无法解决单个超大线程、过深线程或整页统计超限。现有 SDK 显示加载失败，不自动改用新分页。
- 自定义接入可用 `parentId` / `afterId` 按需读取单层节点；规则见 [API 参考](../../reference/api)。两种模式共用读取限流、最多 **4 个并发名额**与 **2 秒数据库读取超时**。繁忙或超时返回 503，频控超限返回 429。
- 读取限流在 CORS 数据库查询前执行，预检与被拒绝的 Origin 也计次。提前拒绝不添加未经验证的跨域许可，浏览器可能只显示加载失败。未正确配置 `trusted_proxies` 时，反代后的访客可能共用代理 IP 的额度；核对[反向代理](../reverse-proxy)，不要信任任意来源。
- SQLite 新建或重建连接都会重新启用外键、同步级别与忙等待设置，避免取消事务后丢失这些设置。这不是数据库迁移。

## 升级操作

1. 在 CI/隔离环境确认常见页面及大线程行为符合预期，再安排短暂停服；本流程不承诺零停机。
2. 按[备份与恢复](../backup)停服、制作并校验卷外冷备份，保存 `data/`、`app/config.yaml`、`ecoku.env` 与原 `compose.yaml`。不要在服务运行时只复制主 SQLite 文件。
3. 镜像发布完成后，只把生产 Compose 的 `image` 改为你的仓库中的精确 `v0.1.9` tag。例如 `registry.example.com/ecoku:v0.1.9` 是占位符，应替换为实际仓库。不要覆盖其他生产配置。
4. 在部署目录执行：

   ```bash
   sudo docker compose config --quiet
   sudo docker compose pull && sudo docker compose up -d
   sudo docker compose ps
   sudo docker compose logs --tail=100 ecoku
   curl --fail --silent --show-error http://127.0.0.1:12123/api/health
   ```

5. 健康接口应返回 `status: healthy`。它只证明进程可响应；还需核对容器健康状态、日志，并检查真实站点的列表、排序、翻页、回复及管理端。不要在生产制造深链或高频请求进行压测。

## 回滚到 v0.1.8

先停服。如果曾显式添加 `rate_limit.comment_list`，删除该键或恢复升级前配置；v0.1.8 严格拒绝未知 YAML 字段。恢复精确 `v0.1.8` 镜像 tag，拉取、启动并复查健康与业务。

从 v0.1.8 升级时两版都是 schema v7，通常无需恢复数据库，可以保留升级后的新评论。只有确认数据异常且接受丢失备份后新增数据时，才按备份文档显式恢复整库；不要自动覆盖当前数据库。若原版本更旧，遵循其 schema 回滚要求。回滚会重新暴露 CWE-400，应仅作为故障处置措施。

## CI 与发布顺序

- `master` push 或目标为 `master` 的 PR：运行 client/admin 检查、VitePress 构建与输出检查、Go 测试、vet 和构建。
- 正式发版提交同步 `VERSION`、根 `package.json`、Compose 精确 tag 与带日期的 CHANGELOG v0.1.9 章节及链接；提交 CI 与 tag 镜像发布是独立流程。
- `v0.1.9` tag：只校验版本一致性并构建、发布 amd64/arm64 镜像及 manifest，不重跑测试，也不部署生产或操作生产库。
- 文档站点另由 `master` push 自动构建发布；应用镜像 tag 不会自动更新线上文档。
