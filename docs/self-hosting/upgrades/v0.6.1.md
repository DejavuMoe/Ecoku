# v0.6.1

- 发布日期：2026-11-19
- schema：v12（无迁移）
- 镜像：`ghcr.io/dejavumoe/ecoku:v0.6.1`
- npm SDK：`ecoku@0.6.1`

## 变更 {#changes}

- Twikoo 预检和导入会拒绝含垃圾评论的导出文件并报告数量。仅有 `rid` 的回复可挂到对应的根评论，无路径的 HTTP(S) 首页地址可正常导入。
- 后台评论列表在同一 SQLite 快照中读取计数、分页数据和回复标记，并通过一次查询统计已发布和已删除的评论。公开评论列表逐行读取评论关系，减少冷请求的内存分配。
- 可信代理配置会拒绝实际覆盖全部 IPv4 地址的 IPv4 映射网段。

## 兼容性 {#compatibility}

- schema 保持 v12。从 v0.6.0 升级时，沿用现有数据与配置挂载、容器用户和健康探针。SDK 运行时代码与 0.6.0 相同。
- 若 `site.trusted_proxies` 含覆盖所有 IPv4 地址的 IPv4 映射网段，服务会拒绝启动。升级前按 [反向代理说明](../reverse-proxy#trusted-proxies) 改为实际受信代理的 IP 或有限网段。
- 从 v0.5.7 或更早版本升级时，先阅读 [distroless 迁移说明](../upgrade#distroless)，同步更换旧 Compose 探针。

## 升级 {#upgrade}

按 [升级步骤](../upgrade#steps) 停服并冷备份，将镜像改为 `ghcr.io/dejavumoe/ecoku:v0.6.1`，再拉取并重建容器。确认状态为 `healthy`，检查后台登录、已发布评论和新评论提交。

## 回滚 {#rollback}

停止服务，将镜像改回 `ghcr.io/dejavumoe/ecoku:v0.6.0`，再拉取并重建容器。两个版本均使用 schema v12，保留现有数据库与健康探针即可。
