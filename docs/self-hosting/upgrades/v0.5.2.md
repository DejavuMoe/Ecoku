# v0.5.2

- 发布日期：2026-10-18
- schema：v12（无迁移）
- 镜像：`ghcr.io/dejavumoe/ecoku:v0.5.2`
- npm SDK：`ecoku@0.5.2`

## 变更 {#changes}

- 首次启动不再将管理员临时密码写入应用日志。新实例完成初始化后，停服并运行 `admin reset-password`，从终端输出取得临时密码，再启动服务完成首次改密。
- 增加安全报告策略与私密漏洞报告入口。依赖图、Dependabot 告警和 CodeQL 已启用，自动依赖更新保持关闭。
- 发布说明明确列出本版镜像和 npm SDK 版本；修正历史说明中混入下一版的文档 SDK 同步记录。

## 兼容性 {#compatibility}

- 没有新增数据库迁移，schema 仍为 v12。API、配置键、环境变量、Compose 挂载与容器端口不变。
- 已设置正式密码的管理员继续使用原账户，升级不会重置密码或撤销已有会话。SDK 运行时代码与 v0.5.1 相同，现有接入保持兼容。
- v0.5.1 及更早版本首次启动可能已把临时密码写入日志。仅升级不会使该密码失效；若仍未完成首次改密，按 [首次登录](../docker#first-sign-in) 停服重置并设置正式密码。检查日志副本的访问范围，避免继续传播凭据。
- 从早于 v0.5.0 的版本升级时，另读 [来源冲突与历史数据说明](./v0.5.0#compatibility)。

## 升级 {#upgrade}

按 [升级步骤](../upgrade#steps) 停服并冷备份，将镜像改为 `ghcr.io/dejavumoe/ecoku:v0.5.2`，执行 `sudo docker compose pull && sudo docker compose up -d`。

检查容器健康状态、启动日志、评论加载与提交、后台登录。每个实例都要单独升级，包括为文档示例提供服务的实例。独立安装的 SDK 可在 npm 发布成功后固定到 `ecoku@0.5.2` 并重新构建网站。

## 回滚 {#rollback}

从 v0.5.1 升级的实例，停服后将镜像改回 `ghcr.io/dejavumoe/ecoku:v0.5.1`，拉取并启动。schema 相同，无需恢复数据库，升级后的评论、设置和已重置密码会保留。SDK 可固定回 `ecoku@0.5.1` 后重新构建网站。

回滚会恢复旧版本的启动行为：使用全新数据库时仍可能把初始密码写入日志。已有持久账户不会因回滚重新生成初始密码；从更早版本升级的实例须核对对应 schema 和回滚说明。
