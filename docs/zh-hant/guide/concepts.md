# 運作方式

本頁說明 Ecoku 如何組織評論、如何處理刪除和身分、儲存了哪些資料。部署和接入前讀一遍，可以避開大部分意外。

## 站點與頁面 {#page-key}

Ecoku 用兩個值確定「一篇文章的評論區」：

- **站點 ID**（`siteId`）：在後台註冊站點時設定。一個實例可以有多個站點，彼此的評論、來源白名單和設定互不相通。
- **頁面 key**（`pageKey`）：由接入程式碼提供，通常是文章的站內路徑，例如 `/posts/hello-world/`。

同一站點下，頁面 key 相同的頁面共用一個評論區。頁面 key 必須是站內相對路徑，最多 512 個字元，不能是完整網址，也不能帶 `?` 查詢參數或 `#` 片段。不合規的 key 仍能顯示評論區，但發表評論會被拒絕。

::: warning 頁面 key 一旦使用就不要更改
評論依頁面 key 儲存。如果之後調整了部落格的永久連結格式，舊文章的頁面 key 隨之改變，原來的評論就不會再顯示（資料仍在資料庫中）。選擇頁面 key 時，請用一個不會變動的值。
:::

## 討論串與分頁 {#threads}

評論是樹狀的：一則根評論下面可以有回覆，回覆下面還可以再回覆。

- **層數**：根評論算第 0 層，新回覆最多到第 16 層。回覆第 16 層的評論會被拒絕，並提示改為回覆較上層的評論。
- **縮排**：縮排隨層數增加，到第 3 層為止，更深的回覆與第 3 層對齊。從第 3 層起，暱稱列會顯示可點擊的 `@被回覆者`，指向它所回覆的那則評論。這樣深層討論在手機上也不會被擠成窄條。
- **摺疊**：有回覆的評論旁邊有 `[-]`，點擊後摺疊整個分支，顯示「已折叠 N 条回复」。

分頁只針對根評論。每頁顯示若干則根評論（預設 10 則），**連同它們下面的全部回覆**一起回傳。翻頁時換的是一整批討論，不會發生回覆被拆到下一頁的情況。

為了避免單一超大討論拖垮服務，一次清單請求有上限：最多 200 則評論、16 層、1 MiB 的回應；統計總數時，同一頁面最多檢查 10,000 則評論。超過任何一項時，伺服器端回傳錯誤而不是截斷的資料，評論區顯示載入失敗。一般部落格評論很難觸及這些上限；真的遇到時，可以調低每頁根評論數，或在自訂前端中改用[逐層讀取的 API](../reference/api#cursor)。

## 刪除 {#deletion}

後台提供兩種刪除，都無法復原：

**墓碑刪除**：清空評論的暱稱、信箱、網址和內文，但保留它在討論中的位置和時間。公開頁面顯示為「已删除」和「[该评论已删除]」，它下面的回覆維持原樣，也不能再回覆它。這樣刪掉一則評論不會讓整串討論失去上下文。

**徹底刪除**：把一則墓碑從資料庫中移除。只有下面**沒有任何回覆**的墓碑可以徹底刪除。

## 訪客身分 {#visitor-identity}

訪客發表評論不需要註冊，只要填三項：

| 欄位 | 是否必填 | 是否公開 |
| --- | --- | --- |
| 暱稱 | 必填，最多 80 個字元 | 公開 |
| 信箱 | 預設必填，可在站點設定中改為選填 | 不公開，只用於回覆通知 |
| 網址 | 預設選填，可改為必填；只接受 `http://` 或 `https://` | 公開，作為暱稱上的連結 |

訪客在根評論框填寫的身分，回覆時會自動帶入。直接點擊某則評論下的「回复」時，缺少的身分資訊就在這個回覆框裡填寫，不會跳回頁面頂端。

發布成功後，瀏覽器會記住這份身分 7 天，下次不必重填：

- 保存在瀏覽器的 IndexedDB 中，以一把不可匯出的 AES-GCM 金鑰加密，不寫入 Cookie、localStorage 或網址；
- 依 Ecoku 服務位址和站點 ID 分開保存，不同站點之間不共用；
- 7 天後失效；瀏覽器不支援、資料損毀或過期時，評論框回到空白狀態，不影響發表評論；
- 清除瀏覽器的網站資料即可刪除它，評論區不另設「忘記我」按鈕。

## 部落客身分 {#blogger}

部落客不需要獨立的帳號。在後台為站點設定部落客暱稱、信箱和口令後，部落客在評論區的**暱稱欄**輸入口令、信箱和網址留空即可發布。伺服器端辨識出口令後：

- 把這則評論的暱稱換成部落客暱稱，網址換成站點網址，信箱換成部落客信箱；
- 為這則評論加上部落客標記，頁面上在暱稱後顯示標誌（預設為 `[博主]`）；
- 瀏覽器清空暱稱欄，也不把口令當作身分保存。

部落客標記在評論儲存時寫入，之後不會重新計算。修改部落客暱稱、更換口令都不會改變既有評論的標記。

只有兩種情況會依據「暱稱與部落客暱稱一致、信箱與部落客信箱一致（不區分大小寫）」回填歷史評論的部落客標記：從舊版本升級到 schema v5 時的一次性遷移，以及 [Twikoo 首次匯入](../self-hosting/twikoo)。

## 純文字

評論內文和暱稱一律以純文字顯示：

- HTML 標籤原樣顯示為文字，不會被解析；
- 不轉譯 Markdown，不會把網址自動變成連結；
- 保留換行。

唯一的例外是 [Smoji 貼圖](../integration/smoji)：站點啟用貼圖包後，符合格式且與貼圖清單同源的 `![smoji:名稱](圖片網址)` 會顯示為圖片，其餘一律以文字顯示。

訪客網址只作為暱稱上的連結出現，並帶有 `rel="nofollow ugc noopener noreferrer"`。

## 儲存和公開的資料 {#data}

每則評論在資料庫中儲存：站點 ID、頁面 key、文章標題、父評論、暱稱、信箱、網址、內文、部落客標記、刪除時間、建立和更新時間。

公開 API 回傳的只有：評論 ID、站點 ID、頁面 key、父評論 ID、暱稱、網址、內文、是否為部落客、是否已刪除和時間。**信箱不會出現在任何公開 API 中。**

Ecoku 不儲存訪客的 IP、User-Agent 或地理位置，日誌裡也不記錄這些資訊。IP 只在記憶體中短暫用於速率限制，程式重新啟動後即清空。評論區不請求任何第三方大頭貼、統計或 IP 查詢服務。

以下情況會讓訪客瀏覽器直接連線到第三方：

- 啟用 Turnstile 或 Cap 時，載入驗證元件；
- 啟用 Smoji 時，從清單所在的伺服器載入貼圖圖片。

## 來源檢查與速率限制

每個站點在後台登記「允許來源」。瀏覽器讀取評論時，不在名單中的來源會被拒絕；送出評論時，請求必須帶有已登記的來源，否則直接拒絕。因此評論區只能在你登記過的網站上使用。

送出、讀取、刪除和後台登入都依 IP 進行速率限制，預設每分鐘 5 次送出、60 次讀取。放在反向代理後面時，需要正確設定 [`trusted_proxies`](../self-hosting/reverse-proxy#trusted-proxies)，否則所有訪客會共用同一份額度。

## 時間與時區

評論時間以 `YYYY-MM-DD HH:mm` 格式顯示，時區由容器的 `TZ` 環境變數決定（在 `ecoku.env` 中設定）。滑鼠停在時間上會顯示時區名稱和偏移量，例如 `Asia/Shanghai UTC+8`。
