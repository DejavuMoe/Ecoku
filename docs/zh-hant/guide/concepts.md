# 核心機制與設計模型

Ecoku 的設計圍繞**輕量化**、**純文字直接發布**、**強隱私邊界**與**極簡維運**展開。

---

## 樹狀評論與分頁模型

Ecoku 採用**“無限語意層級 + 最多 3 級視覺縮排”**方案。

### 1. 語意與視覺分層
- **語意層級（Semantic Level）**：DOM 的 `aria-level` 與 `data-depth` 真實反映樹的物理巢狀深度。
- **視覺縮排（Visual Indent）**：透過 `min(depth, 3)` 截斷在第 3 級（桌面端每級 22px，最大 66px；行動端每級 14px，最大 42px）。
- **上下文補償**：當巢狀深度達到第 3 級及以上時，評論元資訊行中會自動添加可點選的 `@被回覆者` 錨點連結。

### 2. 根執行緒分頁演算法
- 分頁參數 `page` 與 `pageSize` 僅作用於頂層根評論（`parent_id IS NULL`）。
- 預算內的成功回應**完整包含**當前頁的公開後代。超過 200 個節點、16 層後代、1 MiB JSON 或 10,000 條統計記錄時回傳 422，不截斷。現有 SDK 顯示載入失敗；自訂接入可用[單層游標 API](../reference/api.md)按需讀取。

## 墓碑機制（Soft Delete & Purge）

1. **墓碑化（軟刪除）**：
   - 擦除暱稱、私有信箱、網址與原始正文，將 `is_blogger` 置為 0，設定 `deleted_at` 時間戳記。
   - 保留評論 ID、頁面 key、`parent_id` 引用關係。
   - 正文顯示為 `[該評論已刪除]`，禁止新增回覆。
2. **徹底刪除（物理清除）**：
   - 僅當墓碑節點**沒有任何子評論**時，實例管理員才可執行物理清除。

## 訪客身分加密儲存
- 使用瀏覽器原生 Web Crypto API 生成不可導出的 256 位元 AES-GCM 金鑰。
- 按 `serverURL + "::" + siteId` 隔離存入 IndexedDB，有效期設定為 7 天。

---

## 站長身分與口令機制
- 管理員在後台為站點設定 12～80 字元的站長口令（bcrypt 哈希儲存）。
- 站長在評論區發表時，**只需在“暱稱”輸入框中輸入該口令**，免填信箱與網址即可認證。

---

## Outbox 交易一致性通知
- 評論寫入與通知分發在同一 SQLite 交易內提交。
- 支援 SMTP（TLS/STARTTLS）與 Telegram 機器人通知。
