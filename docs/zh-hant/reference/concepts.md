# 運作原理

這一頁說明 Ecoku 的幾個核心規則：評論怎樣歸到文章下、回覆怎樣組織、訪客身分怎樣儲存，以及哪些資料會公開。部署和接入時遇到的大部分「為什麼」都能在這裡找到答案。

## 站點與頁面 key {#page-key}

每則評論屬於某個站點裡的某個頁面，由兩個值確定：

| 值 | 來自 | 例子 |
| --- | --- | --- |
| 站點 ID `siteId` | 在後台登記網站時設定 | `blog` |
| 頁面 key `pageKey` | 接入程式碼傳入，通常是文章路徑 | `/posts/hello-world/` |

同一站點下頁面 key 相同的頁面共用一個評論區。頁面 key 是站內路徑，最長 512 個字元，不要寫成完整 URL，也不要帶 `?` 或 `#`，否則評論區能顯示，但提交評論會被拒絕。

::: warning 頁面 key 定下來就不要改
評論依頁面 key 儲存。改了部落格的永久連結格式，舊文章產生的頁面 key 跟著變，原來的評論就不顯示了（資料還在）。把接入程式碼改回原來的產生方式，評論就會回來。
:::

## 討論串與分頁 {#threads}

評論是一棵樹：根評論下有回覆，回覆下還能再回覆。

- 根評論算第 0 層，回覆最多到第 16 層。第 16 層的評論沒有「回覆」按鈕。
- 縮排到第 3 層為止。從第 3 層起，暱稱後顯示 `@被回覆者`，指向它回覆的那則評論。
- 有回覆的評論旁邊有 `[-]`，點擊摺疊整個分支。

分頁只依根評論分：每頁若干則根評論（預設 10 則），連同下面的全部回覆一起顯示。

單次讀取有上限：200 則評論、16 層、1 MiB 回應；統計時同一頁面最多檢查 10,000 則。超過時評論區顯示載入失敗，而不是只顯示一部分。一般部落格碰不到這些上限；碰到時減少每頁根評論數，或在自訂前端裡使用 [逐層讀取介面](./api#cursor)。

## 刪除 {#deletion}

| | 墓碑刪除 | 徹底刪除 |
| --- | --- | --- |
| 結果 | 清空暱稱、信箱、網址和內文，保留位置 | 從資料庫移除 |
| 條件 | 任何評論 | 只限沒有任何回覆的墓碑 |
| 下面的回覆 | 照常顯示 | — |

兩種都不能復原。操作方法見 [處理評論](../admin/comments)。

## 訪客身分 {#visitor-identity}

| 欄位 | 必填 | 公開 |
| --- | --- | --- |
| 暱稱 | 必填，最多 80 個字元 | 公開 |
| 信箱 | 預設必填，可改為選填 | 不公開，只用於通知 |
| 網址 | 預設選填，只接受 `http(s)://` | 公開，顯示為暱稱上的連結 |

點某則評論的「回覆」時，缺少的身分資訊就在這個回覆框裡補填，不會跳回頂部的評論框。

發布成功後，瀏覽器會在本機記住這組身分 7 天：

- 儲存在 IndexedDB 中，用不可匯出的 AES-GCM 金鑰加密，不寫入 Cookie、localStorage 或 URL；
- 依 Ecoku 服務位址和站點 ID 分開儲存；
- 過期或無法使用時，評論框回到空白，不影響發言；
- 清除瀏覽器的網站資料就能清除它。

## 部落客身分 {#blogger}

部落客透過在暱稱欄填口令發言，伺服器認出口令後用站點設定的部落客資訊儲存這則評論，並寫入部落客標記。標記在儲存時確定，之後不再重新計算。設定方法見 [部落客身分](../admin/blogger)。

## 純文字

評論內文和暱稱一律以純文字顯示：HTML 原樣顯示為文字，不轉譯 Markdown，網址不自動變成連結，換行保留。

唯一的例外是 [Smoji 表情](../integration/smoji)：站點啟用後，符合格式和圖片來源規則的 `![smoji:名称](图片地址)` 顯示為圖片。

訪客網址只出現在暱稱的連結上，帶 `rel="nofollow ugc noopener noreferrer"`。

## 儲存和公開的資料 {#data}

| | 內容 |
| --- | --- |
| 資料庫儲存 | 站點 ID、頁面 key、文章標題、父評論、暱稱、信箱、網址、內文、部落客標記、刪除時間、建立和更新時間 |
| 公開介面回傳 | 評論 ID、站點 ID、頁面 key、父評論 ID、暱稱、網址、內文、是否部落客、是否已刪除、時間 |
| 不儲存 | 訪客 IP、User-Agent、地理位置 |

信箱不會出現在任何公開介面裡。連線 IP 只在記憶體中短暫用於限流，重新啟動即清空，日誌裡也沒有。

訪客瀏覽器只在兩種情況下直接連線第三方：啟用了 Turnstile 或 Cap 時載入驗證元件；啟用了 Smoji 時從清單和圖片所在的伺服器載入資源。

## 來源檢查與限流 {#origins}

每個站點在後台登記「允許來源」。瀏覽器從其他來源讀取評論會被拒絕，提交評論必須帶有已登記的來源，所以評論區只能用在你登記過的網站上。

提交、讀取、刪除和後台登入都依 IP 限流，預設每分鐘 5 次提交、60 次讀取。放在反向代理後面時要設定 [`trusted_proxies`](../self-hosting/reverse-proxy#trusted-proxies)，否則所有訪客共用一個額度。

## 時間與時區

評論時間顯示為 `YYYY-MM-DD HH:mm`，時區由 Compose 裡的 `TZ` 決定，見 [時區與後台語言](../self-hosting/docker#timezone)。滑鼠停在時間上可以看到時區。
