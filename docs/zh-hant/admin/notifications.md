# 通知

有新評論時，Ecoku 可以寄電子郵件或傳 Telegram 訊息給你；訪客的評論被人回覆時，Ecoku 會寄電子郵件告訴這位訪客。在後台「通知」頁設定，對所有站點生效。

- 新評論寄到你的信箱或 Telegram
- 訪客被回覆時收到電子郵件

- `app/config.yaml` 裡填了 `notifications.instance_public_url`
- 伺服器能連上 SMTP 連接埠（465 / 587）或 `api.telegram.org`

## 電子郵件 {#email}

在「通知」頁填寫 SMTP 資訊：

| 欄位 | 說明 |
| --- | --- |
| SMTP 伺服器 | 例如 `smtp.example.com` |
| 連接埠 / 加密方式 | 465 配 `SSL/TLS`，587 配 `STARTTLS`。不支援不加密的連線。 |
| 使用者名稱 | 留空則不做 SMTP 驗證 |
| 密碼 | 必填。儲存後不再顯示，留空表示不修改。 |
| 寄件人地址 | 郵件的 From。很多服務商要求和登入帳號一致。 |
| 通知收件人 | 接收新評論通知的信箱，可以填多個 |

點「發送測試郵件」，它直接用表單裡的值寄信，不需要先儲存。收到後再儲存。

郵件主旨是這樣的：

- 「您在 [站点名称] 上有新评论：[文章标题]」
- 「您在 [站点名称] 上有新回复：[文章标题]」
- 給訪客的：「你在 [站点名称] 的评论收到了回复：[文章标题]」

郵件裡有文章標題、時間、評論者、內文和文章連結，回覆通知還附上被回覆的評論。寄件者顯示名稱是站點名稱。

## Telegram {#telegram}

Telegram 只通知你，不通知訪客。

<div class="steps">

### 建立機器人

找 [@BotFather](https://t.me/BotFather) 建立一個機器人，取得 Bot Token。

### 讓機器人能傳訊息給你

私訊的話，先傳一則訊息給機器人。群組或頻道要把它加進去，頻道還要設為管理員。

### 填寫並測試

在後台填入 Token 和接收方的數字 ID（個人是一串數字，群組和頻道通常以 `-100` 開頭；不支援 `@使用者名稱`）。點「發送測試訊息」，收到後儲存。

</div>

## 什麼時候傳送 {#when}

「部落客」指用 [部落客口令](./blogger) 發布的評論。

| 誰做了什麼 | 通知你 | 以電子郵件通知被回覆的訪客 |
| --- | :---: | :---: |
| 訪客發表評論 | ✓ | — |
| 訪客回覆訪客 | ✓ | ✓ |
| 訪客回覆你 | ✓ | — |
| 你發表或回覆 | — | 回覆訪客時 ✓ |

被回覆的訪客沒留信箱、自己回覆自己，或者電子郵件管道沒啟用時，不寄電子郵件給訪客。

## 傳送與重試

通知不在送出評論時同步傳送，而是進入佇列，背景每 3 秒取出一批。郵件伺服器暫時連不上，不影響訪客發表評論。

- 每個收件者單獨傳送、單獨重試。
- 失敗後間隔 2、4、8 … 128 分鐘重試，最多 8 次。
- 位址不存在、被拒收、機器人被移出這類永久錯誤不再重試。
- 極少數情況下（程序恰好在寄出後當機）可能重複收到一次。

日誌只記錄通知編號和錯誤類型，不記錄收件位址、評論內容或密碼。

## 刪除評論之後 {#after-deletion}

在後台刪除一則評論後：

- 與它有關、還沒寄出的通知不再傳送；
- 以後有人回覆它，不會再寄電子郵件給它的作者；
- 已經傳送的 Telegram 訊息會被改寫為「这条评论已被删除，通知内容已移除。」；
- 已經寄出的電子郵件無法撤回。

通知紀錄保留 30 天，超過後已傳送的 Telegram 訊息就無法再改寫。

## 常見問題 {#troubleshooting}

**啟用時提示「請求參數不符合要求，請檢查後重試。」**
多半是 `app/config.yaml` 裡沒填 `notifications.instance_public_url`。填好後重建容器。

**測試郵件逾時**
通常是雲端服務商封鎖了 SMTP 對外連接埠。在伺服器上執行 `nc -vz smtp.example.com 465` 看能否連通，再確認連接埠和加密方式是否相符。

**容器啟動失敗，日誌提示「通知凭据校验失败」**
SMTP 密碼等憑證用 `data/ecoku-secrets.json` 裡的金鑰加密。確認它和資料庫來自同一份備份，權限為 `600`。不要刪掉它，見 [備份與還原](../self-hosting/backup#restore)。
