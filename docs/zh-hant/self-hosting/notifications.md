# 通知

Ecoku 可以在有新評論時通知部落客，並在訪客的評論被回覆時寄送電子郵件通知對方。通知在後台的「通知」頁設定，對整個實例的所有站點生效。

修改管道設定後，在底部儲存列點擊「保存」。電子郵件和 Telegram 分別驗證、分別儲存；一個管道有錯誤時，另一個有效管道仍可儲存，尚未儲存的修改會留在原頁。

| 管道 | 寄給誰 |
| --- | --- |
| 電子郵件（SMTP） | 部落客：寄到你填寫的收件者清單。訪客：寄到被回覆的評論所留下的信箱。 |
| Telegram 機器人 | 只傳給部落客：傳到你填寫的使用者、群組或頻道 ID。 |

## 啟用前的準備

- `app/config.yaml` 中已填寫 `notifications.instance_public_url`，否則無法啟用任何管道。
- `ecoku.env` 中已設定 `ECOKU_NOTIFICATION_ENCRYPTION_KEY`。SMTP 密碼和 Bot Token 需要用它加密後才能儲存。
- 伺服器能連線到外部的 SMTP 連接埠（常見為 465 或 587）或 `api.telegram.org`。部分雲端服務商預設封鎖 SMTP 對外連接埠。

## 什麼時候寄送通知

是否為「部落客」，看的是評論儲存時記錄的部落客標記，也就是這則評論是否以[部落客口令](./admin#blogger)發布。

| 情境 | 通知部落客（電子郵件 / Telegram） | 以電子郵件通知被回覆的訪客 |
| --- | :---: | :---: |
| 訪客發表根評論 | 寄送 | — |
| 訪客回覆訪客 | 寄送 | 寄送 |
| 訪客回覆部落客 | 寄送 | — |
| 部落客發表根評論 | 不寄送 | — |
| 部落客回覆訪客 | 不寄送 | 寄送 |
| 部落客回覆部落客 | 不寄送 | — |

此外：

- 被回覆的訪客沒有留下信箱，或者回覆者與被回覆者的信箱相同（自己回覆自己），不寄送訪客郵件。
- 被回覆的評論在通知寄出前已被刪除，訪客郵件會取消。
- 評論本身在通知寄出前被刪除，寄給部落客的郵件和 Telegram 訊息也會取消。已經寄出的通知見[刪除評論之後](#after-deletion)。
- 訪客回覆通知只在電子郵件管道啟用時寄送，沒有獨立的開關。關閉電子郵件管道後，訪客回覆通知也不再寄送。
- Telegram 不會通知訪客。

## 電子郵件

| 欄位 | 說明 |
| --- | --- |
| SMTP 服务器 | 例如 `smtp.example.com`。 |
| 端口 | 依郵件服務商的要求填寫，常見為 465（SSL/TLS）或 587（STARTTLS）。 |
| 加密方式 | `SSL/TLS`：連線時即加密；`STARTTLS`：先建立一般連線再升級。不支援不加密的 SMTP。 |
| 用户名 | 可留空，留空時不進行 SMTP 驗證。密碼仍然必填，不需要驗證的伺服器可以填任意值。 |
| 密码 | 儲存後只顯示「已设置」，留空表示不修改。 |
| 发件人地址 | 郵件的 From 位址。很多服務商要求它與登入帳號一致。 |
| 通知收件人 | 接收部落客通知的信箱，可填多個，以 Enter 或逗號分隔。 |

「发送测试邮件」會用目前表單中的值（密碼留空則使用已儲存的密碼）寄一封測試郵件給收件者，不需要先儲存。失敗時頁面會列出原因，例如連線逾時、驗證未通過或 TLS 交握失敗。

郵件同時包含純文字和 HTML 兩個版本。HTML 版與評論區、管理後台使用同一套紙墨配色，文字使用收件裝置內建的中英文無襯線字型，不載入網路字型；支援深色模式的郵件用戶端會自動切換為深色。內容依類型不同：

- 部落客收到新評論：文章標題、發布時間、評論者與評論內文，以及「查看原文」連結；
- 部落客收到新回覆：文章標題、發布時間、被回覆的評論、回覆者與回覆內文，以及「查看原文」連結；
- 訪客收到回覆：文章標題、回覆時間、訪客自己的評論、回覆內文，以及「查看回复」連結。

時間依容器的 `TZ` 顯示，與評論區一致，並註明時區偏移，如 `2026/09/29 10:18 (UTC+8)`。部落客本人的評論在暱稱後顯示站點設定的部落客標誌。

表情包只在站點已啟用表情包、且圖片與目前表情包清單同源時顯示為圖片，圖片從表情包所在的伺服器載入，與評論區相同；郵件用戶端封鎖外部圖片時顯示為 `[表情：标签]`。其他情況以及純文字版本中都顯示為 `[表情：标签]`。

郵件主旨：

- 部落客通知：「您在 [站点名称] 上有新评论：[文章标题]」或「您在 [站点名称] 上有新回复：[文章标题]」
- 訪客回覆通知：「你在 [站点名称] 的评论收到了回复：[文章标题]」

文章標題超過 60 個字元時截斷；頁面沒有標題時，主旨不附加標題。寄件者顯示名稱為站點名稱，位址仍是「发件人地址」。郵件帶有 `Auto-Submitted: auto-generated` 標頭，自動回覆程式通常不會回信。

## Telegram

1. 在 Telegram 中找 [@BotFather](https://t.me/BotFather) 建立機器人，取得 Bot Token。
2. 讓機器人能傳訊息給你：私訊的話，先傳一則訊息給機器人；群組或頻道則把機器人加進去，頻道還需要將它設為管理員。
3. 查出接收目標的 ID：個人使用者是一串數字，例如 `123456789`；群組和頻道通常以 `-100` 開頭，例如 `-1001234567890`。
4. 在後台填入 Bot Token 和接收目標 ID（可填多個），點擊「发送测试消息」確認後再儲存。

訊息包含站點名稱、文章標題、發布時間、評論者或回覆者、被回覆的原評論（以引用區塊顯示，最多 400 個字元）和內文（最多 1000 個字元），結尾附上「查看原文」連結。表情包顯示為 `[表情：标签]`。

## 投遞方式

通知不會在送出評論時同步寄送。評論和它要寄送的通知會在同一個資料庫交易中寫入一張待寄佇列，背景工作每 3 秒取出一批寄送。因此：

- 郵件伺服器暫時連不上，不影響訪客發表評論。
- 每個收件者各自一筆記錄、各自重試。一個位址失敗不影響其他位址。
- 失敗後依 2、4、8、16、32、64、128 分鐘的間隔重試，總共嘗試 8 次，之後放棄。
- 重試也不會成功的失敗直接放棄：收件信箱不存在或郵件被伺服器拒收（SMTP 55x）、Telegram 找不到對話或機器人被移出、封鎖（HTTP 400/403）。Telegram 要求限速（HTTP 429）時，依它給出的等待時間延後。
- 已寄出、已取消和已放棄的紀錄保留 30 天，之後自動清理。
- 通知在加入佇列時就決定了寄給誰。之後關閉管道或修改收件者，已經加入佇列的通知仍會照原樣投遞。
- 程式若在「已寄出、尚未記錄結果」的瞬間當掉，重新啟動後可能會再寄一次。極少數情況下會收到重複通知。

日誌只記錄通知編號、錯誤類型和次數，不記錄收件位址、評論內容或憑據。

## 刪除評論之後 {#after-deletion}

在後台刪除一則評論後：

- 還沒寄出的通知不再寄送，包括寄給部落客的郵件和 Telegram 訊息。
- 別人對這則評論的回覆不會再寄郵件給它的作者，佇列中記錄的該信箱位址也一併刪除。
- 已經寄出的 Telegram 訊息會被改寫為「这条评论已被删除，通知内容已移除。」，只保留站點名稱和文章標題。
- 已經寄出的郵件無法撤回。

以下情況無法改寫已寄出的 Telegram 訊息：通知寄出已超過 30 天，紀錄已經清理；撤回完成前就徹底刪除了這則墓碑；程序在訊息寄出後、記錄結果前當機。

## 常見問題 {#troubleshooting}

**啟用管道時儲存失敗，提示「请求参数不符合要求，请检查后重试。」**：如果表單填寫無誤，多半是沒有填寫實例公開網址。在 `app/config.yaml` 中填寫 `notifications.instance_public_url` 後重建容器。

**儲存時提示「服务端暂时无法完成操作，数据没有被修改。」**：多半是沒有設定加密主金鑰。在 `ecoku.env` 中設定 `ECOKU_NOTIFICATION_ENCRYPTION_KEY` 後重建容器，見 [Docker 部署](./docker#env)。

**測試郵件逾時**：多半是伺服器的 SMTP 對外連接埠被封鎖。先在伺服器上用 `nc -vz smtp.example.com 465` 確認能連通，再檢查連接埠與加密方式是否相符（465 對應 SSL/TLS，587 對應 STARTTLS）。
