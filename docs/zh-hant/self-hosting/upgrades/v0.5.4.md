# v0.5.4

- 發布日期：2026-10-23
- schema：v12（無遷移）
- 映像檔：`ghcr.io/dejavumoe/ecoku:v0.5.4`
- npm SDK：`ecoku@0.5.4`

## 變更 {#changes}

- SDK 重新載入時若目前末頁已因評論刪除而消失，會重新載入仍有效的末頁；評論全部刪除後恢復第 1 頁。導覽或銷毀前的舊請求不會覆蓋目前頁面。
- `setPageKey()` 與初始化統一處理文章標題：去除首尾空白，並截取前 200 個 UTF-16 碼元，避免導覽後提交過長標題遭拒。
- JavaScript 呼叫缺少 `siteId` 時，SDK 在掛載或發起請求之前回報錯誤。
- 修復首次管理員設定與並行讀取憑證、實例金鑰之間的資料競爭，增加對應 race 回歸檢查。
- 更新 Vite、DOMPurify 與 Go 建置工具鏈至修復版本。

## 相容性 {#compatibility}

- 沒有新增資料庫遷移，schema 仍為 v12。HTTP 介面、設定鍵、環境變數、Compose 掛載與容器連接埠不變；管理員帳戶、實例金鑰和已儲存評論的格式不變。
- 前端三項修復需要更新 SDK；首次設定的並行修復需要更新伺服器映像檔。JavaScript 接入必須提供有效的 `siteId`，缺少時會立即回報錯誤。
- 從早於 v0.5.2 的版本升級時，另讀 [v0.5.2 的首次登入說明](./v0.5.2#compatibility)；早於 v0.5.0 時，再讀 [來源衝突與歷史資料說明](./v0.5.0#compatibility)。

## 升級 {#upgrade}

依 [升級步驟](../upgrade#steps) 停服並冷備份，將映像檔改為 `ghcr.io/dejavumoe/ecoku:v0.5.4`，依通用步驟拉取映像檔、重建容器並等待健康。

檢查容器健康狀態、啟動日誌、評論載入與提交、後台登入。每個實例都要單獨升級，包括為文件範例提供服務的實例。獨立安裝的 SDK 可在 npm 發布成功後固定到 `ecoku@0.5.4` 並重新建置網站；固定版本的 CDN 接入也需同步更新 SDK 位址。

## 回滾 {#rollback}

從 v0.5.3 升級的實例，停服後將映像檔改回 `ghcr.io/dejavumoe/ecoku:v0.5.3`，拉取並啟動。schema 相同，無需還原資料庫，升級後的評論和設定會保留。SDK 可固定回 `ecoku@0.5.3` 後重新建置網站。回滾會恢復本版修復前的行為；從更早版本升級的實例須核對對應 schema 和回滾說明。
