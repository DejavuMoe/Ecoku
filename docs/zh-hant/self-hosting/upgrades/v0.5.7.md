# v0.5.7

- 發布日期：2026-11-12
- schema：v12（無遷移）
- 映像檔：`ghcr.io/dejavumoe/ecoku:v0.5.7`
- npm SDK：`ecoku@0.5.7`

## 變更 {#changes}

- 公開讀取使用獨立的 SQLite 唯讀連線池，重用資料庫未變更時的列表、站點和人機驗證設定結果；評論列表支援 `ETag` 與條件請求，減少重複讀取。
- HTML 載入器依 SDK 內容雜湊請求資源，並在下載 SDK 的同時預取第一頁評論。
- 修復排序、換頁、同頁重新整理和回覆提交交錯時遺失草稿、恢復舊排序或不顯示新評論的問題；保留同頁重新整理的折疊狀態，清空內文時同步更新預覽。
- 管理後台的時間與日期分組使用實例 `TZ`；恢復工作階段時，語言與時區設定載入失敗會自動重試。
- 更新 SQLite 驅動、建置和測試工具鏈；文件固定流程圖改用本地 SVG，移除 Mermaid 執行時與相依套件。

## 相容性 {#compatibility}

- 沒有新增資料庫遷移，schema 仍為 v12。SQLite 驅動更換不改變資料庫結構；設定鍵、環境變數、Compose 掛載和容器連接埠不變。
- `GET /api/admin/login-config` 新增 `timeZone`。預設時區仍為 `Asia/Shanghai`；已設定其他 `TZ` 的實例，後台時間和按日分組會依該時區顯示。
- 回覆框有草稿時，同頁重新整理結果會暫存到回覆關閉後再顯示，包括發送根評論後的重新整理。發送前既有的列表請求會被提交成功後的重新整理取代，重新整理沿用尚未完成的頁碼與排序選擇。
- 映像檔內建更新後的 SDK。透過 npm 或固定版本 CDN 獨立接入的網站，需要另外更新至 `ecoku@0.5.7` 才能取得用戶端修復；既有 HTML 接入 markup 無需修改。
- 從早於 v0.5.4 的版本升級時，另讀 [v0.5.4 的相容性說明](./v0.5.4#compatibility)；早於 v0.5.2 時，再讀 [首次登入說明](./v0.5.2#compatibility)；早於 v0.5.0 時，還需核對 [來源衝突與歷史資料說明](./v0.5.0#compatibility)。

## 升級 {#upgrade}

依 [升級步驟](../upgrade#steps) 停服並冷備份，將映像檔改為 `ghcr.io/dejavumoe/ecoku:v0.5.7`，再拉取映像檔、重建容器並等待健康。

檢查評論載入與提交、撰寫回覆時重新整理和切換排序、後台登入及時間顯示。已啟用通知的實例，再確認通知投遞。每個實例都要單獨升級，包括文件範例背後的伺服器。獨立使用 npm SDK 的網站固定到 `ecoku@0.5.7` 後重新建置；固定版本 CDN 接入同步更新 SDK 位址。

## 回滾 {#rollback}

從 v0.5.6 升級的實例，停服後將映像檔改回 `ghcr.io/dejavumoe/ecoku:v0.5.6`，拉取並啟動。schema 相同，無需還原資料庫，升級後的評論和設定會保留。獨立 SDK 可固定回 `ecoku@0.5.6` 後重新建置網站。回滾會失去本版的時序修復、時區顯示和讀取最佳化；從更早版本升級的實例須核對對應 schema 和回滾說明。
