# v0.3.2

- 發布日期：2026-10-04
- schema：v12（無遷移）
- 映像檔：`ghcr.io/dejavumoe/ecoku:v0.3.2`
- npm SDK：`ecoku@0.3.2`

## 變更 {#changes}

- 後台的站點、通知和安全設定改用帶邊框的輸入框，減少橫線與底線。允許來源、通知收件人和 Telegram 接收目標改為逐項輸入：按 Enter 新增下一項，可一次貼上多行；有誤的項目在下方提示，來源缺少協定或帶有路徑時可一鍵修正，重複項目儲存時合併。
- 通知郵件頁首改用「區」印章。印章以內嵌圖片隨郵件傳送，不從網路載入。
- SDK 的 `i18n` 參數同時決定評論區文字、`lang` 屬性和 Cap 驗證元件的語言，不再被站點語言覆寫。英語與繁體中文評論區在未完成人機驗證時給出對應提示。
- 後台重新整理後保持 `ECOKU_ADMIN_LOCALE` 設定的語言，英語與繁體中文介面補齊先前未翻譯的文案；進入後台時不再出現焦點框。

## 相容性 {#compatibility}

- 沒有資料庫遷移，schema 仍為 v12。Compose、掛載、設定項和環境變數不變。
- 站點介面的 `i18n` 只接受 `zh-CN`、`zh-Hant`、`en`（及 `zh-TW`、`en-US` 等地區寫法），其他值回傳 `400`；先前會被改成 `zh-CN`。以腳本呼叫管理介面時，請檢查傳入的值。
- `ECOKU_ADMIN_LOCALE` 無效時照常啟動，後台使用 `zh-CN`，並在啟動日誌中提示。
- 通知郵件的 HTML 部分改為 `multipart/related`，每封郵件多帶一個 2.5 KB 的內嵌 PNG。純文字版本不變。
- 接入時傳入 `i18n` 的網站，評論區的 `lang` 屬性和 Cap 元件語言會隨之改變。

## 升級 {#upgrade}

1. 停服並 [冷備份](../backup#cold-backup) 資料庫、`ecoku-secrets.json`、Compose 和設定檔。
2. 按 [升級步驟](../upgrade#steps) 將映像檔改為 `ghcr.io/dejavumoe/ecoku:v0.3.2`，執行 `sudo docker compose pull && sudo docker compose up -d`。
3. 檢查容器健康狀態、管理員登入、站點與通知設定；傳送一封測試郵件，確認頁首印章正常顯示。
4. npm 發布成功後，使用 `pnpm add --save-exact ecoku@0.3.2` 更新獨立接入的 SDK 並重新建置網站。容器內建 SDK 隨映像檔更新。

## 回滾 {#rollback}

schema 沒有變化。停服後將映像檔改回 `ghcr.io/dejavumoe/ecoku:v0.3.1`，拉取並啟動即可，不需要還原資料庫；升級後新增的評論和設定修改會保留。
