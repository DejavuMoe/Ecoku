# v0.2.0

停服冷備份 → 修改精確鏡像 tag → `sudo docker compose pull && sudo docker compose up -d` → 健康與業務檢查。

本版本主要校正並完善文件、接入範例與 API 參考（2026-09-12）。

## 升級影響

- SQLite 維持 **schema v7**，沒有資料庫遷移。
- 環境變數、Compose 掛載、連接埠、容器權限與執行期資料格式不變。
- 公開評論列表的預算、游標分頁、讀取頻控與狀態碼文件已與 v0.1.9 實作一致。

## 升級操作

1. 在隔離環境檢查頁面、評論列表、回覆與管理端。
2. 停服並備份 `data/`、`app/config.yaml`、`ecoku.env` 與原有 `compose.yaml`。
3. 將 `compose.yaml` 的 `image` 改為 `git.via.moe/dejavu/ecoku:v0.2.0`，不要修改其他設定。
4. 執行：

   ```bash
   sudo docker compose config --quiet
   sudo docker compose pull && sudo docker compose up -d
   sudo docker compose ps
   sudo docker compose logs --tail=100 ecoku
   curl --fail --silent --show-error http://127.0.0.1:12123/api/health
   ```

5. 確認健康介面、實際評論列表、排序、分頁、回覆與管理端正常。

## 回滾至 v0.1.9

停服後恢復精確 `v0.1.9` 鏡像 tag，拉取並啟動。兩版均為 schema v7，通常無需恢復資料庫；只有確認資料異常時才依冷備份流程恢復整庫。
