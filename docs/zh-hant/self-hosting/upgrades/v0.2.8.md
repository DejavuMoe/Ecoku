# v0.2.8

- 發布日期：2026-10-01
- schema：v9（從 v0.2.7 升級不變）
- 映像檔：`git.via.moe/dejavu/ecoku:v0.2.8`

## 變更 {#changes}

- 管理後台的評論依日期分組，刪除時在評論旁確認；設定表單改為列式欄位，有修改時才顯示儲存列，離開尚未儲存的頁面前會提示。增加鍵盤快捷鍵與窄螢幕底部導覽，管理後台和文件站使用「區」印章標誌。
- 站點儲存失敗時保留尚未儲存的名稱、博主口令等草稿；通知和安全設定載入失敗時停用表單並提供重試。
- 官方映像檔內建日誌、評論區資源、管理後台資源和 SQLite 路徑，預設啟用管理後台。`*_env` 欄位省略時使用標準環境變數名稱；`admin.allowed_origins` 省略時取 `notifications.instance_public_url` 的來源。具體值見[設定參考](../../reference/configuration)。
- 部署範本精簡：`app/config.yaml` 只需填寫 `notifications.instance_public_url`；`ecoku.env` 不再重複設定映像檔已有的 `GIN_MODE`；Compose 使用 Docker 守護行程的日誌設定。

## 相容性 {#compatibility}

- 從 v0.2.7 升級不執行資料庫遷移，schema 仍為 v9。評論區與 SDK、HTTP 介面、Compose 掛載和既有設定欄位保持不變。
- 舊的完整設定檔與 Compose `logging` 設定仍可使用，無需刪減。明確設定的值優先於預設值；管理員憑證、通知加密金鑰與資料目錄繼續使用原值。
- 容器目錄與管理後台開關的預設值由映像檔中的 `ECOKU_RUNTIME=container` 啟用；從原始碼執行時保留原本的目錄與開關預設值。
- v0.2.7 不支援新的精簡設定；如果升級時刪掉了原本的明確設定，回滾前需要還原完整設定。

## 升級 {#upgrade}

1. 依照[備份與還原](../backup#cold-backup)停止服務並做冷備份，保留原本的 `compose.yaml`、`app/config.yaml` 和 `ecoku.env`。
2. 依照[升級步驟](../upgrade#steps)操作，映像檔改為 `git.via.moe/dejavu/ecoku:v0.2.8`。現有部署可以繼續使用原設定，無需換成精簡範本。
3. 健康檢查通過後，確認評論區能載入、發布，管理後台能登入，評論刪除與站點、通知設定儲存正常。

## 回滾 {#rollback}

回到 v0.2.7 時 schema 相同，可以保留目前資料庫及升級後產生的評論和設定修改：

1. 停止服務；如果採用了精簡 `app/config.yaml`，先還原升級前的完整設定。
2. 把映像檔改回 `git.via.moe/dejavu/ecoku:v0.2.7`，依照[升級步驟](../upgrade#steps)拉取、啟動並檢查。

v0.2.6 及更早版本無法開啟 schema v9 資料庫。回到這些版本時，必須[還原](../backup#restore)對應舊 schema 的冷備份，備份之後的評論和設定修改會遺失。
