# v0.2.3 升級說明（待發佈）

停服冷備份並驗證 → 改精確鏡像 tag → `sudo docker compose pull && sudo docker compose up -d` → 健康與業務檢查、必要時回滾。

準備日期：2026-09-16。等待 master CI 驗收及後續 tag 發佈；鏡像建置成功後再升級。

## 主要修復

- 儲存站點設定不再重新授予歷史留言站長身分；口令限制 UTF-8 72 位元組，既有 bcrypt 雜湊繼續有效。
- SMTP 全流程支援取消及逾時；通知完成寫入失敗只重試資料庫；Telegram 保留完整連結與 HTML。
- Twikoo 亂序匯入保留直接父子關係；修復 Unicode 輸入、管理請求取消、Loader 重試、Smoji URL/鍵盤與非同步控件清理。
- SPA 可用 `setPageKey(pageKey, pageTitle)` 更新標題；省略第二參數會清空舊標題。直接 SDK 的外部 CSS 仍需宿主自行載入。

## 升級相容性

本次修復保持 schema v7、掛載路徑、環境變數與 bcrypt 雜湊格式，可由 v0.2.2 原位升級，不刪除留言、設定、WAL 或備份。儲存站點設定不再回填博主標記，既有標記保留；歷史誤標無法自動與口令驗證記錄區分，需另行核實及授權修正。通知採至少一次投遞：完成狀態寫入失敗時重試寫回，本程序不重送；成功投遞後、持久化前崩潰，重啟可能重送。

## 升級步驟

1. 依 [備份說明](../backup) 停服並驗證卷外冷備份。保存 `data/`（含 WAL/SHM）、`app/config.yaml`、`ecoku.env` 及原 `compose.yaml`。
2. 鏡像發佈後，把 Compose image 改為 `git.via.moe/dejavu/ecoku:v0.2.3`。設定、環境變數與掛載維持不變。
3. 執行下列命令，再檢查管理登入、歷史留言、站長身分及通知；真實通知測試由操作者明確執行。

```bash
sudo docker compose pull && sudo docker compose up -d
sudo docker compose logs --tail=100 ecoku
curl --fail --silent --show-error http://127.0.0.1:12123/api/health
```

## 回滾至 v0.2.2

兩版均為 schema v7，通常可停服後改回 `git.via.moe/dejavu/ecoku:v0.2.2`，拉取並啟動，保留目前資料庫與新留言，但舊版缺陷也會恢復。只有確需升級前資料才恢復整套冷備份；先保留現場並明確接受備份後寫入遺失，不自動覆蓋資料庫。
