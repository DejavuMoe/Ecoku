# v0.3.7

- 發布日期：2026-10-06
- schema：v12（無遷移）
- 映像檔：`ghcr.io/dejavumoe/ecoku:v0.3.7`
- npm SDK：`ecoku@0.3.7`

## 變更 {#changes}

- 公開評論清單跳過葉節點的無效查詢，管理清單重用狀態統計，保留排序、分頁和讀取上限。
- 評論刪除與通知最終傳送協調，傳送前重新檢查狀態；刪除父評論後，已傳送直接回覆的 Telegram 訊息會排入佇列移除父引用，保留回覆內文。
- 登入設定、管理查詢和通知 worker 繼承取消訊號；補齊 Cap IPv6 位址檢查，金鑰檔案替換失敗時保留舊檔案。
- 原始碼啟動預設僅監聽 `127.0.0.1`；開發示範頁固定連線到本機 API。
- 最佳化 Docker 建置階段和 CI 相依套件安裝；固定基礎映像檔 digest，並為雙架構發布增加執行檢查、SBOM 和弱點掃描。
- 更新 Vue 至 `3.5.42`、`source-map-js` 至 `1.2.2`，修正相依套件稽核發現的高風險弱點。
- 修正映像檔驗證容器的日誌驅動程式參數，使執行檢查能夠正常啟動。
- 容器建置升級 OpenSSL 執行階段函式庫，要求 `libcrypto3`、`libssl3` 至少為 `3.5.8-r0`，修正映像檔掃描中的 `CVE-2026-14456` 相依套件命中。

## 相容性 {#compatibility}

- 沒有資料庫遷移，schema 仍為 v12。Compose 掛載、設定鍵、環境變數和容器監聽方式不變。
- 原始碼模式不再預設對區域網路開放；容器部署繼續依照既有 Compose 連接埠和反向代理設定存取。
- 刪除可能等待已經開始的通知投遞結束，單筆投遞期限為 20 秒。已傳送郵件無法召回，Telegram 更新以非同步方式完成；完整邊界見 [刪除評論之後](../notifications#after-deletion)。
- HTTP 介面和正式 SDK 保持相容，獨立接入的 `ecoku@0.3.5` 可繼續使用。

## 升級 {#upgrade}

1. 停服並 [冷備份](../backup#cold-backup) 資料庫、`ecoku-secrets.json`、Compose 和設定檔。
2. 按 [升級步驟](../upgrade#steps) 將映像檔改為 `ghcr.io/dejavumoe/ecoku:v0.3.7`，執行 `sudo docker compose pull && sudo docker compose up -d`。
3. 檢查容器健康狀態、啟動日誌、評論載入和後台登入。已設定通知的實例同時觀察投遞和刪除後的 Telegram 更新是否正常。
4. 如需統一 SDK 版本，等 npm 發布成功後使用 `pnpm add --save-exact ecoku@0.3.7` 並重新建置網站。容器內建 SDK 隨映像檔更新。

## 回滾 {#rollback}

schema 沒有變化。停服後將映像檔改回 `ghcr.io/dejavumoe/ecoku:v0.3.5`，拉取並啟動即可，不需要還原資料庫；升級後新增的評論和設定修改會保留。獨立安裝的 npm SDK 可固定回 `ecoku@0.3.5` 後重新建置網站。

回滾會撤回本版的效能和安全修正。舊版本會取消尚未完成的存活回覆引用更新任務，回滾前應確認需要移除的 Telegram 父引用已經改寫完成。
