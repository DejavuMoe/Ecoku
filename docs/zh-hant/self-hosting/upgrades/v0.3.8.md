# v0.3.8

- 發布日期：2026-10-09
- schema：v12（無遷移）
- 映像檔：`ghcr.io/dejavumoe/ecoku:v0.3.8`
- npm SDK：`ecoku@0.3.8`

## 變更 {#changes}

- Go 工具鏈與容器建置映像檔升級至 `1.27.2`，`golang.org/x/net` 升級至 `v0.60.0`，並同步相關相依套件，修正弱點稽核命中的 HTTP/2、HTTP/1、MIME 與 TLS 弱點。
- 三語文件依原始碼複核，修正部署、備份、REST API 與接入說明，補齊 HTML 屬性取值、`pageKey` 限制和 Twikoo 匯入的停服步驟。

## 相容性 {#compatibility}

- 沒有資料庫遷移，schema 仍為 v12。Compose 掛載、設定鍵、環境變數、容器連接埠和 HTTP 介面不變。
- 管理端與 SDK 執行階段程式碼與 v0.3.7 相同；獨立安裝的 `ecoku@0.3.7` 可繼續使用。
- 從原始碼建置時，相依套件要求最低 Go `1.26.0`，專案透過 `mise.toml` 和 `go.mod` 固定使用 Go `1.27.2`。使用容器的實例不必在主機安裝 Go。

## 升級 {#upgrade}

按 [升級步驟](../upgrade#steps) 停服並冷備份，將映像檔改為 `ghcr.io/dejavumoe/ecoku:v0.3.8`，拉取並啟動。

檢查容器健康狀態、啟動日誌、評論載入和後台登入；啟用了人機驗證或通知的實例，同時確認驗證與投遞正常。容器內建 SDK 隨映像檔更新；獨立安裝的 SDK 可在 npm 發布成功後固定到 `ecoku@0.3.8` 並重新建置網站。

## 回滾 {#rollback}

從 v0.3.7 升級的實例，停服後將映像檔改回 `ghcr.io/dejavumoe/ecoku:v0.3.7`，拉取並啟動即可。schema 相同，不必還原資料庫，升級後的評論與設定會保留。獨立安裝的 SDK 可固定回 `ecoku@0.3.7` 後重新建置網站。

回滾會重新引入本版修正的 Go 安全弱點，僅在排查升級問題時暫時使用。若從更早版本升級，先核對該版本的 schema 與 [回滾說明](./v0.3.7#rollback)。
