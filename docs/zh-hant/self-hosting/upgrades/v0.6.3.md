# v0.6.3

- 發布日期：2026-11-24
- schema：v12（無遷移）
- 映像檔：`ghcr.io/dejavumoe/ecoku:v0.6.3`
- npm SDK：`ecoku@0.6.3`

## 變更 {#changes}

- 評論區右下角顯示「Powered by Ecoku」，Ecoku 依評論區語言連結到文件站首頁。署名在評論列表載入完成後出現，有分頁時位於分頁下方。預設樣式中它比正文更淡，可用 `.ecoku-powered-by` 調整，見 [自訂樣式](../../integration/custom-css)。
- 管理後台登入後，每個頁面底部置中顯示「Powered by Ecoku」與目前版本號，版本號連結到 GitHub 上對應的 Release。登入頁不顯示版本號。
- 管理端工作階段介面（`POST /api/admin/login`、`GET /api/admin/session`、`POST /api/admin/initial-setup`）的回應新增 `version` 欄位，見 [HTTP 介面](../../reference/api)。

## 相容性 {#compatibility}

- schema 維持 v12。從 v0.6.2 升級時，沿用現有資料與設定掛載、容器使用者和健康探針；設定項不變。
- 評論區新增 `.ecoku-powered-by` 元素，位於評論列表與分頁之後。使用 `ecoku.unstyled.css` 或 `data-css-url="none"` 的部落格會看到一行無配色的署名，可依需要加樣式。
- 自行從原始碼建置、未傳入 `ECOKU_VERSION` 的映像檔，後台顯示 `dev`。
- 從 v0.5.7 或更早版本升級時，先閱讀 [distroless 遷移說明](../upgrade#distroless)，同步更換舊 Compose 探針。

## 升級 {#upgrade}

按 [升級步驟](../upgrade#steps) 停止服務並冷備份，將映像檔改為 `ghcr.io/dejavumoe/ecoku:v0.6.3`，再拉取並重建容器。確認狀態為 `healthy`，登入後台查看底部版本號為 `v0.6.3`，再檢查已發布評論和新評論送出。透過 npm 引入 SDK 的網站，將相依套件改為 `ecoku@0.6.3`。

## 回滾 {#rollback}

停止服務，將映像檔改回 `ghcr.io/dejavumoe/ecoku:v0.6.2`，再拉取並重建容器。兩個版本皆使用 schema v12，保留現有資料庫與健康探針即可。
