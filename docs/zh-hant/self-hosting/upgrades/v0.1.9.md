# v0.1.9

- 發布日期：2026-08-31
- schema：v7，無遷移
- 映像檔：`git.via.moe/dejavu/ecoku:v0.1.9`

## 變更

本版修正公開評論清單的資源耗盡問題（CWE-400）：

- 一次清單請求最多回傳 200 則評論、16 層回覆、1 MiB JSON；統計時同一頁面最多檢查 10,000 則評論。超過任一項會回傳 `422`，不回傳截斷的資料。現有的評論區會顯示載入失敗，不會自動改用其他讀取方式。
- 新增逐層讀取：傳入 `parentId` / `afterId`，每次只回傳一層直接回覆，供自訂前端依需要載入，見 [REST API](../../reference/api#cursor)。
- 清單處理最多同時處理 4 個請求，每次資料庫讀取限時 2 秒。忙碌或逾時會回傳 `503`。
- 新增 `rate_limit.comment_list`，預設每個 IP 每 60 秒 60 次，超出會回傳 `429`。瀏覽器的預檢請求和來源被拒絕的請求也會計入。
- 每種速率限制最多追蹤 10,000 個 IP，滿了之後拒絕新的 IP，而不是擠掉既有記錄。
- SQLite 連線重建後會重新啟用外鍵、同步層級和忙碌等待設定。這不是資料庫遷移。

## 相容性

- Compose 掛載、UID/GID、連接埠、日誌、環境變數和金鑰都不變，可以從 v0.1.8 原地升級。
- 未設定 `rate_limit.comment_list` 時使用預設值 60，舊設定可以直接啟動。
- 調低每頁根評論數，無法解決單一討論串過大、過深，或整頁評論數超過統計上限的情況。
- 沒有正確設定 `trusted_proxies` 時，反向代理後面的所有訪客會共用讀取額度，請參考[反向代理](../reverse-proxy#trusted-proxies)檢查。

## 升級

依照[升級步驟](../upgrade#steps)操作，映像檔改為 `git.via.moe/dejavu/ecoku:v0.1.9`。啟動後在實際頁面上檢查評論清單、排序、翻頁和回覆。不要在正式環境中製造深層討論或高頻請求來測試上限。

## 回滾到 v0.1.8

1. 停止服務。
2. 如果在設定中加過 `rate_limit.comment_list`，請刪除它。v0.1.8 不認得這個欄位，會拒絕啟動。
3. 把映像檔改回 `git.via.moe/dejavu/ecoku:v0.1.8`，拉取並啟動。

兩個版本都是 schema v7，資料庫不需要還原。回滾會重新暴露上述資源耗盡問題，只應作為臨時措施。
