# v0.1.9

停服冷備份 → 修改精確鏡像 tag → `sudo docker compose pull && sudo docker compose up -d` → 健康檢查與回滾準備。

本頁描述 v0.1.9 發布候選。先等待提交通過 CI，再建立 tag 並等待鏡像發布完成；文件中的版本號不代表鏡像已可拉取。

## 從 v0.1.8 升級的影響

- SQLite 維持 **schema v7**，沒有新遷移。不刪除或重建資料庫、評論、設定、WAL 或備份；更早版本仍依既有遷移鏈升級。
- 掛載、UID/GID `10001:10001`、連接埠、日誌、環境變數與金鑰不變。保留生產設定與資料目錄。
- 可選 `rate_limit.comment_list` 預設 **60**，沿用 `window_seconds`（預設 60 秒）。舊設定省略此鍵仍可啟動，詳見[設定參考](../configuration)。
- 預算內的成功回應相容現有 SDK。完整討論串最多 **200 個節點、16 層後代、1 MiB JSON**；統計探針預算為同站點/頁面 **10,000 條 ID/父關係**。超限回傳 **422**，不靜默截斷。縮小根 `pageSize` 無法解決單一過大/過深討論串或整篇文章統計超限；現有 SDK 顯示載入失敗，不自動切換模式。
- 自訂接入可透過 `parentId` / `afterId` 按需讀取單層節點，見 [API 參考](../../reference/api)。兩種模式共用讀取頻控、**4 個並行名額**與 **2 秒資料庫讀取期限**。忙碌或逾時回傳 503，頻控超限回傳 429。
- 保護在 CORS 資料庫查詢前生效，預檢與被拒絕來源也計次；提前拒絕不添加未驗證的跨域許可，瀏覽器可能只顯示載入失敗。未正確設定 `trusted_proxies` 時，代理後的訪客可能共享額度；核對[反向代理](../reverse-proxy)，不要信任所有位址。
- SQLite 新建或重建連線會重新套用外鍵、同步級別與忙等待設定，避免取消交易後遺失設定；這不是 schema 遷移。

## 升級操作

1. 在 CI/隔離環境檢查一般頁面與大型討論串，再安排短暫停服；此流程不保證零停機。
2. 按[備份與恢復](../backup)停服，製作並校驗卷外冷備份，保存 `data/`、`app/config.yaml`、`ecoku.env` 與原 `compose.yaml`。不要在服務執行時只複製 SQLite 主檔。
3. 鏡像發布完成後，只把生產 image 改成實際倉庫的精確 `v0.1.9` tag。`registry.example.com/ecoku:v0.1.9` 是佔位符；不要覆蓋其他設定。
4. 在部署目錄執行：

   ```bash
   sudo docker compose config --quiet
   sudo docker compose pull && sudo docker compose up -d
   sudo docker compose ps
   sudo docker compose logs --tail=100 ecoku
   curl --fail --silent --show-error http://127.0.0.1:12123/api/health
   ```

5. 健康介面回傳 `status: healthy` 只代表程序可回應；仍需核對容器健康、日誌、列表、排序、分頁、回覆及管理端。不要在生產建立深鏈或進行壓測。

## 回滾至 v0.1.8

先停服。若明確新增了 `rate_limit.comment_list`，刪除此鍵或恢復舊設定；v0.1.8 會拒絕未知 YAML 欄位。改回精確 `v0.1.8` tag，拉取、啟動並檢查健康及業務。

從 v0.1.8 升級時兩版都是 schema v7，通常可保留當前資料庫回滾鏡像，保留新評論。只有確認資料異常並接受遺失備份後新增資料時，才明確恢復整庫冷備份；不要自動覆蓋當前資料庫。若起始版本更舊，遵循該版 schema 回滾要求。回滾會重新暴露 CWE-400，只應用於故障處置。

## CI 與發布順序

- `master` push 或目標為 `master` 的 PR 執行 client/admin、VitePress 建置與輸出檢查、Go 測試、vet 與建置。
- 測試通過後，發布提交同步 `VERSION`、根 `package.json`、Compose 精確 tag 與帶日期的 CHANGELOG v0.1.9 章節及連結，並確認該提交 CI 通過。
- `v0.1.9` tag 僅核對版本並建置/發布 amd64、arm64 鏡像與 manifest；不重跑測試、不部署生產、不操作生產庫。
- 文件網站另由 `master` 的 manual 流程發布，應用鏡像 tag 不會自動發布網站。
