# v0.5.0

- 發布日期：2026-10-11
- schema：v12（無遷移）
- 映像檔：`ghcr.io/dejavumoe/ecoku:v0.5.0`
- npm SDK：`ecoku@0.5.0`

## 變更 {#changes}

- 評論區依站點語言更新預覽、貼圖按鈕及無障礙標籤，SDK 明確指定的語言仍優先。
- 單頁應用切換文章後，舊人機驗證結果不再觸發新文章的送出，舊請求的收尾也不會解除新送出的鎖定。
- 同頁面重新整理、排序與分頁依請求先後協調，舊回應不會覆蓋新清單；首次載入失敗仍顯示錯誤。
- 送出期間，已開啟或延遲載入的貼圖面板不能修改正在傳送的內文；送出失敗後恢復編輯。
- 在 DOM 就緒前執行的載入器會保留自己的指令碼位址，繼續從同目錄載入 SDK。
- 實例金鑰全部驗證通過後才寫入持久檔案；無效的首次設定或失敗的簽章金鑰輪替不會先寫壞金鑰檔案。
- Twikoo 匯入保留孤兒評論和循環評論的有效後代關係；驗證整個檔案是單一 JSON 陣列且不超過 64 MiB（包含結尾空白）；HTML 轉成純文字時保留 `<pre>` 內的縮排、定位字元和內部空白行。匯入後仍按一般評論顯示，不提供程式碼區塊樣式或語法醒目提示。
- SMTP 伺服器確認接收完整郵件後，結束連線失敗不再觸發重寄；儲存和測試設定時保留密碼首尾空白，留空仍沿用已儲存密碼。
- 來源比較統一處理預設連接埠、連接埠前導零和等價 IPv6 寫法，相容已儲存的來源。啟動時檢查管理來源與資料庫內所有站點來源是否重疊。
- 全新資料庫套用 YAML 站點種子的 `i18n`，建表、遷移和種子寫入在同一交易中完成；既有站點繼續使用資料庫中的語言設定。
- 管理後台首次設密和通知測試遇到失效工作階段時返回登入；空評論清單回到第 1 頁；通知重試儲存時清除舊錯誤，並保留本次部分儲存失敗的提示。
- 墓碑刪除及重複刪除回應中的 `has_children` 反映實際直接回覆，包括已刪除的回覆。
- 維護用 API 冒煙指令碼透過 Cookie 工作階段登入，並僅對明確的 `429` 回應依 `Retry-After` 有限重試。

## 相容性 {#compatibility}

- 沒有新增資料庫遷移，schema 仍為 v12。管理位址、API 路徑、設定鍵、環境變數、Compose 掛載和容器連接埠不變。
- 管理來源必須與資料庫中所有站點的允許來源分開。已有重疊時，升級前在原後台修正站點來源，或調整管理網域、來源設定和反向代理。新版本發現衝突會拒絕啟動，開啟資料庫的 CLI 子指令也會拒絕繼續；見 [設定生效與來源檢查](../../reference/configuration#reload)。
- 既有評論、站點、管理員帳戶和設定繼續保留。升級不會自動修復以前寫壞的金鑰檔案、被裁掉空白的 SMTP 密碼、錯誤的站點語言或已匯入的評論結構與內文。需要時重新填寫正確的 SMTP 密碼、在後台修正語言；金鑰和歷史匯入資料應先核對備份，再另行安排還原，不要刪除金鑰或資料庫來重試升級。
- Twikoo 修復只影響以後執行的匯入，仍只接受零評論目標站點；不支援在既有評論上覆蓋重匯。內文繼續按純文字呈現，不解析 HTML 或 Markdown。
- 新建站點種子的語言來自 YAML；重啟或升級不會以 YAML 覆蓋既有站點語言。通知仍為至少一次投遞，寄出後、記錄結果前當掉仍可能造成重複通知。
- 既有接入程式碼保持相容。容器內建 SDK 隨映像檔更新；獨立安裝的 SDK 需要更新後重新建置網站，才能取得評論區修復。

## 升級 {#upgrade}

依照 [升級步驟](../upgrade#steps) 停服並冷備份，將映像檔改為 `ghcr.io/dejavumoe/ecoku:v0.5.0`，執行 `sudo docker compose pull && sudo docker compose up -d`。

檢查容器健康狀態和啟動日誌，再確認評論載入、排序、分頁、文章切換與後台登入。檢查通知設定時，如原密碼包含首尾空白，請重新輸入完整密碼、儲存並寄送測試。Twikoo 遷移仍須先備份、預先檢查，再正式匯入；見 [遷移步驟](../twikoo)。

獨立安裝的 SDK 可在 npm 發布成功後固定到 `ecoku@0.5.0` 並重新建置網站。每個實例都要分別更新映像檔，包括為文件範例提供服務的實例。

## 回滾 {#rollback}

從 v0.4.1 升級的實例，停服後將映像檔改回 `ghcr.io/dejavumoe/ecoku:v0.4.1`，拉取並啟動即可。schema 相同，不必還原資料庫，升級後的評論與設定會保留；本次修復也會隨程式回滾而失去。獨立安裝的 SDK 可固定回 `ecoku@0.4.1` 後重新建置網站。

若從更早版本升級，先核對該版本的 schema 與對應版本的回滾說明。
