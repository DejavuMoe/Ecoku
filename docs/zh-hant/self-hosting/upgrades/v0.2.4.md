## v0.2.4 相容性

v8 新增 `admin_sessions` 表及到期索引，不改寫留言、設定或既有遷移記錄。舊登入失效，必須重新登入。`admin.token_ttl_minutes` 請省略或設為 480；除 `0` 與 `480` 外的其他舊值會阻止啟動。掛載、環境變數及密碼雜湊不變。回滾至 v0.2.3 或更早版本，必須停服並保留現場，再恢復升級前完整冷備份與原鏡像；僅換舊 tag 無法開啟 v8 資料庫。恢復備份會失去備份後的寫入，須由操作者明確接受。

## 升級步驟

1. 依照[備份與恢復](../backup)停服並製作卷外冷備份、校驗歸檔；包含 `data/`（含 WAL/SHM）、`app/config.yaml`、`ecoku.env` 及原 `compose.yaml`，不可在運行中僅複製 SQLite 主檔。
2. 刪除 `admin.token_ttl_minutes` 或設為 480。正式後台使用 HTTPS，反代保留 Origin 及 Cookie；HTTP 僅供白名單回環開發來源。
3. 將 Compose image 設為 `git.via.moe/dejavu/ecoku:v0.2.4`，執行下列命令。啟動時原位交易式升級至 v8，不需手動 SQL。

```bash
sudo docker compose config --quiet
sudo docker compose pull && sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail=100 ecoku
curl --fail --silent --show-error http://127.0.0.1:12123/api/health
```

健康介面只確認程序可回應。檢查容器健康、歷史留言、登入後重新整理/重開恢復，以及登出後拒絕存取。不要在正式環境製造攻擊請求或深鏈。
