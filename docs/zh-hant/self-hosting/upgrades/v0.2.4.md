# v0.2.4

- 發布日期：2026-09-16
- schema：v7 → v8
- 映像檔：`git.via.moe/dejavu/ecoku:v0.2.4`

## 變更

- 管理員登入改為 HttpOnly Cookie 加上資料庫工作階段。登入後固定維持 8 小時，重新整理或關閉再開啟瀏覽器都能恢復，不會延長；登出時伺服器端會撤銷工作階段。登入回應不再回傳 token。
- 人機驗證在檢查部落客口令之前進行，沒通過驗證就無法試探口令是否正確。
- 存取日誌只記錄路由範本，不再寫入實際路徑。
- 新回覆最多 16 層（根評論為第 0 層），第 17 層會被拒絕。既有的深層評論不受影響。

## 相容性

- schema v8 只新增管理員工作階段資料表和過期索引，不更動評論、設定和既有的遷移記錄。
- 升級後所有管理員都需要重新登入。
- `admin.token_ttl_minutes` 只能省略或設為 `480`。舊設定中的其他數值會導致啟動失敗，請在升級前修改。
- 正式環境的管理後台必須透過 HTTPS 存取，反向代理需要保留 `Origin` 請求標頭和 Cookie。HTTP 只允許用於迴路位址上的開發環境。
- 掛載、環境變數和密碼雜湊不變。

## 升級

1. 依照[備份與還原](../backup#cold-backup)停止服務並做冷備份。
2. 檢查 `app/config.yaml` 中的 `admin.token_ttl_minutes`：刪除這一行，或改為 `480`。
3. 依照[升級步驟](../upgrade#steps)操作，映像檔改為 `git.via.moe/dejavu/ecoku:v0.2.4`。首次啟動時會自動遷移到 v8。
4. 檢查：歷史評論正常顯示；登入後台後重新整理、關閉再開啟瀏覽器仍維持登入；點擊登出後無法繼續存取。

## 回滾

升級後資料庫已是 v8，v0.2.3 及更早的版本無法開啟。回滾必須：

1. 停止服務，保留目前的 `data/` 目錄以備查；
2. 用升級前的冷備份[還原](../backup#restore)，備份中的 `compose.yaml` 會帶回原本的映像檔版本。

備份之後產生的評論和設定修改會遺失。
