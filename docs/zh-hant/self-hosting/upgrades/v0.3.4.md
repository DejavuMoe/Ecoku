# v0.3.4

- 發布日期：2026-10-05
- schema：v12（無遷移）
- 映像檔：`ghcr.io/dejavumoe/ecoku:v0.3.4`
- npm SDK：`ecoku@0.3.4`

## 變更 {#changes}

- 修正首次開啟後台時，未登入的工作階段檢查取消驗證設定請求、導致驗證元件偶爾不顯示的問題。驗證載入期間禁止送出；載入失敗後可點擊「重試」，保留已填帳號密碼，重試不會自動登入。
- 送出評論遇到網路中斷、逾時、無效回應或伺服器錯誤時，保留草稿並提示結果尚未確認，不再誤報「尚未送出」，也不會自動重試。
- 選用的身分儲存不再阻塞首次評論載入和發布成功提示；較晚還原的身分不覆蓋使用者編輯。公開列表與提交減少重複的站點設定查詢，部落客口令比較提前排除不符合既有規則的候選值。
- CI 增加 Go 漏洞檢查、JavaScript 鎖定檔相依套件稽核和 SDK 真實瀏覽器儲存測試；修正文件工具鏈及 `brace-expansion` 間接相依套件的已知漏洞。

## 相容性 {#compatibility}

- 沒有資料庫遷移，schema 仍為 v12。Compose 掛載、設定項和環境變數不變。
- 來源檢查、設定讀取、人機驗證與評論寫入共用 8 秒處理預算；SDK 的單次請求逾時仍為 10 秒。較慢的驗證服務可能耗盡預算，詳見 [提交評論](../../reference/api#submit-comment)。
- 提交結果未確認不代表評論一定沒有儲存。先重新整理評論列表檢查，再決定是否手動重試，避免重複發布。
- 身分儲存仍然可選，只在 IndexedDB 中加密儲存 7 天，不新增瀏覽器儲存位置。

## 升級 {#upgrade}

1. 停服並 [冷備份](../backup#cold-backup) 資料庫、`ecoku-secrets.json`、Compose 和設定檔。
2. 按 [升級步驟](../upgrade#steps) 將映像檔改為 `ghcr.io/dejavumoe/ecoku:v0.3.4`，執行 `sudo docker compose pull && sudo docker compose up -d`。
3. 檢查容器健康狀態；登出後台後重新開啟登入頁，確認驗證正常載入並能登入，再檢查評論載入與發布。
4. npm 發布成功後，使用 `pnpm add --save-exact ecoku@0.3.4` 更新獨立接入的 SDK 並重新建置網站。容器內建 SDK 隨映像檔更新；自行託管靜態檔案時一併替換載入器、SDK 和樣式檔。

## 回滾 {#rollback}

schema 沒有變化。停服後將映像檔改回 `ghcr.io/dejavumoe/ecoku:v0.3.3`，拉取並啟動即可，不需要還原資料庫；升級後新增的評論和設定修改會保留。獨立安裝的 npm SDK 可固定回 `ecoku@0.3.3` 後重新建置網站；回滾會撤回本版的登入與評論提交修正。
