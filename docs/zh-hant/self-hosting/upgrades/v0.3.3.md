# v0.3.3

- 發布日期：2026-10-04
- schema：v12（無遷移）
- 映像檔：`ghcr.io/dejavumoe/ecoku:v0.3.3`
- npm SDK：`ecoku@0.3.3`

## 變更 {#changes}

- 執行 [`admin reset-password`](../../reference/cli#admin-reset-password) 後，首次登入設定頁會預先填入目前的使用者名稱，不再固定填 `admin`。改過使用者名稱的管理員重設密碼後直接儲存，不會被改回 `admin`。
- 評論區不再為第 16 層評論顯示「回复」按鈕。伺服器以 `422` 拒絕過深的回覆時，評論區提示「回复层级已达上限，请回复较上层的评论。」，不再顯示籠統的提交錯誤。
- HTML 載入器支援 [`data-i18n`](../../integration/html)，可以在接入程式碼中指定評論區語言，覆寫站點設定。載入器自己的失敗提示也隨之切換語言；未填寫 `data-i18n` 時依頁面的 `<html lang>` 選擇，其他情況為簡體中文。
- 文件依原始碼複核：補充站點「评论区语言」欄位、`EcokuSite` 站點管理憑據的權限範圍，並修正多處與實作不符的描述。

## 相容性 {#compatibility}

- 沒有資料庫遷移，schema 仍為 v12。Compose、掛載、設定項和環境變數不變。
- 以臨時密碼登入時，登入介面與 `GET /api/admin/session` 的回應多一個 `username` 欄位；普通工作階段的回應不變。
- 載入器的失敗提示先前固定為簡體中文。頁面 `<html lang>` 為英語或繁體中文的網站，升級後會看到對應語言的提示。
- 自行託管 `ecoku-loader.js` 的網站，需要把 `ecoku-loader.js` 和 `ecoku.umd.js` 一起換成新版，`data-i18n` 和新的回覆行為才會生效；舊版載入器會忽略 `data-i18n`。

## 升級 {#upgrade}

1. 停服並 [冷備份](../backup#cold-backup) 資料庫、`ecoku-secrets.json`、Compose 和設定檔。
2. 按 [升級步驟](../upgrade#steps) 將映像檔改為 `ghcr.io/dejavumoe/ecoku:v0.3.3`，執行 `sudo docker compose pull && sudo docker compose up -d`。
3. 檢查容器健康狀態和管理員登入，開啟一篇有評論的文章，確認評論區正常載入。
4. npm 發布成功後，使用 `pnpm add --save-exact ecoku@0.3.3` 更新獨立接入的 SDK 並重新建置網站。容器內建 SDK 隨映像檔更新。

## 回滾 {#rollback}

schema 沒有變化。停服後將映像檔改回 `ghcr.io/dejavumoe/ecoku:v0.3.2`，拉取並啟動即可，不需要還原資料庫；升級後新增的評論和設定修改會保留。接入程式碼中已經加上的 `data-i18n` 會被舊版忽略，不影響載入。
