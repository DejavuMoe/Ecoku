# v0.5.6

- 發布日期：2026-11-09
- schema：v12（無遷移）
- 映像檔：`ghcr.io/dejavumoe/ecoku:v0.5.6`
- npm SDK：`ecoku@0.5.6`

## 變更 {#changes}

- 執行時映像檔將 musl 升級至 1.2.6-r3、zlib 升級至 1.3.2-r1 以上，修復 CVE-2026-107891 與 CVE-2026-85091。
- 包含 [v0.5.5](./v0.5.5#changes) 的全部變更：更新 `golang.org/x/net` 至 v0.62.0，修復 Twikoo 匯入解析 HTML 時的二次複雜度漏洞（GO-2026-6860）；更新建置與測試相依套件；整理通知佇列、管理後台工作階段與 SDK 載入器的內部狀態，對外行為不變。v0.5.5 沒有發布映像檔，本版是其後第一個可部署的映像檔。

## 相容性 {#compatibility}

- 沒有新增資料庫遷移，schema 仍為 v12。HTTP 介面、設定鍵、環境變數、Compose 掛載與容器連接埠不變；通知佇列中既有的記錄照常投遞。
- 安全修復位於伺服器映像檔，需要更新映像檔。SDK 對外行為與 `ecoku@0.5.4` 相同，可依需要更新。
- 從早於 v0.5.4 的版本升級時，另讀 [v0.5.4 的相容性說明](./v0.5.4#compatibility)；早於 v0.5.2 時，再讀 [v0.5.2 的首次登入說明](./v0.5.2#compatibility)；早於 v0.5.0 時，還需讀 [來源衝突與歷史資料說明](./v0.5.0#compatibility)。

## 升級 {#upgrade}

依 [升級步驟](../upgrade#steps) 停服並冷備份，將映像檔改為 `ghcr.io/dejavumoe/ecoku:v0.5.6`，依通用步驟拉取映像檔、重建容器並等待健康。

檢查容器健康狀態、啟動日誌、評論載入與提交、後台登入；已啟用通知的實例，可發表一則測試評論確認通知照常送達。每個實例都要單獨升級，包括為文件範例提供服務的實例。獨立安裝的 SDK 可在 npm 發布成功後固定到 `ecoku@0.5.6` 並重新建置網站；固定版本的 CDN 接入也需同步更新 SDK 位址。

## 回滾 {#rollback}

從 v0.5.4 升級的實例，停服後將映像檔改回 `ghcr.io/dejavumoe/ecoku:v0.5.4`，拉取並啟動。schema 相同，無需還原資料庫，升級後的評論和設定會保留。SDK 可固定回 `ecoku@0.5.4` 後重新建置網站。回滾會重新引入本版修復的漏洞；從更早版本升級的實例須核對對應 schema 和回滾說明。
