# v0.5.2

- 發布日期：2026-10-18
- schema：v12（無遷移）
- 映像檔：`ghcr.io/dejavumoe/ecoku:v0.5.2`
- npm SDK：`ecoku@0.5.2`

## 變更 {#changes}

- 首次啟動不再將管理員臨時密碼寫入應用程式日誌。新實例完成初始化後，停服並執行 `admin reset-password`，從終端輸出取得臨時密碼，再啟動服務完成首次改密。
- 增加安全回報政策與私密漏洞回報入口。依賴圖、Dependabot 警示和 CodeQL 已啟用，自動依賴更新保持關閉。
- 發布說明明確列出本版映像檔和 npm SDK 版本；修正歷史說明中混入下一版的文件 SDK 同步記錄。

## 相容性 {#compatibility}

- 沒有新增資料庫遷移，schema 仍為 v12。API、設定鍵、環境變數、Compose 掛載與容器連接埠不變。
- 已設定正式密碼的管理員繼續使用原帳戶，升級不會重設密碼或撤銷既有工作階段。SDK 執行時程式碼與 v0.5.1 相同，既有接入保持相容。
- v0.5.1 及更早版本首次啟動可能已把臨時密碼寫入日誌。僅升級不會使該密碼失效；若仍未完成首次改密，依 [取得管理員臨時密碼](../docker#temporary-password) 停服重設並設定正式密碼。檢查日誌副本的存取範圍，避免繼續傳播憑據。
- 從早於 v0.5.0 的版本升級時，另讀 [來源衝突與歷史資料說明](./v0.5.0#compatibility)。

## 升級 {#upgrade}

依 [升級步驟](../upgrade#steps) 停服並冷備份，將映像檔改為 `ghcr.io/dejavumoe/ecoku:v0.5.2`，執行 `sudo docker compose pull && sudo docker compose up -d`。

檢查容器健康狀態、啟動日誌、評論載入與提交、後台登入。每個實例都要單獨升級，包括為文件範例提供服務的實例。獨立安裝的 SDK 可在 npm 發布成功後固定到 `ecoku@0.5.2` 並重新建置網站。

## 回滾 {#rollback}

從 v0.5.1 升級的實例，停服後將映像檔改回 `ghcr.io/dejavumoe/ecoku:v0.5.1`，拉取並啟動。schema 相同，無需還原資料庫，升級後的評論、設定和已重設密碼會保留。SDK 可固定回 `ecoku@0.5.1` 後重新建置網站。

回滾會恢復舊版本的啟動行為：使用全新資料庫時仍可能把初始密碼寫入日誌。既有持久帳戶不會因回滾重新產生初始密碼；從更早版本升級的實例須核對對應 schema 和回滾說明。
