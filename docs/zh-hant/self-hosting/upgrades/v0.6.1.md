# v0.6.1

- 發布日期：2026-11-19
- schema：v12（無遷移）
- 映像檔：`ghcr.io/dejavumoe/ecoku:v0.6.1`
- npm SDK：`ecoku@0.6.1`

## 變更 {#changes}

- Twikoo 預檢和匯入會拒絕含垃圾評論的匯出檔案並回報數量。僅有 `rid` 的回覆可掛到對應的根評論，無路徑的 HTTP(S) 首頁位址可正常匯入。
- 後台評論清單在同一 SQLite 快照中讀取計數、分頁資料和回覆標記，並透過一次查詢統計已發布和已刪除的評論。公開評論清單逐列讀取評論關係，減少冷請求的記憶體配置。
- 信任代理設定會拒絕實際涵蓋所有 IPv4 位址的 IPv4 映射網段。

## 相容性 {#compatibility}

- schema 維持 v12。從 v0.6.0 升級時，沿用現有資料與設定掛載、容器使用者和健康探針。SDK 執行程式碼與 0.6.0 相同。
- 若 `site.trusted_proxies` 含涵蓋所有 IPv4 位址的 IPv4 映射網段，服務會拒絕啟動。升級前依 [反向代理說明](../reverse-proxy#trusted-proxies) 改為實際受信代理的 IP 或有限網段。
- 從 v0.5.7 或更早版本升級時，先閱讀 [distroless 遷移說明](../upgrade#distroless)，同步更換舊 Compose 探針。

## 升級 {#upgrade}

按 [升級步驟](../upgrade#steps) 停止服務並冷備份，將映像檔改為 `ghcr.io/dejavumoe/ecoku:v0.6.1`，再拉取並重建容器。確認狀態為 `healthy`，檢查後台登入、已發布評論和新評論送出。

## 回滾 {#rollback}

停止服務，將映像檔改回 `ghcr.io/dejavumoe/ecoku:v0.6.0`，再拉取並重建容器。兩個版本皆使用 schema v12，保留現有資料庫與健康探針即可。
