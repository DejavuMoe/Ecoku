# v0.5.1

- 發布日期：2026-10-16
- schema：v12（無遷移）
- 映像檔：`ghcr.io/dejavumoe/ecoku:v0.5.1`
- npm SDK：`ecoku@0.5.1`

## 變更 {#changes}

- 清理伺服器未使用的設定輔助函式、未讀取的日誌路徑標記與重複常數別名，保留既有設定相容行為。
- CI 的 SDK 瀏覽器測試只安裝 Chromium headless shell，保留系統相依套件安裝、瀏覽器測試及其餘驗證步驟。
- 接入文件統一使用服務位址與站點 ID 佔位符，並補充 Astro 靜態頁面與用戶端路由範例。

## 相容性 {#compatibility}

- 沒有新增資料庫遷移，schema 仍為 v12。API、設定鍵、環境變數、Compose 掛載、容器連接埠及日誌路徑行為不變。
- SDK 版本隨伺服器發布，執行時程式碼與 v0.5.0 相同。既有接入程式碼保持相容，無須因本次更新調整應用程式介面或站點設定。
- 若從早於 v0.5.0 的版本升級，先核對 [v0.5.0 相容性說明](./v0.5.0#compatibility)，尤其是管理來源與站點來源衝突及歷史資料處理事項。

## 升級 {#upgrade}

按 [升級步驟](../upgrade#steps) 停服並冷備份，將映像檔改為 `ghcr.io/dejavumoe/ecoku:v0.5.1`，執行 `sudo docker compose pull && sudo docker compose up -d`。

檢查容器健康狀態與啟動日誌，再確認評論載入、提交與後台登入。每個實例都要單獨更新映像檔，包括為文件範例提供服務的實例。

獨立安裝的 SDK 可在 npm 發布成功後固定至 `ecoku@0.5.1` 並重新建置網站；繼續使用 v0.5.0 的 SDK 也保持相容。

## 回滾 {#rollback}

從 v0.5.0 升級的實例，停服後將映像檔改回 `ghcr.io/dejavumoe/ecoku:v0.5.0`，拉取並啟動即可。schema 相同，無須還原資料庫，升級後的評論與設定會保留。獨立安裝的 SDK 可固定回 `ecoku@0.5.0` 後重新建置網站。

若從更早版本升級，先核對該版本的 schema 與對應版本的回滾說明。
