# v0.3.0

- 發布日期：2026-10-03
- schema：v10 → v11
- 映像檔：`ghcr.io/dejavumoe/ecoku:v0.3.0`
- npm SDK：`ecoku@0.3.0`

## 變更 {#changes}

- Smoji 新增選填的「图片来源」。可以自行託管工作台匯出的 JSON，繼續從指定 CDN 載入圖片；評論、預覽、後台及郵件統一使用這項來源規則。
- GitHub Actions 發布 GHCR 雙架構映像檔、npm SDK 和附帶 SDK 套件與校驗和的 GitHub Release。SDK 版本與專案 tag 一致；目前由 Woodpecker 發布文件，映像檔統一使用 GHCR。
- 完整 YAML 範本集中說明預設值、可選值和範例；Compose 明確設定 `TZ: Asia/Shanghai`。文件保留原有版面，採用後台紙墨配色，統一程式碼高亮與行內排版，並修正預設搜尋翻譯。

## 相容性 {#compatibility}

- 在原資料庫的 `sites` 表新增 `smoji_image_origin`，預設為空字串；保留帳戶、站點、評論、佇列和通知設定。沒有向下遷移。
- 未填寫「图片来源」的站點保留清單同源驗證；填寫後只允許指定的單一圖片來源。遠端 JSON 不能擴大允許範圍。
- 既有 Compose、YAML 和管理員憑據繼續有效，不必重新產生密碼或金鑰。v0.2.8 及更早實例仍按 [舊設定遷移](../upgrade#legacy-config) 操作。
- 新增 GHCR 發布不會自動修改既有部署的映像檔來源。npm 與映像檔分別發布，下載前確認對應任務成功。

## 升級 {#upgrade}

1. 停服並 [冷備份](../backup#cold-backup) 資料庫、同目錄的 `ecoku-secrets.json`、Compose 和設定；仍使用 `ecoku.env` 時一起備份。
2. 按 [升級步驟](../upgrade#steps) 將映像檔改為 `ghcr.io/dejavumoe/ecoku:v0.3.0`，執行 `sudo docker compose pull && sudo docker compose up -d`。
3. 檢查健康端點、管理員登入、歷史評論和通知；確認 schema v11 遷移成功。
4. 需要分開託管 Smoji 時，按 [清單與圖片託管](../../integration/smoji#hosting) 填寫「图片来源」，測試選擇器、預覽及評論顯示。
5. 使用 npm SDK 的網站在 npm 發布成功後安裝 `ecoku@0.3.0`，重新建置網站。實例託管的 UMD 接入繼續隨容器更新。

## 回滾 {#rollback}

v0.3.0 是公開部署的起點，沒有可供正式環境回滾的更早公開映像檔。發生問題時先停止服務，按 [還原說明](../backup#restore) 還原同一份完整備份，並使用與備份 schema 相符的受支援版本。v0.2.9 內測程式無法開啟 schema v11，不能只切換映像檔 tag。還原備份會遺失備份之後新增的評論和設定。
