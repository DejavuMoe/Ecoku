# v0.2.9

- 發布日期：2026-10-02
- schema：v9 → v10
- 映像檔：`git.via.moe/dejavu/ecoku:v0.2.9`

## 變更 {#changes}

- 新部署不再填寫管理員密碼雜湊和兩把金鑰。首次啟動建立 `admin`、隨機臨時密碼和持久金鑰檔案；臨時密碼印在啟動日誌中，首次登入必須修改密碼，使用者名稱可保留 `admin`。
- 新增持久管理員帳戶表及 `admin reset-password` 命令。首次改密碼的工作階段只能查看工作階段、登出和完成設定；完成後進入既有站點建立流程。
- 修復後台 favicon、Chrome 表單虛線、通知欄位錯誤排版、父評論貼圖標記、刪除清單跳動、跳轉高亮、重複提示和工作階段過期提示。文件首頁統一使用「區」標識。
- 新 Compose 不再要求 `ecoku.env` 或日誌目錄掛載；日誌預設寫入標準輸出。

## 相容性 {#compatibility}

- 從 v0.2.8 升級時在原資料庫新增 `admin_accounts`，保留站點、評論、通知、人機驗證、佇列和已發布遷移記錄。沒有向下遷移。
- 首次升級保留舊 Compose、YAML 和環境變數。原使用者名稱、bcrypt 雜湊和金鑰會導入持久狀態，不強迫舊管理員修改密碼。
- 舊連接埠、資料庫路徑、靜態目錄、檔案日誌、YAML 站點及管理金鑰仍有相容入口；`admin.enabled: false` 會被忽略，後台始終啟用。舊工作階段時長仍只接受 480 分鐘或省略。
- 持久金鑰位於資料庫同目錄的 `ecoku-secrets.json`，標準掛載下為 `data/ecoku-secrets.json`。須為普通檔案，Linux 權限為 600；不可遺失或任意替換通知加密主金鑰。

## 升級 {#upgrade}

1. 保留原設定和所有舊金鑰，停服並[冷備份](../backup#cold-backup)。舊實例的封存檔還須包含 `ecoku.env`；自訂資料庫路徑須備份其實際位置。
2. 按[升級步驟](../upgrade#steps)將既有 Compose 的映像檔改為 `git.via.moe/dejavu/ecoku:v0.2.9`，拉取並啟動；這次先不替換為新使用者範本。
3. 確認健康介面、原管理員登入、站點數量、歷史評論、通知和人機驗證設定正常，持久金鑰檔案已建立。
4. 如需精簡設定，按[舊設定遷移](../upgrade#legacy-config)再次停服備份後移除舊管理員環境變數。需要保留 `TZ` 或 `EcokuSite` 的變數時，繼續使用對應環境注入方式。確認不再使用舊資料庫路徑和檔案日誌後，才移除其掛載。

## 回滾 {#rollback}

v0.2.8 無法開啟 schema v10。停止服務，按[還原說明](../backup#restore)還原升級前的完整資料庫、原 Compose、設定與 `ecoku.env`，再以 v0.2.8 啟動。只改映像檔 tag 不足以回滾；冷備份後產生的評論和設定會遺失。
