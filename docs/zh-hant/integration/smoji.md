# Smoji 貼圖包

Smoji 讓訪客在純文字評論中插入貼圖圖片。貼圖以一段文字標記保存在評論內文裡，顯示時才變成圖片，評論本身仍然是純文字。

Ecoku 不內建、不代理、不快取任何貼圖圖片。你需要把一份 `smoji.json` 清單和圖片託管在自己的靜態伺服器或 CDN 上，再在後台為站點填寫清單網址。

## 運作方式

1. 訪客第一次點擊評論框的「表情」按鈕時，瀏覽器會載入清單（不帶 Cookie 和 Referer）。
2. 選取一張貼圖後，評論框中會插入一段標記：

   ```text
   ![smoji:赞](https://stickers.example.com/paopao/thumbsup.png)
   ```

3. 送出時，伺服器端檢查每個標記：站點已啟用貼圖包，且圖片網址與清單同源，才允許保存。
4. 顯示評論時，符合同樣條件的標記會呈現為圖片；其他情況一律以原文顯示。

站點關閉貼圖包後，歷史評論中的標記會以文字原樣顯示，不再載入圖片。

::: warning 隱私
貼圖圖片由託管它的伺服器直接傳送到訪客的瀏覽器，這台伺服器看得到訪客的 IP 位址。
:::

## 啟用

在後台「站点」中編輯站點，在「表情包」選擇「启用」，填寫清單網址後儲存。

- 清單網址必須是 HTTPS。只有 `localhost`、`127.0.0.1` 等迴路位址可以用 HTTP，供本機開發使用。
- 網址中不能包含使用者名稱與密碼、`?` 查詢參數或 `#` 片段。
- 清單和評論頁不在同一個網域時，託管清單的伺服器需要允許來自評論頁來源的跨來源請求（CORS）。

## 清單格式

```json
{
  "version": 1,
  "packs": [
    {
      "id": "paopao",
      "label": "泡泡",
      "items": [
        { "id": "smile", "label": "微笑", "src": "https://stickers.example.com/paopao/smile.png" },
        { "id": "thumbsup", "label": "赞", "src": "thumbsup.png" }
      ]
    }
  ]
}
```

| 欄位 | 規則 |
| --- | --- |
| `version` | 固定為 `1`。 |
| `base` | 選填，見下文。 |
| `packs` | 分組清單，1～64 個。 |
| `packs[].id` | 分組 ID，以字母或數字開頭，可包含字母、數字、`.`、`_`、`-`，最多 64 個字元，不能重複。 |
| `packs[].label` | 分組名稱，顯示在選擇器的分頁標籤上。規則同 `items[].label`。 |
| `packs[].items` | 貼圖清單，每組 1～600 個；整份清單合計不超過 6000 個。 |
| `items[].id` | 貼圖 ID，規則同分組 ID，組內不能重複。 |
| `items[].label` | 貼圖名稱，去掉前後空白後為 1～40 個字元，不能包含 `]` 和換行等控制字元。它會寫進評論標記，也用作圖片的替代文字。 |
| `items[].src` | 圖片網址。可以是完整網址，也可以是相對於清單的路徑。 |

清單的整體要求：

- **每個物件只能包含上面列出的欄位**，多出任何欄位都會被拒絕。
- 所有圖片網址解析後必須與清單**同源**（協定、網域、連接埠都相同），不能帶使用者名稱與密碼、`?` 或 `#`。
- 檔案不超過 1 MiB，回應的 `Content-Type` 為 `application/json` 或以 `+json` 結尾，並在 8 秒內下載完成。

## 精簡寫法：base {#base}

貼圖較多時，可以用 `base` 範本取代逐一填寫 `src`：

```json
{
  "version": 1,
  "base": "https://stickers.example.com/smoji/{pack}/{id}.webp",
  "packs": [
    {
      "id": "douyin",
      "label": "抖音",
      "items": [
        { "id": "smile", "label": "微笑" },
        { "id": "cool", "label": "酷", "src": "https://stickers.example.com/smoji/extra/cool.png" }
      ]
    }
  ]
}
```

- `base` 必須同時包含 `{pack}` 和 `{id}`，分別替換為分組 ID 和貼圖 ID；它本身也必須與清單同源。
- 沒有 `src` 的貼圖使用範本產生網址；寫了 `src` 的以 `src` 為準。
- 展開後的結果仍是完整網址，評論中保存的標記格式不變。

`base` 從 v0.2.1 開始支援。

## 更新貼圖素材

評論中保存的是**完整的圖片網址**。更新素材時請注意：

- 保留舊圖片的網址，或在原路徑上放置相容的副本。只替換清單無法修復歷史評論中已經失效的圖片。
- 不要更換託管貼圖的網域。換了之後，舊標記與新清單不再同源，會全部顯示為文字。
- 正式環境的清單中不要出現 `localhost` 網址。使用素材工具匯出時，把資源網址設定為你的 CDN，例如 `https://stickers.example.com/smoji/`。

## 標記格式

```text
![smoji:名称](图片地址)
```

圖片網址中的 `(` 和 `)` 會被編碼為 `%28` 和 `%29`。公開 API 的 `formConfig.smoji` 會回傳站點是否啟用及清單網址，自訂前端可以據此實作自己的選擇器和呈現方式，規則與上文相同。
