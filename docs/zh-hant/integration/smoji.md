# Smoji 貼圖包

::: info v0.3.0 起支援圖片來源
「图片来源」允許清單與圖片分別託管。v0.2.9 及更早版本仍要求兩者同源；既有站點升級後預設保留同源規則。
:::

[Smoji](https://github.com/DejavuMoe/Smoji) 提供貼圖圖庫和清單匯出工具。你可以在 [Smoji 工作台](https://smoji.zsh.moe/) 複製單張貼圖，也可以挑選分類或自選分組，匯出供評論區選擇器使用的清單。

Ecoku 將貼圖儲存為純文字標記，顯示評論時才呈現為圖片。Ecoku 伺服器端不內建、代理或快取貼圖素材。

## 直接使用 Smoji {#quick-start}

使用 Smoji 現有圖庫時，不需要自行下載或託管素材：

1. 在後台「站点」中編輯站點，在「表情包」選擇「启用」。
2. 在「Smoji 清单」填寫公共清單網址，儲存：

   ```text
   https://s3-cdn.zsh.moe/smoji/smoji.json
   ```

3. 開啟評論頁，點擊「表情」選擇圖片；也可以前往 [Smoji 工作台](https://smoji.zsh.moe/) 開啟單張貼圖的詳細資訊，複製 **Markdown** 格式，貼到評論框：

   ```text
   ![smoji:挠脸](https://s3-cdn.zsh.moe/smoji/aodamiao/iclpknnbbcne.webp)
   ```

4. 點擊「预览」檢查圖片，再發布評論。直接貼上標記不需要先開啟「表情」選擇器。

請選擇帶有 `![smoji:…](…)` 的 Markdown 格式。單獨的圖片 URL、HTML 或 BBCode 不會變成 Ecoku 貼圖；一般 Markdown 圖片也不受支援。

直接複製的圖片也要符合站點的來源限制。目前檢查的是圖片來源與標記格式，不要求圖片出現在選擇器清單中。關閉「表情包」後，歷史標記按原文顯示，新的貼圖標記提交會被拒絕。

## 挑選貼圖並匯出清單 {#custom-manifest}

如果只想在選擇器中展示部分貼圖：

1. 在 [Smoji 工作台](https://smoji.zsh.moe/) 使用「按分类导出」勾選分類，或使用「自选分组」建立自己的分組並加入貼圖。
2. 選擇 **Smoji** 格式（v1），點擊「导出」，下載 `smoji-YYYYMMDD.json`。「分组备份」是工作台的備份檔案，不能作為 Ecoku 清單。
3. 將匯出的檔案發布到可公開存取的 HTTPS 靜態網址。可以改名為 `smoji.json`，也可以保留日期後綴，後台填寫實際 URL。託管前先核對[清單與圖片的來源要求](#hosting)。

**匯出得到的是本機 JSON 檔案，不包含圖片，也不會自動上傳或產生專屬託管 URL。** 自選分組和選擇結果儲存在目前的瀏覽器；更新選擇後，需要重新匯出並替換自己託管的檔案。

例如，自選分組 `favorites` 可以包含來自 `aodamiao` 的兩張圖片：

```json
{
  "version": 1,
  "base": "https://s3-cdn.zsh.moe/smoji/{pack}/{id}.webp",
  "packs": [
    {
      "id": "favorites",
      "label": "常用",
      "items": [
        {
          "id": "iclpknnbbcne",
          "label": "挠脸",
          "src": "https://s3-cdn.zsh.moe/smoji/aodamiao/iclpknnbbcne.webp"
        },
        {
          "id": "lhbidblgecnj",
          "label": "坏笑",
          "src": "https://s3-cdn.zsh.moe/smoji/aodamiao/lhbidblgecnj.webp"
        }
      ]
    }
  ]
}
```

保留這些 `src`：它們指向圖片的實際位置，並優先於 `base`。如果刪除 `src`，範本會組合出 `/smoji/favorites/…`，而圖片實際在 `/smoji/aodamiao/…`。

## 清單與圖片的託管 {#hosting}

清單和圖片可以分別託管。將上面的 JSON 原樣放到 `https://example.com/smoji.json` 後，在後台「站点」的「表情包」中填寫：

| 欄位 | 填寫內容 |
| --- | --- |
| 表情包 | 启用 |
| Smoji 清单 | `https://example.com/smoji.json` |
| 图片来源 | `https://s3-cdn.zsh.moe` |

儲存後，瀏覽器從 `example.com` 讀取清單，從 `s3-cdn.zsh.moe` 載入圖片。不需要搬移圖片或修改匯出的 JSON。

「图片来源」是選填的單一來源，只含協定、網域和選用連接埠，不含路徑、使用者名稱與密碼、查詢參數或片段，也不支援萬用字元。正式環境使用 HTTPS，迴路位址可用 HTTP 開發。留空時沿用清單來源，舊站點無需修改；填寫後僅允許指定來源，不會同時額外放行清單來源。

| 清單位置 | 圖片位置 | 結果 |
| --- | --- | --- |
| Smoji 公共 CDN | 同一個 CDN | 可直接使用公共清單和複製的貼圖標記。 |
| 自己的網站 | Smoji 公共 CDN | 將「图片来源」設為 `https://s3-cdn.zsh.moe`。 |
| 自己的靜態伺服器或 CDN | 與清單同源 | 一併託管圖片並更新圖片網址。 |

圖片來源由管理員明確儲存；遠端清單裡的 `base` 和 `src` 不能自行增加受信任來源。相對路徑仍按清單 URL 解析；分別託管時保留匯出的絕對網址。如果選擇自行託管圖片，要確保目標路徑實際提供圖片檔案，再更新清單裡的 `base` 和所有絕對 `src`。

託管時還需滿足：

- 清單網址必須是 HTTPS，不能帶使用者名稱與密碼、`?` 查詢參數或 `#` 片段。只有 `localhost`、`127.0.0.1` 等迴路位址可以用 HTTP，供本機開發使用。
- 清單和**評論所在頁面**不同源時，清單伺服器需要允許該頁面來源的 CORS 請求。公開、無憑據的靜態清單可使用 `Access-Control-Allow-Origin: *`。在 Ecoku 後台修改「允许来源」不能取代靜態伺服器的 CORS 設定。
- 回傳 JSON 檔案本身，`Content-Type` 為 `application/json` 或以 `+json` 結尾；不要回傳下載說明頁、登入頁或 SPA 的 HTML。檔案不超過 1 MiB，並須在 8 秒內下載完成。
- 如果網站設定了 CSP，讓 `connect-src` 允許清單來源，`img-src` 允許圖片來源。CORS 和 CSP 都不會改變 Ecoku 的圖片來源檢查。

## 載入與顯示 {#how-it-works}

1. 訪客第一次開啟「表情」選擇器時，瀏覽器直接請求清單，不帶 Cookie 和 Referer。
2. 瀏覽器檢查清單，解析 `base` 和 `src`，再從圖片網址載入選擇器中的圖片。選取後，將完整圖片 URL 寫入評論標記。
3. 提交時，Ecoku 伺服器端檢查站點開關、標記格式和圖片來源；伺服器端不會下載清單或圖片。
4. 預覽、公開評論和後台評論按站點設定呈現合規標記，不需要先下載清單。圖片從資源主機直接載入，不經過 Ecoku 伺服器端。郵件通知也使用相同的來源規則，Telegram 顯示文字標籤。

清單載入失敗會影響選擇器，不會讓已儲存且符合來源規則的貼圖自動失效。圖片檔案仍需可存取。

::: warning 隱私
清單和圖片由資源主機直接傳送到訪客瀏覽器，該主機看得到訪客的 IP 位址。使用 Smoji 公共 CDN 時，請求會發往該 CDN；圖片請求設定了 `no-referrer`，但這不會隱藏訪客 IP。
:::

## 清單格式 {#manifest-format}

| 欄位 | 規則 |
| --- | --- |
| `version` | 固定為 `1`。 |
| `base` | 選填，見下文。 |
| `packs` | 分組清單，1～64 個。 |
| `packs[].id` | 分組 ID，以字母或數字開頭，可包含字母、數字、`.`、`_`、`-`，最多 64 個字元，不能重複。 |
| `packs[].label` | 分組名稱，顯示在選擇器的分頁標籤上。規則同 `items[].label`。 |
| `packs[].items` | 貼圖清單，每組 1～600 個；整份清單合計不超過 6000 個。 |
| `items[].id` | 貼圖 ID，規則同分組 ID，組內不能重複。 |
| `items[].label` | 貼圖名稱，去掉前後空白後為 1～40 個字元，不能包含 `]` 和換行等控制字元。它會寫進評論標記，也用作圖片的替代文字。 |
| `items[].src` | 圖片網址。可以是完整網址，也可以是相對於清單的路徑。 |

清單的整體要求：

- **每個物件只能包含上面列出的欄位**，多出任何欄位都會被拒絕。
- 所有圖片網址解析後必須與設定的圖片來源**同源**（協定、網域、有效連接埠相同），不能帶使用者名稱與密碼、`?` 或 `#`。圖片來源留空時使用清單來源。
- 檔案大小與回應要求見[託管說明](#hosting)。

## 精簡寫法：base {#base}

貼圖較多時，可以用 `base` 範本取代逐一填寫 `src`：

```json
{
  "version": 1,
  "base": "https://stickers.example.com/smoji/{pack}/{id}.webp",
  "packs": [
    {
      "id": "douyin",
      "label": "抖音",
      "items": [
        { "id": "smile", "label": "微笑" },
        { "id": "cool", "label": "酷", "src": "https://stickers.example.com/smoji/extra/cool.png" }
      ]
    }
  ]
}
```

- `base` 必須同時包含 `{pack}` 和 `{id}`，分別替換為分組 ID 和貼圖 ID；展開後也必須符合圖片來源設定。
- 沒有 `src` 的貼圖使用範本產生網址；寫了 `src` 的以 `src` 為準。
- 展開後的結果仍是完整網址，評論中保存的標記格式不變。

`base` 從 v0.2.1 開始支援。

## 更新貼圖素材 {#updates}

評論中保存的是**完整的圖片網址**。更新素材時請注意：

- 保留舊圖片的網址，或在原路徑上放置相容的副本。只替換清單無法修復歷史評論中已經失效的圖片。
- 保持歷史圖片符合已設定的圖片來源。明確設定來源後，移動清單不會改變圖片的信任範圍；留空時，更換清單來源會使舊來源的標記顯示為文字。歷史評論不會自動改寫。
- 從自選清單移除一張貼圖，只會從選擇器中移除它，不會刪除歷史評論裡的標記，也不會禁止同源圖片標記直接提交。
- 使用公共 CDN 時，圖片是否持續可用取決於素材託管方。自行遷移素材時，同時檢查 `base` 和每個明確指定的 `src`；正式環境清單不要引用本機開發網址。

## 標記格式 {#markers}

```text
![smoji:名称](图片地址)
```

圖片網址中的 `(` 和 `)` 會被編碼為 `%28` 和 `%29`。公開 API 的 `formConfig.smoji` 會回傳 `enabled`、`manifestUrl` 和選用的 `imageOrigin`，自訂前端可以據此實作自己的選擇器和呈現方式，規則與上文相同。
