# 動作の仕組み

このページでは、Ecoku がコメントをどう構成し、削除と訪問者情報をどう扱い、どんなデータを保存するかを説明します。デプロイや埋め込みの前に一読しておくと、想定外の挙動の大半を避けられます。

## サイトとページ {#page-key}

Ecoku は 2 つの値で「1 つの記事のコメント欄」を特定します。

- **サイト ID**（`siteId`）：管理画面でサイトを登録するときに決めます。1 つのインスタンスに複数のサイトを置けますが、コメント、許可オリジン、設定はサイト間で共有されません。
- **ページキー**（`pageKey`）：埋め込みコードが渡す値で、通常は `/posts/hello-world/` のような記事のサイト内パスです。

同じサイト内でページキーが同じページは、1 つのコメント欄を共有します。ページキーはサイト内の相対パスで、最大 512 文字です。完全な URL は使えず、`?` のクエリーパラメーターや `#` のフラグメントも含められません。

::: warning 一度使ったページキーは変更しないでください
コメントはページキーごとに保存されます。後からブログのパーマリンク形式を変えると、古い記事のページキーも変わり、それまでのコメントは表示されなくなります（データはデータベースに残っています）。ページキーには変わらない値を選んでください。
:::

## スレッドとページング {#threads}

コメントはツリー構造です。ルートコメントに返信を付けられ、その返信にさらに返信できます。

- **階層**：ルートコメントを 0 階層目とし、新しい返信は最大 16 階層目までです。16 階層目のコメントへの返信は拒否され、より上の階層のコメントに返信するよう案内されます。
- **インデント**：インデントは階層に応じて深くなりますが 3 階層目までで、それより深い返信は 3 階層目と同じ位置に揃います。3 階層目以降はニックネームの行にクリックできる `@返信先` が表示され、返信先のコメントを指します。これにより、深い議論でもスマートフォンで細長く潰れません。
- **折りたたみ**：返信のあるコメントの横には `[-]` があり、クリックすると枝全体が折りたたまれ、「N 件の返信を折りたたみ済み」（已折叠 N 条回复）と表示されます。

ページングはルートコメントにだけ適用されます。1 ページに一定数のルートコメント（デフォルト 10 件）を表示し、**その下のすべての返信もまとめて**返します。ページをめくると議論がまるごと入れ替わるので、返信が次のページに分断されることはありません。

1 つの巨大な議論がサービスを圧迫しないよう、1 回の一覧リクエストには上限があります。コメントは最大 200 件、階層は 16、レスポンスは 1 MiB までです。総数を数えるときは、同じページについて最大 10,000 件のコメントまでを確認します。どれか 1 つでも超えると、サーバーは切り詰めたデータではなくエラーを返し、コメント欄には読み込み失敗と表示されます。通常のブログコメントでこれらの上限に達することはまずありません。実際に達した場合は、1 ページあたりのルートコメント数を減らすか、独自のフロントエンドで[階層ごとに読み込む API](../reference/api#cursor)を使ってください。

## 削除 {#deletion}

管理画面には 2 種類の削除があり、どちらも取り消せません。

**墓標削除**：コメントのニックネーム、メールアドレス、URL、本文を消去しますが、議論内の位置と日時は残します。公開ページでは「削除済み」（已删除）と「[このコメントは削除されました]」（[该评论已删除]）と表示されます。その下の返信はそのまま残り、墓標には返信できなくなります。これにより、コメントを 1 件削除しても議論全体の文脈は失われません。

**完全削除**：墓標をデータベースから取り除きます。完全削除できるのは、**返信が 1 件も付いていない**墓標だけです。

## 訪問者情報 {#visitor-identity}

訪問者はコメントするのに登録は不要で、入力するのは 3 項目だけです。

| 項目 | 必須か | 公開されるか |
| --- | --- | --- |
| ニックネーム | 必須、最大 80 文字 | 公開 |
| メールアドレス | デフォルトで必須。サイト設定で任意に変更可能 | 非公開。返信通知にのみ使用 |
| URL | デフォルトで任意。必須に変更可能。`http://` または `https://` のみ受け付けます | 公開。ニックネームのリンクとして表示 |

訪問者がルートコメント欄で入力した情報は、返信するときにも自動で使われます。あるコメントの「返信」（回复）を直接押した場合、足りない訪問者情報はその返信欄で入力します。ページの先頭には戻りません。

投稿に成功すると、ブラウザがこの訪問者情報を 7 日間記憶するので、次回から入力し直す必要はありません。

- ブラウザの IndexedDB に保存され、エクスポートできない AES-GCM 鍵で暗号化されます。Cookie、localStorage、URL には書き込みません。
- Ecoku のサービスアドレスとサイト ID ごとに別々に保存され、サイト間では共有されません。
- 7 日後に無効になります。ブラウザが対応していない場合、データが壊れている場合、期限が切れた場合は、コメント欄が空の状態に戻るだけで、コメントの投稿には影響しません。
- ブラウザのサイトデータを消去すれば削除されます。コメント欄に別途「情報を忘れる」ボタンはありません。

## ブロガー {#blogger}

ブロガーに専用のアカウントは必要ありません。管理画面でサイトのブロガーのニックネーム、メールアドレス、合言葉を設定すると、ブロガーはコメント欄の**ニックネーム欄**に合言葉を入力し、メールアドレスと URL を空のままにすれば投稿できます。サーバーが合言葉を認識すると、次のように処理します。

- このコメントのニックネームをブロガーのニックネームに、URL をサイトの URL に、メールアドレスをブロガーのメールアドレスに置き換えます。
- このコメントにブロガーの印を付け、ページではニックネームの後にバッジ（デフォルトは `[博主]`）を表示します。
- ブラウザはニックネーム欄を空にし、合言葉を訪問者情報として保存しません。

ブロガーの印はコメントの保存時に書き込まれ、その後は再計算されません。ブロガーのニックネームを変えても、合言葉を変えても、既存のコメントの印は変わりません。

「ニックネームがブロガーのニックネームと一致し、メールアドレスがブロガーのメールアドレスと一致する（大文字と小文字を区別しない）」ことを基準に過去のコメントへブロガーの印を補完するのは、次の 2 つの場面だけです。旧バージョンから schema v5 へアップグレードするときの一回限りのマイグレーションと、[Twikoo の初回インポート](../self-hosting/twikoo)です。

## 純テキスト

コメント本文とニックネームは、常に純テキストとして表示されます。

- HTML タグは解釈されず、そのまま文字として表示されます。
- Markdown はレンダリングせず、URL も自動でリンクにしません。
- 改行は保持されます。

唯一の例外は [Smoji スタンプ](../integration/smoji)です。サイトでスタンプパックを有効にすると、形式が正しく、スタンプ一覧と同じオリジンにある `![smoji:名前](画像URL)` が画像として表示されます。それ以外はすべて文字として表示されます。

訪問者の URL はニックネームのリンクとしてだけ表示され、`rel="nofollow ugc noopener noreferrer"` が付きます。

## 保存・公開されるデータ {#data}

各コメントについて、データベースにはサイト ID、ページキー、記事タイトル、親コメント、ニックネーム、メールアドレス、URL、本文、ブロガーの印、削除日時、作成日時と更新日時を保存します。

公開 API が返すのは、コメント ID、サイト ID、ページキー、親コメント ID、ニックネーム、URL、本文、ブロガーかどうか、削除済みかどうか、日時だけです。**メールアドレスはどの公開 API にも含まれません。**

Ecoku は訪問者の IP、User-Agent、位置情報を保存せず、ログにも記録しません。IP はレート制限のためにメモリ上で短時間使うだけで、プロセスを再起動すると消えます。コメント欄はサードパーティーのアバター、アクセス解析、IP 検索サービスに一切リクエストしません。

次の場合は、訪問者のブラウザがサードパーティーに直接接続します。

- Turnstile または Cap を有効にしている場合、検証ウィジェットを読み込むとき
- Smoji を有効にしている場合、スタンプ一覧があるサーバーからスタンプ画像を読み込むとき

## オリジン検証とレート制限

各サイトは管理画面で「許可オリジン」（允许来源）を登録します。ブラウザがコメントを読み込むとき、一覧にないオリジンは拒否されます。コメントを投稿するときは、登録済みのオリジンがリクエストに含まれていないとそのまま拒否されます。そのため、コメント欄は登録したサイトでしか使えません。

投稿、読み込み、削除、管理画面ログインはすべて IP ごとにレート制限され、デフォルトでは 1 分あたり投稿 5 回、読み込み 60 回です。リバースプロキシの背後に置く場合は [`trusted_proxies`](../self-hosting/reverse-proxy#trusted-proxies) を正しく設定してください。設定しないと、すべての訪問者が 1 つの枠を共有してしまいます。

## 日時とタイムゾーン

コメントの日時は `YYYY-MM-DD HH:mm` 形式で表示され、タイムゾーンはコンテナの環境変数 `TZ`（`ecoku.env` で設定）で決まります。日時にマウスを重ねると、`Asia/Shanghai UTC+8` のようにタイムゾーン名とオフセットが表示されます。
