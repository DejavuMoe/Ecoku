# コアコンセプトと動作原理

Ecoku の内部モデルとアルゴリズムについて解説します。

---

## スレッドコメントとページネーションモデル

Ecoku は**「無制限セマンティクス階層 + 最大3段階の視覚的インデント」**を採用しています。

### 1. セマンティクスと表示の分離
- **セマンティクス階層**：DOM の `aria-level` と `data-depth` はデータベース上の実際の深さを反映。
- **視覚的インデント**：`min(depth, 3)` で最大3階層までに制限。
- **文脈アンカー**：深さ $\ge 3$ のコメントには、直接の親コメントへの `@返信先` リンクがヘッダーに自動挿入されます。

### 2. ルートスレッドページネーション
- `page` と `pageSize` はルートコメント（`parent_id IS NULL`）にのみ適用。
- 上限内の成功レスポンスは**すべての公開子孫コメント**を含みます。200 ノード、子孫 16 階層、1 MiB JSON、集計対象 10,000 件のいずれかを超えると、切り詰めず 422 を返します。現行 SDK は読み込み失敗を表示し、独自の組み込みでは[単一階層カーソル API](../reference/api.md)で必要な分だけ取得できます。

---

## 墓標メカニズム（Soft Delete & Hard Purge）

1. **ソフトデリート（墓標化）**：
   - ニックネーム、メール、URL、本文を消去し、`deleted_at` を設定。
   - コメント ID と親子関係を保持し、会話の文脈を崩しません。
   - 本文は `[このコメントは削除されました]` と表示され、新規返信は不可。
2. **完全削除（物理パージ）**：
   - **子孫コメントが一切存在しない**墓標コメントのみ、管理者権限で物理削除可能。

---

## 訪問者情報の暗号化保存
- Web Crypto API で 256 ビット AES-GCM 鍵を生成。
- `serverURL + "::" + siteId` ごとに分離して IndexedDB に保存（有効期限 7 日間）。

---

## ブロガー合言葉認証
- サイトごとに 12〜80 文字の合言葉を bcrypt ハ希で保存。
- 投稿時、ニックネーム欄に合言葉を入力するだけで自動認証。

---

## トランザクショナル Outbox 通知
- コメント保存と通知キューへの登録を同一の SQLite トランザクションで実行。
- SMTP (TLS/STARTTLS) および Telegram Bot で配信。
