# アップグレードと移行

Ecoku は順序付けられたインプレース SQLite スキーママイグレーションを採用しています。

**[v0.1.9](./upgrades/v0.1.9)** への更新準備では、対象バージョンのリリースノートを事前にご確認ください。v0.1.8 からは schema v7 のままであり、データベース移行は不要です。主に公開読み取り上限とレート制限の保護が追加されます。v0.1.8 にロールバックする前に、明示的に追加した `rate_limit.comment_list` を削除してください。詳細な制限やロールバック手順はバージョン別ガイドを参照してください。

---

## 手順

1. 対象バージョンのリリースノートを確認し、コールドバックアップを取得。
2. `compose.yaml` の正確なイメージタグを変更（例: `git.via.moe/dejavu/ecoku:v0.1.9`）。
3. イメージを pull して再起動：
   ```bash
   sudo docker compose pull
   sudo docker compose up -d
   sudo docker compose logs --tail=100 -f ecoku
   curl -f http://127.0.0.1:12123/api/health
   ```

## スキーマの変遷

| イメージバージョン | スキーマ | 主な変更点 |
| :--- | :---: | :--- |
| **`v0.1.9`** | `v7`（変更なし） | 新規移行なし。公開コメント一覧の CWE-400 予算保護、単層カーソルページネーション、独立読み取りレート制限。 |
| **`v0.1.8`** | `v7` | `sites` テーブルに `smoji_enabled` および `smoji_manifest_url` を追加、サイト絵文字対応。 |
| **`v0.1.7`** | `v6`（変更なし） | スキーマ変更なし。ツールチェーン更新および多言語ドキュメント体系の整備。 |
| **`v0.1.6`** | `v6`（変更なし） | スキーマ変更なし。Cap クライアントに必要な動的 CSP ポリシーの最適化。 |
| **`v0.1.5`** | `v6` | `turnstile_settings` を `captcha_settings` に変更し、セルフホスト Cap をサポート。 |
| **`v0.1.4`** | `v5`（変更なし） | スキーマ変更なし。管理画面で合言葉保存時に過去コメントの `is_blogger` フラグを自動補完。 |
| **`v0.1.3`** | `v5` | `sites.blogger_passphrase_hash`、`comments.is_blogger`、Outbox 通知キューの宛先別分割。 |
| **`v0.1.2`** | `v4`（変更なし） | スキーマ変更なし。コメント欄タイポグラフィのベースライン配置調整。 |
| **`v0.1.1`** | `v4`（変更なし） | スキーマ変更なし。コメント折りたたみボタンの等幅 3ch 固定。 |
| **`v0.1.0`** | `v4` | 初回正式リリース。マルチサイトプレーンテキストコメント、墓標論理削除、通知、Turnstile。 |
| **以前のバージョン** | `v1`〜`v4` | プレリリース期間：単一コンテナ設計、SQLite WAL モード導入、タイムゾーン正規化。 |
