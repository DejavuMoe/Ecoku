# アップグレードとマイグレーション

Ecoku はバージョン管理されたインプレース（In-Place）かつトランザクション保証のある SQLite スキーママイグレーション体系を採用しています。

**[v0.2.1](./upgrades/v0.2.1)** へのアップデート準備では、まず該当バージョンのリリースノートをご確認ください。本リリースは schema v7 のままで、データベース移行はありません。主な変更点は Smoji マニフェスト容量の拡張と任意の `base` テンプレート対応です。詳細な制約、クライアント側の挙動、ロールバック手順はバージョン別ガイドを参照してください。

アップグレード作業では、Compose ファイル内の**正確なイメージタグ**を変更するだけです。サービス起動時に自動検出され、バージョン順にデータベースマイグレーションが実行されます。

---

## アップグレードのコア規約

1. **一方向トランザクションマイグレーション**：スキーママイグレーションは同一の SQLite ファイル内で順次実行され、成功時に `schema_migrations` テーブルにバージョン記録を追加します。Ecoku は**自動ダウングレード（Down-migration）をサポートしません**。
2. **浮動タグの厳禁**：本番環境で `latest` を使用することは厳禁です。必ず `v0.2.1` のような正確なリリースバージョンを指定してください。
3. **不可逆性とロールバックの原則**：一度上位スキーマ（例: v7）にマイグレーションされたデータベースは、**イメージタグを古いバージョンに戻すだけでは起動できません**。古いバイナリは未知の上位スキーマを検出すると起動を拒否します。ロールバックには必ずアップグレード前に取得したコールドバックアップを使用してください。

## 標準停止アップデート手順（SOP）

```bash
cd ~/Ecoku

# ステップ 1: アップグレード対象バージョンのリリースノートを確認し、設定変更を把握
# （下記のバージョン別移行ガイド一覧を参照）

# ステップ 2: サービスを停止してコールドバックアップを取得
sudo docker compose down
tar -czvf "ecoku-preupgrade-$(date +%Y%m%d_%H%M%S).tar.gz" data/ app/config.yaml ecoku.env compose.yaml

# ステップ 3: compose.yaml 内の image を新バージョンに変更（例: git.via.moe/dejavu/ecoku:v0.2.1）
# 新しい環境変数が必要な場合は ecoku.env に追記

# ステップ 4: 新しいイメージを pull して起動
sudo docker compose pull
sudo docker compose up -d

# ステップ 5: 起動ログとスキーママイグレーション状態を確認
sudo docker compose logs --tail=100 -f ecoku

# ステップ 6: ヘルスチェックと動作検証
curl --fail --silent --show-error http://127.0.0.1:12123/api/health
```

## スキーマバージョン変遷履歴

| イメージバージョン | スキーマバージョン | データベースの主な変更点と機能 |
| :--- | :---: | :--- |
| **`v0.1.9`** | `v7`（変更なし） | 新規移行なし。公開コメント一覧の CWE-400 リソース予算保護、単層カーソルページネーション、独立読み取りレート制限。 |
| **`v0.1.8`** | `v7` | `sites` テーブルに `smoji_enabled` (真偽値) および `smoji_manifest_url` (TEXT) を追加、サイト絵文字パック対応。 |
| **`v0.1.7`** | `v6`（変更なし） | スキーマ変更なし。ビルドツールチェーン更新、多言語ドキュメント体系の構築、CI 最適化。 |
| **`v0.1.6`** | `v6`（変更なし） | スキーマ変更なし。Cap クライアント計測スクリプトに必要な動的 CSP ポリシーの修正。 |
| **`v0.1.5`** | `v6` | `turnstile_settings` テーブルを `captcha_settings` に変更、`provider` およびセルフホスト Cap 設定を追加。 |
| **`v0.1.4`** | `v5`（変更なし） | スキーマ変更なし。管理画面で合言葉保存時に既存の全有効コメントの `is_blogger` フラグを自動補完。 |
| **`v0.1.3`** | `v5` | `sites.blogger_passphrase_hash`、`comments.is_blogger`、Outbox 通知キューの宛先別分割。 |
| **`v0.1.2`** | `v4`（変更なし） | スキーマ変更なし。コメントメタデータ表示のベースライン揃えと 14px タイプスケール。 |
| **`v0.1.1`** | `v4`（変更なし） | スキーマ変更なし。コメント折りたたみボタン（`[+]`/`[-]`）を 3ch 等幅に固定し、ガタつきを排除。 |
| **`v0.1.0`** | `v4` | 初回正式リリース。マルチサイトプレーンテキストコメント、墓標論理削除、通知設定、Turnstile。 |
| **以前のバージョン** | `v1` 〜 `v4` | RC プレリリース期間：単一コンテナアーキテクチャ、SQLite WAL モード導入、タイムゾーン標準化。 |
