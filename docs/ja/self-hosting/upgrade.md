# アップグレードとマイグレーション

Ecoku はバージョン管理されたインプレース（In-Place）かつトランザクション保証のある SQLite スキーママイグレーション体系を採用しています。

**[v0.2.5](./upgrades/v0.2.5)** は 2026-09-26 に公開されました。コメント欄の既定スタイルを紙と墨に変更し、既定の変数をホストから上書きでき、`auto` がホストのライト／ダークに追従します。schema は v8 のままです。

更新前に対象バージョンの設定互換性を確認してください。Compose の正確なイメージ tag を変更すると、起動時に順番に DB 移行を実行します。

---

## アップグレードのコア規約

1. **一方向トランザクションマイグレーション**：スキーママイグレーションは同一の SQLite ファイル内で順次実行され、成功時に `schema_migrations` テーブルにバージョン記録を追加します。Ecoku は**自動ダウングレード（Down-migration）をサポートしません**。
2. **浮動タグの厳禁**：本番環境で `latest` を使用することは厳禁です。必ず `v0.2.5` のような正確なリリースバージョンを指定してください。
3. **不可逆性とロールバックの原則**：一度上位スキーマ（例: v8）にマイグレーションされたデータベースは、**イメージタグを古いバージョンに戻すだけでは起動できません**。古いバイナリは未知の上位スキーマを検出すると起動を拒否します。ロールバックには必ずアップグレード前に取得したコールドバックアップを使用してください。

## 標準停止アップデート手順（SOP）

```bash
(
set -eu
umask 077
cd "$HOME/Ecoku"
install -d -m 700 "$HOME/backups"
sudo docker compose down
archive="$HOME/backups/ecoku-$(date +%Y%m%d_%H%M%S).tar.gz"
[ ! -e "$archive" ]
sudo tar -czf - data/ app/config.yaml ecoku.env compose.yaml > "$archive"
contents=$(tar -tzf "$archive")
for required in data/ecoku.sqlite3 app/config.yaml ecoku.env compose.yaml; do
  printf '%s\n' "$contents" | grep -Fx "$required" > /dev/null
done
printf 'Verified backup: %s\n' "$archive"
vi app/config.yaml compose.yaml
sudo docker compose pull && sudo docker compose up -d
curl --fail --silent --show-error http://127.0.0.1:12123/api/health
)
```

## v0.2.5 の互換性

スキーマは v8 のままで新しい移行はありません。設定キー、環境変数、Compose のマウント、パスワードハッシュは変わらず、v0.2.4 からインプレースで更新でき、v0.2.4 へ戻す場合も通常は旧イメージ tag に戻すだけで済みます。コメント欄の既定スタイルはイメージとともに変わり、既存の上書き CSS が新しい既定値に重なる場合があるため、更新後に各埋め込みサイトをライトとダークで確認してください。詳しくは [v0.2.5 へのアップグレード](./upgrades/v0.2.5) を参照してください。
