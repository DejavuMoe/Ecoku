# v0.2.5 へのアップグレード

停止してコールドバックアップを検証 → 正確なイメージ tag を指定 → `sudo docker compose pull && sudo docker compose up -d` → ヘルスチェック、必要ならロールバック。

リリース日：2026-09-26。

コメント欄の既定スタイルを「紙と墨」に変更し、既定の `--ecoku-*` 変数をホストから直接上書きできるようにしました。`data-theme="auto"` はホストのライト／ダークに追従し、Turnstile のサーバー側検証は HTTP リダイレクトを拒否します。

## 主な変更

- コメント欄の既定スタイル：身元フィールドは罫線入力になり、本文は投稿カードに直接書き込みます。塗りの主ボタンは 1 つだけで、スタンプ、プレビュー、キャンセル、並べ替えはテキストボタンです。角丸は 6px / 3px、日時・折りたたみ・文字数・ページ番号は等幅フォント、ブロガーバッジ・リンクホバー・フォームエラーは朱色のアクセントを使います。Cap は公式の 260×58px を維持し、枠の角丸は Ecoku の変数に従います。
- 既定の `--ecoku-*` 変数は詳細度ゼロで宣言され、`.ecoku-comments` に同名の変数を書くだけで上書きできます。アクセント、エラー、角丸、影、等幅フォント、文字サイズの変数を追加しました。[カスタム CSS](../../integration/custom-css) を参照してください。
- `data-theme="auto"` は `color-scheme` を固定しなくなり、サイトの手動ライト／ダーク切り替えがシステム設定と異なってもコメント欄の配色が反転しません。
- タッチ端末ではコメント入力欄を 16px 以上に保ち、iOS のフォーカス時拡大を防ぎます。
- Turnstile Siteverify が HTTP リダイレクトを受け取った場合は検証サービス利用不可として扱い、引き続きフェイルクローズします。

## 互換性

スキーマは v8 のままで、新しい移行はありません。設定キー、環境変数、Compose のマウント、パスワードハッシュは変わらず、v0.2.4 からインプレースで更新できます。コメント欄の DOM クラス名、文言、SDK とローダーのインターフェースも変わりません。

埋め込みサイトの注意点：

- 既定の注入スタイルまたは `/client/ecoku.css` を使うサイトは、イメージの更新とともに見た目が変わります。既存の上書き CSS が新しい既定値に重なる場合があるため、更新後にライトとダークでコメント欄を確認してください。旧既定値に勝つためだけに書いた詳細度の高いルールは、`.ecoku-comments` 上の変数宣言に置き換えられます。
- `data-css-url` で独自のスタイルシートを指定しているサイト、または `none` のサイトは見た目が変わりません。
- `/client/` のアセットは 1 時間キャッシュされるため、更新直後はブラウザが旧スタイルを使う場合があります。

## アップグレード手順

1. [バックアップと復元](../backup) に従って停止し、ボリューム外にコールドバックアップを作成・検証します。`data/`（WAL/SHM を含む）、`app/config.yaml`、`ecoku.env`、元の `compose.yaml` を含めます。
2. Compose の image を `git.via.moe/dejavu/ecoku:v0.2.5` に変更し、次を実行します。

```bash
sudo docker compose config --quiet
sudo docker compose pull && sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail=100 ecoku
curl --fail --silent --show-error http://127.0.0.1:12123/api/health
```

3. 各埋め込みサイトの記事ページを開き、ライトとダークでコメント欄、返信フォーム、検証ウィジェットが正しく表示されることを確認します。

## v0.2.4 へのロールバック

どちらもスキーマ v8 です。通常は停止してイメージを `git.via.moe/dejavu/ecoku:v0.2.4` に戻し、pull して起動すれば、現在のデータベースと更新後の新しいコメントを保持できます。コメント欄のスタイルと Turnstile のリダイレクト修正も元に戻ります。更新前のデータが必要な場合に限り完全なコールドバックアップを復元してください。先に現在の状態を退避し、バックアップ後の書き込みが失われることを明示的に受け入れたうえで行い、データベースを自動で上書きしないでください。
