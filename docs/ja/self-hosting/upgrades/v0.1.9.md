# v0.1.9

- リリース日：2026-08-31
- schema：v7、マイグレーションなし
- イメージ：`git.via.moe/dejavu/ecoku:v0.1.9`

## 変更点

このバージョンでは、公開コメント一覧のリソース枯渇の問題（CWE-400）を修正しました。

- 1 回の一覧リクエストで返すのは、最大でコメント 200 件、返信 16 階層、1 MiB の JSON です。総数を数えるときは、同じページについて最大 10,000 件のコメントまでを確認します。どれか 1 つでも超えると `422` を返し、切り詰めたデータは返しません。既存のコメント欄には読み込み失敗と表示され、自動的に別の読み込み方式に切り替わることはありません。
- 階層ごとの読み込みを追加しました。`parentId` / `afterId` を渡すと、直接の返信を 1 階層分だけ返します。独自のフロントエンドで必要に応じて読み込むためのもので、[REST API](../../reference/api#cursor) を参照してください。
- 一覧の処理は同時に最大 4 リクエストまでで、データベースの読み込みは 1 回あたり 2 秒で打ち切られます。混雑またはタイムアウトの場合は `503` を返します。
- `rate_limit.comment_list` を追加しました。デフォルトは IP ごとに 60 秒あたり 60 回で、超えると `429` を返します。ブラウザのプリフライトリクエストや、オリジンが拒否されたリクエストも数に含まれます。
- レート制限の種類ごとに追跡する IP は最大 10,000 個で、上限に達すると既存の記録を追い出すのではなく、新しい IP を拒否します。
- SQLite の接続を作り直した後に、外部キー、同期レベル、ビジー待機の設定を再度有効にします。これはデータベースのマイグレーションではありません。

## 互換性

- Compose のマウント、UID/GID、ポート、ログ、環境変数、シークレットはいずれも変わらず、v0.1.8 からその場でアップグレードできます。
- `rate_limit.comment_list` を書かない場合はデフォルト値 60 が使われるので、古い設定のままでも起動できます。
- 1 ページあたりのルートコメント数を減らしても、1 つのスレッドが大きすぎる・深すぎる場合や、ページ全体のコメント数が集計の上限を超える場合は解決しません。
- `trusted_proxies` を正しく設定していないと、リバースプロキシの背後にいるすべての訪問者が読み込みの枠を共有します。[リバースプロキシ](../reverse-proxy#trusted-proxies)を参照して確認してください。

## アップグレード

[アップグレード手順](../upgrade#steps)に従い、イメージを `git.via.moe/dejavu/ecoku:v0.1.9` に変更します。起動後、実際のページでコメント一覧、並び替え、ページ送り、返信を確認してください。上限を試すために、本番環境で深い議論を作ったり高頻度のリクエストを送ったりしないでください。

## v0.1.8 へのロールバック

1. サービスを停止します。
2. 設定に `rate_limit.comment_list` を追加していた場合は削除します。v0.1.8 はこのフィールドを認識せず、起動を拒否します。
3. イメージを `git.via.moe/dejavu/ecoku:v0.1.8` に戻し、取得して起動します。

どちらのバージョンも schema v7 なので、データベースの復元は不要です。ロールバックすると上記のリソース枯渇の問題が再び露出するため、一時的な措置としてだけ使ってください。
