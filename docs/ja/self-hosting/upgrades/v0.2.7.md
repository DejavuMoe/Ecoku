## 変更点

- 通知メールを、コメント欄や管理画面と同じ紙と墨の配色（ダークモード対応）に変更しました。文字はシステムに搭載されている中国語・欧文のサンセリフフォントで表示され、Windows のメールクライアントで中国語が宋体になることはなくなりました。
- メールの件名に記事タイトルが付きます（例：「您在 [站点名称] 上有新评论：[文章标题]」（[サイト名] に新しいコメントがあります：[記事タイトル]））。新しい返信と訪問者向け返信のメールにも記事タイトルと日時が表示されます。日時は UTC 固定ではなく、コンテナの `TZ` で表示し、UTC との時差を併記します。
- メール内のスタンプは、記法のままではなく画像または `[表情：标签]`（[スタンプ：ラベル]）として表示されます。
- Telegram の通知に投稿日時を追加し、返信されたコメントを引用として表示します。本文の上限は 1000 文字になりました。
- コメントを削除すると、未送信の通知は送られず、送信済みの Telegram メッセージは「这条评论已被删除，通知内容已移除。」（このコメントは削除され、通知の内容は取り除かれました）に書き換えられます。送信済みのメールは取り消せません。詳しくは[コメントを削除した後](../notifications#after-deletion)を参照してください。
- 宛先のメールボックスが拒否された場合や Telegram のチャットが使えない場合は、再試行しなくなりました。完了した通知のレコードは 30 日後に自動的に削除されます。
- ドキュメントをソースコードと照合し、API、コマンドライン、バックアップと復元、よくある質問の記述を複数修正しました。

## 互換性

- schema v9 は通知キューのテーブル `notification_outbox` をその場で作り直し、新しい状態、イベントの種類、メッセージ ID の列とインデックスを追加します。コメント、サイト、設定は変わらず、キューのレコードと番号はすべて保持されます。8 回の試行を使い切った失敗レコードは「諦めた」状態になります。
- 設定項目、環境変数、Compose のマウント、管理 API、コメント欄、SDK は変わりません。
- アップグレード前に送信された Telegram メッセージにはメッセージ ID が記録されていないため、後で対応するコメントを削除しても書き換えられません。

## 過去の移行上の注意 {#upgrade}

このバージョンは記録用です。インストールやダウングレードの手順は提供しません。異なる schema に戻すには、対象バージョンに対応した完全なコールドバックアップが必要です。
