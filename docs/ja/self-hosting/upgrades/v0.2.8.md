## 変更点 {#changes}

- 管理画面のコメントは日付ごとにまとまり、削除の確認はコメントの横に表示されます。設定フォームは項目ごとの行になり、編集後にだけ保存バーが表示され、未保存のページを離れる前に確認します。キーボードショートカットと狭い画面の下部ナビゲーションを追加しました。管理画面とドキュメントサイトには「區」の印章ロゴを使います。
- サイトの保存に失敗しても、名前やブロガーの合言葉などの未保存の内容を保持します。通知やセキュリティの設定を読み込めない場合は、フォームを無効にして再試行できます。
- 公式イメージにログ、コメント欄の静的ファイル、管理画面の静的ファイル、SQLite のパスを組み込み、管理画面をデフォルトで有効にしました。`*_env` を省略すると標準の環境変数名を使い、`admin.allowed_origins` を省略すると `notifications.instance_public_url` のオリジンを使います。値は[設定リファレンス](../../reference/configuration)を参照してください。
- デプロイ用テンプレートを短くしました。`app/config.yaml` には `notifications.instance_public_url` のみが必要で、`ecoku.env` ではイメージに設定済みの `GIN_MODE` を繰り返しません。Compose は Docker デーモンのログ設定を使います。

## 互換性 {#compatibility}

- v0.2.7 からのアップグレードではデータベースのマイグレーションは実行されず、schema は v9 のままです。コメント欄と SDK、HTTP API、Compose のマウント、既存の設定キーは変わりません。
- 既存の完全な設定ファイルと Compose の `logging` 設定はそのまま使え、削る必要はありません。明示した値がデフォルトより優先されます。管理者の認証情報、通知の暗号化キー、データディレクトリは現在のものを使い続けます。
- イメージ内の `ECOKU_RUNTIME=container` が、コンテナのパスと管理画面のデフォルト設定を有効にします。ソースから実行する場合のパスと管理画面のデフォルトは従来どおりです。
- v0.2.7 は新しい最小構成の設定に対応していません。アップグレード時に明示的な設定を削った場合は、ロールバック前に完全な設定を戻す必要があります。

## 過去の移行上の注意 {#upgrade}

このバージョンは記録用です。インストールやダウングレードの手順は提供しません。異なる schema に戻すには、対象バージョンに対応した完全なコールドバックアップが必要です。
