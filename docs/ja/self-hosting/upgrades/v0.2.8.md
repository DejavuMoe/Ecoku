# v0.2.8

- リリース日：2026-10-01
- schema：v9（v0.2.7 からのアップグレードでは変更なし）
- イメージ：`git.via.moe/dejavu/ecoku:v0.2.8`

## 変更点 {#changes}

- 管理画面のコメントは日付ごとにまとまり、削除の確認はコメントの横に表示されます。設定フォームは項目ごとの行になり、編集後にだけ保存バーが表示され、未保存のページを離れる前に確認します。キーボードショートカットと狭い画面の下部ナビゲーションを追加しました。管理画面とドキュメントサイトには「區」の印章ロゴを使います。
- サイトの保存に失敗しても、名前やブロガーの合言葉などの未保存の内容を保持します。通知やセキュリティの設定を読み込めない場合は、フォームを無効にして再試行できます。
- 公式イメージにログ、コメント欄の静的ファイル、管理画面の静的ファイル、SQLite のパスを組み込み、管理画面をデフォルトで有効にしました。`*_env` を省略すると標準の環境変数名を使い、`admin.allowed_origins` を省略すると `notifications.instance_public_url` のオリジンを使います。値は[設定リファレンス](../../reference/configuration)を参照してください。
- デプロイ用テンプレートを短くしました。`app/config.yaml` には `notifications.instance_public_url` のみが必要で、`ecoku.env` ではイメージに設定済みの `GIN_MODE` を繰り返しません。Compose は Docker デーモンのログ設定を使います。

## 互換性 {#compatibility}

- v0.2.7 からのアップグレードではデータベースのマイグレーションは実行されず、schema は v9 のままです。コメント欄と SDK、HTTP API、Compose のマウント、既存の設定キーは変わりません。
- 既存の完全な設定ファイルと Compose の `logging` 設定はそのまま使え、削る必要はありません。明示した値がデフォルトより優先されます。管理者の認証情報、通知の暗号化キー、データディレクトリは現在のものを使い続けます。
- イメージ内の `ECOKU_RUNTIME=container` が、コンテナのパスと管理画面のデフォルト設定を有効にします。ソースから実行する場合のパスと管理画面のデフォルトは従来どおりです。
- イメージでは `admin.enabled` のデフォルトが `true` になりました。`app/config.yaml` に `admin.enabled` を書いていない場合、アップグレードすると管理画面が有効になります。このとき管理者の認証情報の環境変数と、`notifications.instance_public_url` または `admin.allowed_origins` が必要で、どれかが欠けているとサービスは起動しません。管理画面を使わない場合は、アップグレード前に `admin.enabled: false` を追加してください。v0.2.7 のドキュメントのテンプレートに沿った設定には `admin.enabled: true` が明記されているため、影響はありません。
- v0.2.7 は新しい最小構成の設定に対応していません。アップグレード時に明示的な設定を削った場合は、ロールバック前に完全な設定を戻す必要があります。

## アップグレード {#upgrade}

1. [バックアップと復元](../backup#cold-backup)に従ってサービスを停止し、コールドバックアップを取ります。元の `compose.yaml`、`app/config.yaml`、`ecoku.env` を残してください。
2. [アップグレード手順](../upgrade#steps)に従い、イメージを `git.via.moe/dejavu/ecoku:v0.2.8` に変更します。既存のデプロイでは設定をそのまま使え、最小構成のテンプレートに置き換える必要はありません。
3. ヘルスチェックが通ったら、コメントの読み込みと投稿、管理画面へのログイン、コメントの削除、サイトと通知の設定の保存を確認します。

## ロールバック {#rollback}

v0.2.7 は schema が同じなので、現在のデータベースと、アップグレード後のコメントや設定の変更を保持できます。

1. サービスを停止します。最小構成の `app/config.yaml` に変更した場合は、アップグレード前の完全な設定を戻します。
2. イメージを `git.via.moe/dejavu/ecoku:v0.2.7` に戻し、[アップグレード手順](../upgrade#steps)に従って取得、起動、確認します。

v0.2.6 以前のバージョンは schema v9 のデータベースを開けません。これらに戻す場合は、対応する古い schema のコールドバックアップから[復元](../backup#restore)する必要があります。バックアップ後のコメントや設定の変更は失われます。
