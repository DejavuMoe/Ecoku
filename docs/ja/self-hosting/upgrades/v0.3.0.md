# v0.3.0

- リリース日：2026-10-03
- schema：v10 → v11
- イメージ：`git.via.moe/dejavu/ecoku:v0.3.0`
- GHCR イメージ：`ghcr.io/dejavumoe/ecoku:v0.3.0`
- npm SDK：`ecoku@0.3.0`

## 変更 {#changes}

- Smoji に省略可能な「图片来源」（画像オリジン）を追加しました。エクスポートした JSON を自分でホストし、画像は指定した CDN から読み込めます。コメント、プレビュー、管理画面、メールで同じ規則を使用します。
- GitHub Actions が GHCR の両アーキテクチャのイメージ、npm SDK、SDK アーカイブとチェックサム付き GitHub Release を公開します。SDK バージョンはプロジェクトの tag と一致します。Woodpecker はドキュメントと既存の Forgejo イメージを引き続き公開します。
- YAML テンプレートに既定値、選択肢、例を集約しました。Compose に `TZ: Asia/Shanghai` を明記しました。ドキュメントは従来のレイアウトを維持し、管理画面の紙と墨の配色、コード強調表示とインライン余白を統一し、既定の検索翻訳を修正しました。

## 互換性 {#compatibility}

- 既存の `sites` テーブルに `smoji_image_origin` を追加します。既定値は空文字列です。アカウント、サイト、コメント、キュー、通知設定を維持します。ダウンマイグレーションはありません。
- 「图片来源」が空のサイトは一覧と同じオリジンのみ許可します。指定すると、その単一の画像オリジンのみ許可します。リモート JSON は許可範囲を拡張できません。
- 既存の Compose、YAML、管理者認証情報は引き続き有効です。パスワードやキーの再生成は不要です。v0.2.8 以前は引き続き [旧設定の移行](../upgrade#legacy-config) に従ってください。
- GHCR 公開の追加で既存環境のイメージ取得元は自動変更されません。npm とイメージは別々に公開されるため、取得前に該当ジョブの成功を確認してください。

## アップグレード {#upgrade}

1. サービスを停止し、データベース、同じディレクトリの `ecoku-secrets.json`、Compose、設定を [コールドバックアップ](../backup#cold-backup) します。`ecoku.env` を使用中なら含めてください。
2. [アップグレード手順](../upgrade#steps) に従い、イメージを `git.via.moe/dejavu/ecoku:v0.3.0` に変更し、`sudo docker compose pull && sudo docker compose up -d` を実行します。GHCR に切り替える場合は上記の同一バージョンを使用できます。
3. ヘルスエンドポイント、管理者ログイン、過去のコメント、通知を確認し、schema v11 への移行成功を確認します。
4. Smoji の配信元を分ける場合は [一覧と画像のホスティング](../../integration/smoji#hosting) に従って「图片来源」を指定し、選択 UI、プレビュー、コメント表示を確認します。
5. npm SDK を使うサイトは npm 公開成功後に `ecoku@0.3.0` をインストールし、再ビルドします。インスタンス配信の UMD はコンテナと一緒に更新されます。

## ロールバック {#rollback}

v0.2.9 は schema v11 を開けません。サービスを停止し、[復元手順](../backup#restore) に従って更新前のデータベース、永続キー、Compose、設定を復元してから旧イメージを起動してください。イメージ tag の変更だけでは戻せません。バックアップ後に追加したコメントや設定は失われます。npm SDK を使うサイトも以前の依存関係とビルド成果物に戻してください。
