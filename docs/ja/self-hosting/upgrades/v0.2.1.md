# v0.2.1

サービス停止とコールドバックアップ → 正確なイメージタグを変更 → `sudo docker compose pull && sudo docker compose up -d` → ヘルスチェックと業務確認。

## 更新による影響

- SQLite は **schema v7** のままで、データベース移行はありません。
- 環境変数、Compose マウント、ポート、コンテナー権限は変更しません。
- Smoji の上限を 64 パック、1 パック 600 件、合計 6,000 件、1 MiB UTF-8 に拡張し、任意の `base` テンプレートに対応しました。従来のマニフェストも利用できます。

## 更新手順

1. サービスを停止し、`data/`、`app/config.yaml`、`ecoku.env`、元の `compose.yaml` をバックアップします。
2. イメージを `git.via.moe/dejavu/ecoku:v0.2.1` に変更します。
3. `sudo docker compose config --quiet && sudo docker compose pull && sudo docker compose up -d` を実行し、ログ、ヘルスエンドポイント、コメントを確認します。

## v0.2.0 へのロールバック

停止後、正確な `v0.2.0` イメージタグに戻して pull・起動します。両版とも schema v7 のため通常は DB 復元不要です。
