# v0.2.0

サービス停止とコールドバックアップ → 正確なイメージタグを変更 → `sudo docker compose pull && sudo docker compose up -d` → ヘルスチェックと業務確認。

本リリースは主にドキュメント、組み込み例、API リファレンスの事実関係を修正・拡充します（2026-09-12）。

## 更新による影響

- SQLite は **schema v7** のままで、データベース移行はありません。
- 環境変数、Compose マウント、ポート、コンテナー権限、実行時データ形式は変更しません。
- 公開コメント一覧の予算、カーソルページング、読み取り制限、ステータスコードの説明を v0.1.9 の実装に合わせました。

## 更新手順

1. 隔離環境でページ、コメント一覧、返信、管理画面を確認します。
2. サービスを停止し、`data/`、`app/config.yaml`、`ecoku.env`、元の `compose.yaml` をバックアップします。
3. `compose.yaml` の `image` を `git.via.moe/dejavu/ecoku:v0.2.0` に変更します。他の設定は変更しません。
4. 実行します：

   ```bash
   sudo docker compose config --quiet
   sudo docker compose pull && sudo docker compose up -d
   sudo docker compose ps
   sudo docker compose logs --tail=100 ecoku
   curl --fail --silent --show-error http://127.0.0.1:12123/api/health
   ```

5. ヘルスエンドポイント、実際のコメント一覧、並べ替え、ページ切り替え、返信、管理画面を確認します。

## v0.1.9 へのロールバック

停止後、正確な `v0.1.9` イメージタグに戻して pull・起動します。両版とも schema v7 のため通常は DB 復元不要ですが、データ異常が確認された場合だけコールドバックアップ全体を復元してください。
