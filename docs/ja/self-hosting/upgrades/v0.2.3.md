# v0.2.3 への更新

停止してコールドバックアップを検証 → 正確なイメージ tag に変更 → `sudo docker compose pull && sudo docker compose up -d` → health と業務動作を確認し、必要ならロールバック。

Git tag 公開日：2026-09-16。更新前に、この正確な tag のイメージを取得できることを確認してください。

## 主な修正

- サイト設定保存時に過去コメントへ管理者フラグを再付与しません。合言葉は UTF-8 72 バイト以下とし、既存 bcrypt ハッシュは維持します。
- SMTP 全体にキャンセルと期限を適用。通知の完了保存に失敗した場合は DB 書き込みのみを再試行し、Telegram のリンクと HTML 構造を保持します。
- 順不同の Twikoo データでも直接の親子関係を保持します。Unicode 入力、管理リクエストの取消、Loader 再試行、Smoji URL/キーボード、非同期ウィジェットの終了処理を修正します。
- SPA は `setPageKey(pageKey, pageTitle)` でタイトルを更新できます。第2引数省略時は旧タイトルを消去します。直接 SDK の外部 CSS は引き続きホスト側で読み込みます。

## 互換性

今回の修正は schema v7、マウントパス、環境変数、bcrypt ハッシュを維持し、v0.2.2 から同じデータベースで更新できます。コメント、設定、WAL、バックアップを削除しません。設定保存によるブログ管理者フラグの再付与を停止し、既存フラグは保持します。過去の誤判定は認証済みコメントと自動判別できず、別途確認と修正許可が必要です。通知は少なくとも一度の配信です。完了書き込み失敗時は同じ結果を再保存し、プロセス内では再送しませんが、配信後・保存前のクラッシュでは再起動時に重複することがあります。

## 更新手順

1. [バックアップ手順](../backup)に従って停止し、ボリューム外のアーカイブを検証します。`data/`（WAL/SHM を含む）、`app/config.yaml`、`ecoku.env`、元の `compose.yaml` を保存してください。
2. イメージ公開後に Compose image を `git.via.moe/dejavu/ecoku:v0.2.3` へ変更します。設定、環境変数、マウントは維持します。
3. 以下を実行後、管理ログイン、既存コメント、管理者識別、通知を確認します。実際のテスト通知は操作者が明示的に実行してください。

```bash
sudo docker compose pull && sudo docker compose up -d
sudo docker compose logs --tail=100 ecoku
curl --fail --silent --show-error http://127.0.0.1:12123/api/health
```

## v0.2.2 へのロールバック

両版とも schema v7 なので、通常は停止後に `git.via.moe/dejavu/ecoku:v0.2.2` へ戻し、pull と起動を行えば、現在の DB と新規コメントを維持できます。ただし旧版の不具合も戻ります。更新前のデータが必要な場合のみ完全バックアップを復元します。現状を先に退避し、以降の書き込みが失われることを明示的に了承してから実行してください。DB を自動上書きしません。
