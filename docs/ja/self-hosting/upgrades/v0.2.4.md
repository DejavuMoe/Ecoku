# v0.2.4 への更新

停止してコールドバックアップを検証 → 正確なイメージ tag に変更 → `sudo docker compose pull && sudo docker compose up -d` → ヘルス確認とロールバック。

公開日：2026-09-16。

CAPTCHA を合言葉比較より先に検証し、ログはルートテンプレートのみ記録します。新規の 17 階層目返信を拒否します。管理者セッションは固定 8 時間で再読み込み・再起動後に復元でき、ログアウトで失効します。

## v0.2.4 の互換性

v8 は `admin_sessions` と有効期限インデックスを追加し、コメント、設定、既存の移行履歴を変更しません。旧ログインは失効し、再ログインが必要です。`admin.token_ttl_minutes` は省略するか 480 にしてください。`0` と `480` 以外の値では起動できません。マウント、環境変数、パスワードハッシュは維持します。v0.2.3 以前へ戻す場合は停止し、現在の状態を退避した後、更新前の完全なコールドバックアップと元のイメージを復元してください。古い tag に戻すだけでは v8 DB を開けません。復元によりバックアップ後の書き込みが失われるため、操作者の明示的判断が必要です。

## 更新手順

1. [バックアップと復元](../backup)に従って停止し、`data/`（WAL/SHM を含む）、`app/config.yaml`、`ecoku.env`、元の `compose.yaml` をボリューム外に保存して検証します。稼働中の SQLite メインファイルだけをコピーしないでください。
2. `admin.token_ttl_minutes` を削除するか 480 に設定します。本番管理画面は HTTPS とし、プロキシで Origin と Cookie を保持してください。HTTP は明示的に許可したループバック開発オリジンのみ使用できます。
3. Compose image を `git.via.moe/dejavu/ecoku:v0.2.4` に変更し、次のコマンドを実行します。初回起動で既存 DB をトランザクション内で v8 に移行します。手動 SQL は不要です。

```bash
sudo docker compose config --quiet
sudo docker compose pull && sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail=100 ecoku
curl --fail --silent --show-error http://127.0.0.1:12123/api/health
```

ヘルス API はプロセスの応答のみ確認します。コンテナのヘルス、既存コメント、再読み込み・再表示でのログイン復元、ログアウト後のアクセス拒否を確認してください。本番で攻撃リクエストや深いスレッドを作成しないでください。
