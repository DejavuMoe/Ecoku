# v0.2.4

- リリース日：2026-09-16
- schema：v7 → v8
- イメージ：`git.via.moe/dejavu/ecoku:v0.2.4`

## 変更点

- 管理者ログインを、HttpOnly Cookie とデータベースのセッションによる方式に変更しました。ログイン後は 8 時間固定で、再読み込みしてもブラウザを閉じて開き直しても復元されますが、延長はされません。ログアウト時にはサーバー側でセッションを取り消します。ログインのレスポンスは token を返さなくなりました。
- CAPTCHA はブロガーの合言葉のチェックより前に行われ、検証を通過しないと合言葉が正しいかどうかを試せません。
- アクセスログにはルートのテンプレートだけを記録し、実際のパスは書き込まなくなりました。
- 新しい返信は最大 16 階層（ルートコメントを 0 階層目とする）までで、17 階層目は拒否されます。既存の深い階層のコメントには影響しません。

## 互換性

- schema v8 は、管理者セッションのテーブルと有効期限のインデックスを追加するだけで、コメント、設定、既存のマイグレーション記録には手を加えません。
- アップグレード後、すべての管理者が再ログインする必要があります。
- `admin.token_ttl_minutes` は省略するか `480` にするしかありません。古い設定でそれ以外の値を使っていると起動に失敗するので、アップグレード前に変更してください。
- 本番環境の管理画面には HTTPS でアクセスする必要があり、リバースプロキシは `Origin` リクエストヘッダーと Cookie を保持する必要があります。HTTP はループバックの開発用アドレスにだけ許可されます。
- マウント、環境変数、パスワードハッシュは変わりません。

## アップグレード

1. [バックアップと復元](../backup#cold-backup)の手順で、サービスを停止してコールドバックアップを取ります。
2. `app/config.yaml` の `admin.token_ttl_minutes` を確認します。この行を削除するか、`480` に変更します。
3. [アップグレード手順](../upgrade#steps)に従い、イメージを `git.via.moe/dejavu/ecoku:v0.2.4` に変更します。初回起動時に自動で v8 にマイグレーションされます。
4. 確認：過去のコメントが正しく表示されること。管理画面にログインした後、再読み込みしてもブラウザを閉じて開き直してもログインが保たれること。ログアウトを押した後は続けてアクセスできないこと。

## ロールバック

アップグレード後のデータベースは v8 になっており、v0.2.3 以前のバージョンでは開けません。ロールバックには次の手順が必要です。

1. サービスを停止し、調査用に現在の `data/` ディレクトリを残しておきます。
2. アップグレード前のコールドバックアップから[復元](../backup#restore)します。バックアップ内の `compose.yaml` によって、元のイメージのバージョンに戻ります。

バックアップ後に投稿されたコメントや設定の変更は失われます。
