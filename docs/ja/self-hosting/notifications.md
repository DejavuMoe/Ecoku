# 通知

Ecoku は、新しいコメントがあったときにブロガーへ通知し、訪問者のコメントに返信が付いたときにその訪問者へメールで知らせることができます。通知は管理画面の「通知設定」（通知设置）ページで設定し、インスタンス内のすべてのサイトに適用されます。

| チャネル | 送信先 |
| --- | --- |
| メール（SMTP） | ブロガー：入力した宛先リストに送ります。訪問者：返信されたコメントに残されたメールアドレスに送ります。 |
| Telegram ボット | ブロガーにのみ送ります。入力したユーザー、グループ、チャンネルの ID に送ります。 |

## 有効にする前の準備

- `app/config.yaml` に `notifications.instance_public_url` が設定されていること。設定されていないと、どのチャネルも有効にできません。
- `ecoku.env` に `ECOKU_NOTIFICATION_ENCRYPTION_KEY` が設定されていること。SMTP パスワードと Bot Token は、このキーで暗号化しないと保存できません。
- サーバーが外部の SMTP ポート（一般的には 465 または 587）または `api.telegram.org` にアクセスできること。クラウド事業者によっては、SMTP の送信ポートがデフォルトでブロックされています。

## 通知が送られるタイミング

「ブロガー」かどうかは、コメントの保存時に記録されたブロガーの印、つまりそのコメントが[ブロガーの合言葉](./admin#blogger)で投稿されたかどうかで判断します。

| 場面 | ブロガーへの通知（メール / Telegram） | 返信された訪問者へのメール |
| --- | :---: | :---: |
| 訪問者がルートコメントを投稿 | 送信 | — |
| 訪問者が訪問者に返信 | 送信 | 送信 |
| 訪問者がブロガーに返信 | 送信 | — |
| ブロガーがルートコメントを投稿 | 送信しない | — |
| ブロガーが訪問者に返信 | 送信しない | 送信 |
| ブロガーがブロガーに返信 | 送信しない | — |

補足：

- 返信された訪問者がメールアドレスを残していない場合や、返信した人と返信された人のメールアドレスが同じ場合（自分への返信）は、訪問者へのメールは送りません。
- 通知が送られる前に返信先のコメントが削除された場合、訪問者へのメールは取り消されます。
- 訪問者への返信通知は、メールチャネルが有効なときにだけ送られます。個別のスイッチはありません。メールチャネルを無効にすると、訪問者への返信通知も送られなくなります。
- Telegram で訪問者に通知することはありません。

## メール

| 項目 | 説明 |
| --- | --- |
| SMTP サーバー | 例：`smtp.example.com`。 |
| ポート | メール事業者の指定に従って入力します。一般的には 465（SSL/TLS）または 587（STARTTLS）です。 |
| 暗号化方式 | `SSL/TLS`：接続時から暗号化します。`STARTTLS`：通常の接続を確立してから暗号化に切り替えます。暗号化しない SMTP には対応していません。 |
| ユーザー名 | 空でもかまいません。空の場合は SMTP 認証を行いません。 |
| パスワード | 保存後は「設定済み」（已设置）とだけ表示されます。空のままにすると変更しません。 |
| 送信元アドレス | メールの From アドレスです。多くの事業者は、ログインアカウントと一致することを求めます。 |
| 通知の宛先 | ブロガー向け通知を受け取るメールアドレスです。複数入力でき、Enter キーまたはカンマで区切ります。 |

「テストメールを送信」（发送测试邮件）は、フォームに入力中の値（パスワードが空の場合は保存済みのパスワード）を使って宛先にテストメールを送ります。事前に保存する必要はありません。失敗した場合は、接続タイムアウト、認証の失敗、TLS ハンドシェイクの失敗など、原因がページに表示されます。

メールにはプレーンテキスト版と HTML 版の両方が含まれ、サイト名、コメントした人、記事タイトル、投稿日時、コメント本文、元のコメントに移動するリンクが記載されます。返信通知には、返信されたコメントも添付されます。メール内の日時は UTC です。

件名の形式：

- ブロガー向け通知：「您在 [站点名称] 上有新评论」（[サイト名] に新しいコメントがあります）または「您在 [站点名称] 上有新回复」（[サイト名] に新しい返信があります）
- 訪問者向け返信通知：「你在 [站点名称] 的评论收到了回复」（[サイト名] でのあなたのコメントに返信がありました）

## Telegram

1. Telegram で [@BotFather](https://t.me/BotFather) からボットを作成し、Bot Token を取得します。
2. ボットがメッセージを送れるようにします。個人チャットの場合は、先にボットにメッセージを 1 通送ります。グループやチャンネルの場合はボットを追加し、チャンネルではさらに管理者にする必要があります。
3. 送信先の ID を調べます。個人ユーザーは `123456789` のような数字の列で、グループとチャンネルは通常 `-100` で始まります（例：`-1001234567890`）。
4. 管理画面に Bot Token と送信先 ID（複数可）を入力し、「テストメッセージを送信」（发送测试消息）で確認してから保存します。

メッセージの内容はメールと同じです。本文が長い場合は切り詰められ（コメント本文は最大 1200 文字）、末尾に「元の記事を見る」（查看原文）リンクが付きます。

## 配信の仕組み

通知はコメントの投稿時に同期的には送られません。コメントと、それに伴って送る通知は、同じデータベーストランザクションで送信待ちキューに書き込まれ、バックグラウンドタスクが 3 秒ごとにまとめて取り出して送信します。そのため、次のようになります。

- メールサーバーに一時的に接続できなくても、訪問者のコメント投稿には影響しません。
- 宛先ごとに別々のレコードになり、個別に再試行されます。1 つのアドレスで失敗しても、ほかのアドレスには影響しません。
- 失敗すると 2、4、8、16、32、64、128 分の間隔で再試行し、合計 8 回試してもだめなら諦めます。
- 通知の送信先はキューに入った時点で確定します。その後チャネルを無効にしたり宛先を変更したりしても、すでにキューに入った通知はそのまま配信されます。
- 「送信済みだが結果をまだ記録していない」瞬間にプロセスがクラッシュすると、再起動後にもう一度送られることがあります。まれに通知が重複して届く場合があります。

ログには通知の番号、エラーの種類、回数だけを記録し、宛先アドレス、コメント内容、認証情報は記録しません。

## よくある問題 {#troubleshooting}

**保存時に「实例公开网址尚未配置」（インスタンスの公開 URL が設定されていません）と表示される**：`app/config.yaml` に `notifications.instance_public_url` を設定してから、コンテナを作り直してください。

**保存時に「通知加密密钥尚未配置」（通知の暗号化キーが設定されていません）と表示される**：`ecoku.env` に `ECOKU_NOTIFICATION_ENCRYPTION_KEY` を設定してから、コンテナを作り直してください。[Docker デプロイ](./docker#env)を参照してください。

**テストメールがタイムアウトする**：ほとんどの場合、サーバーの SMTP 送信ポートがブロックされています。まずサーバー上で `nc -vz smtp.example.com 465` を実行して接続できることを確認し、次にポートと暗号化方式が合っているか（465 は SSL/TLS、587 は STARTTLS）を確認してください。
