# Twikoo からの移行

`import-twikoo` コマンドは、Twikoo からエクスポートしたコメントを 1 つの Ecoku サイトにインポートします。インポートは 1 回しかできません。対象のサイトは登録済みで、しかも**コメントが 1 件もない**（削除済みのものも含む）必要があります。そのため、新しいサイトを公開して誰かがコメントする前に済ませてください。

## インポートされるもの

| Twikoo のフィールド | インポート後 |
| --- | --- |
| `_id` / `id`、`pid`、`rid` | 返信関係を再構築します。直接の親コメントを優先して使います。エクスポートファイルに直接の親コメントがない場合は、`rid` が指すルートコメントの下に付けます。どちらも見つからない、親コメントが別のページにある、循環している場合は、そのコメントをルートコメントにし、「親レコードの欠落」（缺失父记录）として数えます。 |
| `url` | パス部分をページキーとして使い、クエリーパラメーターと `#` フラグメントを取り除きます。 |
| `comment` | HTML を純テキストに変換します。`<br>` とブロック要素は改行に、画像は alt テキストまたは `[图片]`（画像）に変わり、`<script>` と `<style>` は捨てられます。Markdown は解釈しません。 |
| `nick` | ニックネーム。空の場合は「访客」（訪問者）になります。 |
| `mail` | 非公開のメールアドレス。以後の返信通知に使います。254 文字を超える場合はインポートしません。 |
| `link` | 訪問者の URL。`http`/`https` のアドレスだけを残します。スキームのないアドレス（`example.com` など）には `https://` を補います。 |
| `created` / `updated` | 作成日時と更新日時。 |

IP、User-Agent、アバター、いいね、Twikoo のユーザー ID、エクスポートファイル内のブロガーの印はインポートしません。

インポートしたコメントはそのまま公開され、インポート中に通知は一切送られません。

**ブロガーの印**は、その時点での対象サイトのブロガーのニックネームとメールアドレスをもとに補完されます。ニックネームが完全に一致し、メールアドレスが一致する（大文字と小文字を区別しない）コメントがブロガーのコメントとして扱われます。必要であれば、インポートの前に管理画面でブロガー情報を設定しておいてください。

## 1. 準備

1. 管理画面で[対象のサイトを登録](./admin#sites)します。ブロガーの印を補完する場合は、ブロガーのニックネームとメールアドレスの両方を設定する必要があります。
2. Twikoo からコメントをエクスポートし、JSON 配列のファイル（上限 64 MiB）を用意します。
3. [バックアップと復元](./backup#cold-backup)の手順でコールドバックアップを 1 回取ります。バックアップスクリプトは最後にサービスを起動しますが、次の手順でもう一度停止します。

エクスポートしたファイルを `data/` ディレクトリにコピーし、コンテナのユーザーが読めるようにします（`/path/to/twikoo.json` は実際のパスに置き換えてください。元のファイルはそのまま残ります）。

```bash
cd ~/Ecoku
sudo docker compose down
sudo install -o 10001 -g 10001 -m 600 /path/to/twikoo.json data/twikoo.json
```

## 2. 事前チェック

`blog` を対象のサイト ID に置き換え、まず `--dry-run` を付けて実行します。

```bash
sudo docker compose run --rm --no-deps ecoku \
  import-twikoo --site=blog --file=/data/twikoo.json --dry-run
```

事前チェックはインポートを最後まで実行してからロールバックするので、コメントは保存されません。出力は次のようになります。

```text
Twikoo 导入预检通过：评论=128 根评论=90 回复=38 页面=24 邮箱=110 网站=45 缺失父记录=0
```

（Twikoo インポートの事前チェック成功：コメント、ルートコメント、返信、ページ、メールアドレス、Web サイト、親レコードの欠落の件数です。）

これらの数が Twikoo 側の状況と合っているか確認してください。「親レコードの欠落」（缺失父记录）が 0 でない場合、一部の返信がルートコメントになることを意味します。スキップされるわけではありません。

JSON の形式が誤っている、エクスポートが空の配列である、ID が重複している、本文が 10000 文字を超えている、ニックネームが 80 文字を超えている、ページキーが空または 512 文字を超えている、対象サイトが存在しない、またはすでにコメントがある場合、コマンドはエラーで終了し、何も変更しません。

::: info
事前チェックではコメントを保存しませんが、コマンドの起動時にデータベースは開かれます。データベースのバージョンが古い場合は先にマイグレーションが実行されるので、完全な読み取り専用の操作ではありません。
:::

## 3. 本番のインポート

事前チェックの結果とバックアップに問題がないことを確認したら、`--dry-run` を外してもう一度実行します。インポートは 1 つのトランザクションで行われ、どれか 1 件でもエラーになると全体がロールバックされます。成功したら一時コピーを削除し、サービスを起動します。

```bash
(
set -eu
cd ~/Ecoku
sudo docker compose run --rm --no-deps ecoku \
  import-twikoo --site=blog --file=/data/twikoo.json
sudo rm -- data/twikoo.json
sudo docker compose up -d
)
```

いくつかの記事を開いて、過去のコメントと返信関係が正しく表示されることを確認してください。元のエクスポートファイルとバックアップは、自分の運用に合わせて保管または削除してください。

## ページキーを一致させる

インポート時のページキーは、Twikoo のレコードの `url` のパス（例：`/posts/hello-world/`）から取られます。パスに含まれる漢字などの非 ASCII 文字は、`/posts/%E4%BD%A0%E5%A5%BD/` のようにパーセントエンコードされた形で保存されます。

コメント欄を埋め込むとき、`data-page-key` がまったく同じ文字列を生成しないと、過去のコメントは対応する記事の下に表示されません。インポート後は管理画面のコメント詳細で各コメントのページキーを確認し、ブログのテンプレートが出力する値と比べてください。一致しない場合（末尾に `/` があるかどうか、エンコードされているかどうかなど）は、埋め込みコードを調整してください。インポート済みのデータは変更しないでください。
