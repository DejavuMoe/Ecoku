# Twikoo 過去データの移行

Ecoku には、Twikoo からエクスポートした JSON データを完全なデータ整合性で移行するための専用 CLI ツールが用意されています。

> [!IMPORTANT]
> **新規初期デプロイ時のみ実行可能**：
> Twikoo コメント取り込みコマンド（`import-twikoo`）は、**管理コンソールで登録済み、かつコメント数が 0 件の初期サイトに対してのみ実行を許可**します。
> 対象サイトに既に 1 件でもコメントが投稿されている場合、ツリー階層構造、外部キー参照制約、コメント ID の連続性を保護するため、システムは**インポートを厳格に拒否**します。

---

## 移行の前提条件と規約

1. **対象サイトが空であること**：Twikoo 取り込みは、**管理画面で作成済みかつコメント数が 0 件**のサイトにのみ実行可能です。既存コメントへの追加取り込みは禁止されています。
2. **コールドバックアップの実施**：実際の移行を実行する前に、必ずデータベースのコールドバックアップを完了してください。
3. **ドライラン（Dry-Run）のサポート**：データベースへの書き込みを行わずにデータ形式を事前解析・検証する `--dry-run` をサポートしています。
4. **単一トランザクションによる不可分実行**：移行プロセス全体は単一の SQLite トランザクション内で実行されます。1 件でも構文エラーや不整合が発生した場合は全体がロールバックされ、部分的なゴミデータは一切残りません。
5. **通知の完全無効化**：過去データの移行処理中、メールや Telegram 通知は**一切送信されません**。

---

## フィールドマッピングとサニタイズ規則

| Twikoo 元フィールド | Ecoku マッピングおよび変換ルール |
| :--- | :--- |
| `_id` / `rid` / `pid` | 親子コメントの階層関係（`parent_id`）を自動的に解析・再構築。 |
| `url` (ページ識別子) | 正規のサイト内相対パスに自動整形（プロトコル、ホスト、クエリパラメータ、ハッシュアンカーを除去）。 |
| `comment` (本文) | 過去の HTML / Markdown 本文を抽出し、安全なプレーンテキストに変換。すべてのタグインジェクションを除去。 |
| `nick` | コメント投稿者ニックネームにマッピング。 |
| `mail` | プライベートメールアドレスにマッピング（将来の返信通知のみに使用され、公開 API には一切露出しません）。 |
| `link` | 正当性を検証した上で、投稿者ウェブサイトにマッピング（安全な `http://` / `https://` リンクのみ保持）。 |
| `created` | 過去の投稿 UNIX タイムスタンプを正確に保持。 |
| `ip` / `ua` / `os` | **即座に破棄**。Ecoku のプライバシー境界に厳格に準拠。 |
| `is_blogger` | 取り込み完了後、対象サイトのブロガーニックネームおよびメールアドレスと照合し、ブロガーバッジフラグを自動補完。 |

## 移行手順の実践

### 1. ドライラン検証（Dry-Run）

Twikoo からエクスポートした JSON ファイルをホスト側に配置し（例: `~/Ecoku/data/twikoo.json`）、まず Dry-Run を実行して検証します：

```bash
cd ~/Ecoku

sudo docker compose run --rm --no-deps ecoku \
  import-twikoo \
  --site=blog \
  --file=/data/twikoo.json \
  --dry-run
```

コンソールに出力される解析統計情報（親コメント数、子返信数、スキップされた異常データ数など）を確認します。

### 2. 本番インポートの実行

ドライランで問題がないことを確認したら、本番の書き込みを実行します：

```bash
cd ~/Ecoku

sudo docker compose run --rm --no-deps ecoku \
  import-twikoo \
  --site=blog \
  --file=/data/twikoo.json
```

### 3. インポートファイルの削除とサービス起動

移行完了後、サーバーディスクから平文の過去 IP やメールアドレスを含む `twikoo.json` を直ちに削除し、サービスを起動します：

```bash
# 一時エクスポートファイルを安全に削除
rm -f ~/Ecoku/data/twikoo.json

# サービスの起動
sudo docker compose up -d
```
