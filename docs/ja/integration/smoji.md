# Smoji スタンプパック

Smoji を使うと、訪問者は純テキストのコメントにスタンプ画像を挿入できます。スタンプはテキストの記法としてコメント本文に保存され、表示するときにだけ画像になるので、コメント自体は純テキストのままです。

Ecoku はスタンプ画像を内蔵せず、プロキシもキャッシュもしません。`smoji.json` の一覧と画像を自分の静的サーバーまたは CDN でホストし、管理画面でサイトに一覧のアドレスを設定する必要があります。

## 仕組み

1. 訪問者が初めてコメント欄の「スタンプ」（表情）ボタンを押したとき、ブラウザが一覧を読み込みます（Cookie と Referer は付けません）。
2. スタンプを選ぶと、コメント欄に次のような記法が挿入されます。

   ```text
   ![smoji:赞](https://stickers.example.com/paopao/thumbsup.png)
   ```

3. 投稿時に、サーバーが各記法を確認します。サイトでスタンプパックが有効で、画像のアドレスが一覧と同じオリジンの場合にだけ保存を許可します。
4. コメントを表示するとき、同じ条件を満たす記法は画像として描画され、それ以外はすべて原文のまま表示されます。

サイトでスタンプパックを無効にすると、過去のコメントの記法は文字のまま表示され、画像は読み込まれなくなります。

::: warning プライバシー
スタンプ画像はそれをホストしているサーバーから訪問者のブラウザに直接送られるため、そのサーバーは訪問者の IP アドレスを知ることができます。
:::

## 有効にする

管理画面の「サイト管理」（站点管理）でサイトを編集し、「スタンプパックを有効にする」（启用表情包）にチェックを入れ、一覧のアドレスを入力して保存します。

- 一覧のアドレスは HTTPS でなければなりません。HTTP を使えるのは、ローカル開発用の `localhost`、`127.0.0.1` などのループバックアドレスだけです。
- アドレスにはユーザー名とパスワード、`?` のクエリーパラメーター、`#` のフラグメントを含められません。
- 一覧とコメントのページが別のドメインにある場合、一覧をホストするサーバーは、コメントのページのオリジンからのクロスオリジンリクエスト（CORS）を許可する必要があります。

## 一覧の形式

```json
{
  "version": 1,
  "packs": [
    {
      "id": "paopao",
      "label": "泡泡",
      "items": [
        { "id": "smile", "label": "微笑", "src": "https://stickers.example.com/paopao/smile.png" },
        { "id": "thumbsup", "label": "赞", "src": "thumbsup.png" }
      ]
    }
  ]
}
```

| フィールド | ルール |
| --- | --- |
| `version` | `1` 固定。 |
| `base` | 任意。後述を参照してください。 |
| `packs` | グループのリスト。1～64 個。 |
| `packs[].id` | グループ ID。英字または数字で始まり、英字、数字、`.`、`_`、`-` を使えます。最大 64 文字で、重複できません。 |
| `packs[].label` | グループ名。ピッカーのタブに表示されます。ルールは `items[].label` と同じです。 |
| `packs[].items` | スタンプのリスト。1 グループあたり 1～600 個、一覧全体で合計 6000 個以下。 |
| `items[].id` | スタンプ ID。ルールはグループ ID と同じで、グループ内で重複できません。 |
| `items[].label` | スタンプ名。前後の空白を除いて 1～40 文字で、`]` と改行は含められません。コメントの記法に書き込まれ、画像の代替テキストにも使われます。 |
| `items[].src` | 画像のアドレス。完全なアドレスでも、一覧からの相対パスでもかまいません。 |

一覧全体の要件：

- **各オブジェクトに含められるのは上に挙げたフィールドだけ**で、それ以外のフィールドがあると拒否されます。
- すべての画像アドレスは、解決後に一覧と**同じオリジン**（スキーム、ドメイン、ポートがすべて同じ）でなければならず、ユーザー名とパスワード、`?`、`#` は含められません。
- ファイルは 1 MiB 以下で、レスポンスの `Content-Type` は `application/json` または `+json` で終わるものとし、8 秒以内にダウンロードが終わる必要があります。

## 簡略な書き方：base {#base}

スタンプが多い場合は、`src` を 1 つずつ書く代わりに `base` テンプレートを使えます。

```json
{
  "version": 1,
  "base": "https://stickers.example.com/smoji/{pack}/{id}.webp",
  "packs": [
    {
      "id": "douyin",
      "label": "抖音",
      "items": [
        { "id": "smile", "label": "微笑" },
        { "id": "cool", "label": "酷", "src": "https://stickers.example.com/smoji/extra/cool.png" }
      ]
    }
  ]
}
```

- `base` には `{pack}` と `{id}` の両方を含める必要があり、それぞれグループ ID とスタンプ ID に置き換えられます。`base` 自体も一覧と同じオリジンでなければなりません。
- `src` のないスタンプはテンプレートで生成したアドレスを使い、`src` を書いたスタンプは `src` が優先されます。
- 展開した結果は完全なアドレスのままで、コメントに保存される記法の形式は変わりません。

`base` は v0.2.1 から対応しています。

## スタンプ素材を更新する

コメントに保存されるのは**完全な画像アドレス**です。素材を更新するときは次の点に注意してください。

- 古い画像のアドレスを残すか、元のパスに互換用のコピーを置いてください。一覧を差し替えるだけでは、過去のコメントですでに表示できなくなった画像は直りません。
- スタンプをホストするドメインを変えないでください。変えると、古い記法と新しい一覧が同じオリジンでなくなり、すべて文字として表示されます。
- 本番用の一覧に `localhost` のアドレスを含めないでください。素材ツールでエクスポートするときは、リソースのアドレスを自分の CDN（例：`https://stickers.example.com/smoji/`）に設定してください。

## 記法の形式

```text
![smoji:名前](画像URL)
```

画像アドレス内の `(` と `)` は `%28` と `%29` にエンコードされます。公開 API の `formConfig.smoji` は、サイトで有効かどうかと一覧のアドレスを返します。独自のフロントエンドはこれをもとに、上記と同じルールで独自のピッカーと描画を実装できます。
