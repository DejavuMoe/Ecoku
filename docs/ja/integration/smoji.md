# Smoji スタンプパック

::: info v0.3.0 以降の画像オリジン設定
「图片来源」（画像オリジン）で一覧と画像を別々にホストできます。v0.2.9 以前は同一オリジンが必要です。既存サイトの更新後も、既定では同一オリジンの規則を維持します。
:::

[Smoji](https://github.com/DejavuMoe/Smoji) は、スタンプのギャラリーと一覧のエクスポート機能を提供しています。[Smoji ワークベンチ](https://smoji.zsh.moe/) で個々のスタンプをコピーしたり、カテゴリやカスタムグループを選び、コメント欄のピッカーで使う一覧をエクスポートしたりできます。

Ecoku はスタンプをプレーンテキストの記法として保存し、コメントを表示するときに画像として描画します。Ecoku サーバーはスタンプ素材を内蔵せず、プロキシやキャッシュも行いません。

## Smoji をそのまま使う {#quick-start}

Smoji の既存のギャラリーを使う場合、素材を自分でダウンロードしたりホストしたりする必要はありません。

1. 管理画面の「站点」（サイト）でサイトを編集し、「表情包」（スタンプパック）で「启用」（有効）を選びます。
2. 「Smoji 清单」（Smoji 一覧）に公開一覧の URL を入力して保存します。

   ```text
   https://s3-cdn.zsh.moe/smoji/smoji.json
   ```

3. コメントページで「表情」（スタンプ）を押して画像を選びます。[Smoji ワークベンチ](https://smoji.zsh.moe/) で個々のスタンプの詳細を開き、**Markdown** 形式をコピーしてコメント欄に貼り付けることもできます。

   ```text
   ![smoji:挠脸](https://s3-cdn.zsh.moe/smoji/aodamiao/iclpknnbbcne.webp)
   ```

4. 「预览」（プレビュー）で画像を確認してから投稿します。記法を直接貼り付ける場合、先にスタンプピッカーを開く必要はありません。

`![smoji:…](…)` を含む Markdown 形式を選んでください。画像 URL 単体、HTML、BBCode は Ecoku のスタンプとして表示されません。通常の Markdown 画像にも対応していません。

コピーした画像もサイトのオリジン制限を満たす必要があります。現在の検証対象は画像のオリジンと記法の形式であり、ピッカーの一覧に含まれる画像である必要はありません。「表情包」を無効にすると、過去の記法は文字のまま表示され、新たなスタンプ記法を含む投稿は拒否されます。

## スタンプを選んで一覧をエクスポートする {#custom-manifest}

ピッカーに一部のスタンプだけを表示したい場合：

1. [Smoji ワークベンチ](https://smoji.zsh.moe/) の「按分类导出」（カテゴリ別エクスポート）でカテゴリを選ぶか、「自选分组」（カスタムグループ）でグループを作ってスタンプを追加します。
2. **Smoji** 形式（v1）を選び、「导出」（エクスポート）で `smoji-YYYYMMDD.json` をダウンロードします。「分组备份」（グループのバックアップ）はワークベンチ用のバックアップであり、Ecoku の一覧としては使えません。
3. エクスポートしたファイルを、公開アクセスできる HTTPS の静的 URL で配信します。`smoji.json` に改名しても、日付の接尾辞を残してもかまいません。管理画面には実際の URL を入力します。ホストする前に[一覧と画像のオリジン要件](#hosting)を確認してください。

**エクスポートされるのはローカルの JSON ファイルです。画像は含まれず、自動アップロードや専用のホスティング URL の発行も行われません。** カスタムグループと選択状態は現在のブラウザに保存されます。選択を変更したら、再度エクスポートして自分でホストしているファイルを置き換えてください。

例えば、カスタムグループ `favorites` に `aodamiao` の画像を 2 枚含めると、次のようになります。

```json
{
  "version": 1,
  "base": "https://s3-cdn.zsh.moe/smoji/{pack}/{id}.webp",
  "packs": [
    {
      "id": "favorites",
      "label": "常用",
      "items": [
        {
          "id": "iclpknnbbcne",
          "label": "挠脸",
          "src": "https://s3-cdn.zsh.moe/smoji/aodamiao/iclpknnbbcne.webp"
        },
        {
          "id": "lhbidblgecnj",
          "label": "坏笑",
          "src": "https://s3-cdn.zsh.moe/smoji/aodamiao/lhbidblgecnj.webp"
        }
      ]
    }
  ]
}
```

これらの `src` は残してください。画像の実際の場所を指し、`base` より優先されます。削除するとテンプレートは `/smoji/favorites/…` を生成しますが、画像は実際には `/smoji/aodamiao/…` にあります。

## 一覧と画像をホストする {#hosting}

一覧と画像は別々にホストできます。上の JSON をそのまま `https://example.com/smoji.json` に置き、管理画面の「站点」（サイト）の「表情包」（スタンプパック）を設定します。

| フィールド | 入力内容 |
| --- | --- |
| 表情包（スタンプパック） | 启用（有効） |
| Smoji 清单（Smoji 一覧） | `https://example.com/smoji.json` |
| 图片来源（画像オリジン） | `https://s3-cdn.zsh.moe` |

保存後、ブラウザは `example.com` から一覧、`s3-cdn.zsh.moe` から画像を読み込みます。画像の移動やエクスポートした JSON の変更は不要です。

「图片来源」は任意の単一オリジンです。スキーム、ホスト名、任意のポートだけを指定し、パス、認証情報、クエリー、フラグメント、ワイルドカードは含めません。本番は HTTPS、開発用ループバックアドレスは HTTP も使えます。空欄なら一覧のオリジンを使うため既存サイトは変更不要です。指定した場合はそのオリジンのみを許可し、一覧のオリジンが追加で許可されることはありません。

| 一覧の場所 | 画像の場所 | 結果 |
| --- | --- | --- |
| Smoji 公開 CDN | 同じ CDN | 公開一覧とコピーした記法をそのまま使えます。 |
| 自分のウェブサイト | Smoji 公開 CDN | 「图片来源」に `https://s3-cdn.zsh.moe` を指定します。 |
| 自分の静的サーバーまたは CDN | 一覧と同じオリジン | 画像もホストし、画像 URL を更新します。 |

画像オリジンは管理者が明示的に保存します。リモート一覧の `base` や `src` が信頼するオリジンを追加することはできません。相対 URL は一覧 URL を基準に解決されるため、別々にホストするときはエクスポートされた絶対 URL を維持してください。画像も自分でホストする場合、移動先で実際に画像を配信してから `base` とすべての絶対 `src` を更新します。

ホスティングには次の条件もあります。

- 一覧 URL は HTTPS とし、認証情報、`?` のクエリーパラメーター、`#` のフラグメントを含めないでください。HTTP を使えるのは、ローカル開発用の `localhost`、`127.0.0.1` などのループバックアドレスだけです。
- 一覧と**コメントを表示するページ**のオリジンが異なる場合、一覧サーバーでそのページからの CORS リクエストを許可してください。認証情報を使わない公開の静的一覧には `Access-Control-Allow-Origin: *` を使えます。Ecoku の「允许来源」（許可するオリジン）を変更しても静的サーバーの CORS 設定の代わりにはなりません。
- JSON ファイルそのものを返し、`Content-Type` は `application/json` または `+json` で終わるメディアタイプにしてください。ダウンロード案内、ログインページ、SPA の HTML は使えません。ファイルは 1 MiB 以下で、8 秒以内にダウンロードが完了する必要があります。
- ウェブサイトで CSP を設定している場合、`connect-src` で一覧のオリジン、`img-src` で画像のオリジンを許可してください。CORS と CSP のどちらも Ecoku の画像オリジン検証を変更するものではありません。

## 読み込みと表示 {#how-it-works}

1. 訪問者が初めてスタンプピッカーを開くと、ブラウザは Cookie と Referer を付けずに一覧を直接取得します。
2. ブラウザは一覧を検証し、`base` と `src` を解決して、その画像 URL からピッカー用の画像を読み込みます。画像を選ぶと、完全な URL がコメントの記法に書き込まれます。
3. 投稿時、Ecoku サーバーはサイトの有効設定、記法の形式、画像のオリジンを検証します。サーバーは一覧や画像をダウンロードしません。
4. プレビュー、公開コメント、管理画面のコメントは、一覧を先にダウンロードせず、サイトの設定に従って有効な記法を描画します。画像は Ecoku サーバーを経由せず、素材のホストから直接読み込まれます。メールも同じ画像オリジン規則を使い、Telegram では文字ラベルとして表示します。

一覧の読み込み失敗はピッカーに影響しますが、保存済みでオリジン要件を満たすスタンプを自動的に無効にするものではありません。画像ファイルには引き続きアクセスできる必要があります。

::: warning プライバシー
一覧と画像は素材のホストから訪問者のブラウザへ直接送られ、そのホストは訪問者の IP アドレスを知ることができます。Smoji 公開 CDN を使う場合、リクエストはその CDN に送られます。画像リクエストには `no-referrer` が設定されますが、訪問者の IP アドレスは隠れません。
:::

## 一覧の形式 {#manifest-format}

| フィールド | ルール |
| --- | --- |
| `version` | `1` 固定。 |
| `base` | 任意。後述を参照してください。 |
| `packs` | グループのリスト。1～64 個。 |
| `packs[].id` | グループ ID。英字または数字で始まり、英字、数字、`.`、`_`、`-` を使えます。最大 64 文字で、重複できません。 |
| `packs[].label` | グループ名。ピッカーのタブに表示されます。ルールは `items[].label` と同じです。 |
| `packs[].items` | スタンプのリスト。1 グループあたり 1～600 個、一覧全体で合計 6000 個以下。 |
| `items[].id` | スタンプ ID。ルールはグループ ID と同じで、グループ内で重複できません。 |
| `items[].label` | スタンプ名。前後の空白を除いて 1～40 文字で、`]` や改行などの制御文字は含められません。コメントの記法に書き込まれ、画像の代替テキストにも使われます。 |
| `items[].src` | 画像のアドレス。完全なアドレスでも、一覧からの相対パスでもかまいません。 |

一覧全体の要件：

- **各オブジェクトに含められるのは上に挙げたフィールドだけ**で、それ以外のフィールドがあると拒否されます。
- 画像は解決後に、指定した画像オリジンと**同じオリジン**（スキーム、ホスト名、実効ポートが一致）でなければなりません。認証情報、`?`、`#` は禁止です。画像オリジンが空欄なら一覧のオリジンを使います。
- ファイルサイズとレスポンスの要件は[ホスティング](#hosting)を参照してください。

## 簡略な書き方：base {#base}

スタンプが多い場合は、`src` を 1 つずつ書く代わりに `base` テンプレートを使えます。

```json
{
  "version": 1,
  "base": "https://stickers.example.com/smoji/{pack}/{id}.webp",
  "packs": [
    {
      "id": "douyin",
      "label": "抖音",
      "items": [
        { "id": "smile", "label": "微笑" },
        { "id": "cool", "label": "酷", "src": "https://stickers.example.com/smoji/extra/cool.png" }
      ]
    }
  ]
}
```

- `base` は `{pack}` と `{id}` の両方を含み、グループ ID とスタンプ ID に置き換えられます。展開後も画像オリジン設定に従う必要があります。
- `src` のないスタンプはテンプレートで生成したアドレスを使い、`src` を書いたスタンプは `src` が優先されます。
- 展開した結果は完全なアドレスのままで、コメントに保存される記法の形式は変わりません。

`base` は v0.2.1 から対応しています。

## スタンプ素材を更新する {#updates}

コメントに保存されるのは**完全な画像アドレス**です。素材を更新するときは次の点に注意してください。

- 古い画像のアドレスを残すか、元のパスに互換用のコピーを置いてください。一覧を差し替えるだけでは、過去のコメントですでに表示できなくなった画像は直りません。
- 過去の画像も設定した画像オリジンに一致させてください。明示した場合、一覧を移動しても画像の信頼範囲は変わりません。空欄の場合、一覧のオリジンを変更すると旧オリジンの記法は文字になります。既存コメントは自動では書き換えられません。
- 自選の一覧からスタンプを除くと、ピッカーからだけ削除されます。過去のコメントの記法は削除されず、同じオリジンの画像記法を直接投稿することも禁止されません。
- 公開 CDN の画像が継続して使えるかどうかは素材のホスト側に依存します。自分で素材を移す場合は、`base` と明示的な `src` の両方を確認し、本番の一覧にローカル開発用のアドレスを含めないでください。

## 記法の形式 {#markers}

```text
![smoji:名称](图片地址)
```

画像アドレス内の `(` と `)` は `%28` と `%29` にエンコードされます。公開 API の `formConfig.smoji` は `enabled`、`manifestUrl`、任意の `imageOrigin` を返します。独自のフロントエンドはこれをもとに、上記と同じルールで独自のピッカーと描画を実装できます。
