# カスタムスタイル

コメント欄のスタイルには 3 つの使い方があります。変更の度合いが小さい順に並べると次のとおりです。

| 方式 | やり方 | 向いている場合 |
| --- | --- | --- |
| デフォルトのスタイル + 変数 | `data-css-url` を設定せず、ブログの CSS で `--ecoku-*` 変数を上書きします | ほとんどのブログ。色、角丸、文字サイズを調整したいだけの場合 |
| 構造スタイル | `data-css-url` で `/client/ecoku.unstyled.css` を指定します | レイアウトは残し、色と装飾はすべて自分で書きたい場合 |
| 完全なカスタマイズ | `data-css-url="none"` | すべてのスタイルをブログ側で用意する場合 |

スタイルが影響するのはコメント欄だけで、管理画面とは関係ありません。コメント欄のフォントはブログのページから継承します。

## 変数でデフォルトのスタイルを調整する

ブログの CSS で、`.ecoku-comments` に同じ名前の変数を書くだけです。

```css
.ecoku-comments {
  --ecoku-accent: #a8412c;
  --ecoku-radius: 8px;
  --ecoku-font-size: 16px;
}
```

デフォルト値は詳細度 0 の `:where(.ecoku-comments)` で宣言されているので、自分で書いた `.ecoku-comments` のルールはどれも有効になります。`!important` は不要で、スタイルシートの読み込み順にも左右されません。

### ライトモードとダークモード

`data-theme` で、コメント欄が配色をどう選ぶかが決まります。

- **`auto`（デフォルト）**：コメント欄はブログのページの `color-scheme` を継承します。色の変数は、ブログで定義された同じ名前の変数を優先して読み取ります（下表の「デフォルト値」列にある `var(--theme, …)` など）。そのため、ブログが `light-dark()` やクラス名の切り替えでこれらの変数を変えると、コメント欄も一緒に変わります。ブログでこれらの変数が定義されていない場合は、システムのライト / ダークの設定に従って内蔵の配色を使います。
- **`light` / `dark`**：内蔵のライトまたはダークの配色に固定し、ブログの色の変数は読み取りません。

色の変数のフォールバック名は PaperMod テーマと同じなので、PaperMod では通常何も設定する必要はありません。

## 変数一覧 {#variables}

| 変数 | デフォルト値 | 用途 |
| --- | --- | --- |
| `--ecoku-theme` | `var(--theme, #f7f4ee)` | メインボタンの文字、Cap のチェックボックスの地色 |
| `--ecoku-entry` | `var(--entry, #fbf9f5)` | 投稿カード、並び替えメニュー、スタンプパネル、エラーメッセージの地色 |
| `--ecoku-primary` | `var(--primary, #1e1c19)` | 見出し、ニックネーム、入力文字、メインボタンの地色、フォーカス時の下線 |
| `--ecoku-secondary` | `var(--secondary, #6b655b)` | 日時、文字数、項目のラベル、文字だけのボタン |
| `--ecoku-content` | `var(--content, #35312b)` | コメント本文と本文の入力欄 |
| `--ecoku-border` | `var(--border, #cbc3b5)` | 訪問者情報の項目の下線、補助ボタンの枠線、「返信」（回复）の下線 |
| `--ecoku-border-soft` | `var(--border-soft, rgb(30 28 25 / 0.12))` | カードの枠線、スレッドの区切り線、返信のガイド線 |
| `--ecoku-surface-muted` | `var(--surface-muted, #efebe3)` | スタンプのマスにホバーしたときの地色 |
| `--ecoku-code-bg` | `var(--code-bg, #ece7de)` | デフォルトのスタイルでは未使用。カスタムスタイル用に残しています |
| `--ecoku-accent` | 朱色 `#c8553a` と `--ecoku-primary` の混色 | ブロガーバッジ、リンクのホバー |
| `--ecoku-danger` | `var(--ecoku-accent)` | フォームのエラーメッセージと無効な項目 |
| `--ecoku-focus` | `--ecoku-primary` の 40% の透明度 | キーボードフォーカスの枠。`transparent` にすると非表示になります |
| `--ecoku-radius` | `6px` | カード、メニュー、パネル、ボタンの角丸 |
| `--ecoku-radius-sm` | `3px` | メニュー項目、スタンプのマス、チェックボックスの角丸 |
| `--ecoku-shadow` | 淡い 2 層の影 | 並び替えメニューとスタンプパネル |
| `--ecoku-font-mono` | Maple Mono。なければシステムの等幅フォント | 日時、`[+]` / `[-]`、文字数、ページ番号 |
| `--ecoku-font-size` | `15px` | 本文と入力欄 |
| `--ecoku-font-size-small` | `13px` | メタ情報、ラベル、ボタン |
| `--ecoku-font-size-title` | `22px`（狭い画面では `20px`） | 「N 件のコメント」（N 条评论）の見出し |

等幅フォントは、ページですでに読み込まれている Maple Mono だけを使い、Ecoku がフォントをダウンロードすることはありません。ない場合は `ui-monospace`、`SFMono-Regular`、`Menlo`、`Consolas` の順にフォールバックします。

タッチデバイスでは、iOS がフォーカス時にページを拡大しないよう、入力欄の文字サイズを 16px 以上にしています。

## 構造スタイル

`/client/ecoku.unstyled.css` にはレイアウト（グリッド、余白、スタンプパネル、検証ウィジェットのサイズ、折りたたみボタンの幅など）だけが含まれ、色、枠線、背景は一切なく、`--ecoku-*` 変数も使いません。

```html
<section
  data-ecoku-comments
  data-css-url="https://ecoku.example.com/client/ecoku.unstyled.css"
  ...
>
```

HTML のローダーを使う場合は、このスタイルシートの `<link>` がページに自動で挿入されます。SDK を直接使う場合は自分で読み込む必要があります。[SDK · スタイル](./sdk#styles)を参照してください。

## 完全なカスタマイズ

`data-css-url="none"` の場合、Ecoku はスタイルを注入も読み込みもしません。コメント欄のルート要素は `.ecoku-comments` で、すべての要素に `ecoku-` という接頭辞のクラス名が付いています。まず `ecoku.unstyled.css` を開いて構造と扱う必要のある状態（折りたたみ、非表示、スタンプパネルなど）を把握し、それをもとに書き始めるとよいでしょう。

## レイアウトの詳細

カスタムスタイルを書くときは、デフォルトのスタイルの次の決まりを参考にできます。

- 返信のインデント：1 階層ごとに 22px、狭い画面（≤ 620px）では 14px、最大 3 階層まで。現在の階層は、要素の `--ecoku-depth` 変数（0～3）で渡されます。
- 折りたたみボタン `[+]` / `[-]` は `3ch` の固定幅で、切り替えても同じ行の内容は動きません。
- ニックネーム、日時、折りたたみボタン、「返信」（回复）は同じ行にあり、文字のベースラインで揃えられています。
- Turnstile ウィジェットの幅は 300px 以下、Cap ウィジェットは 260×58px のままです。
