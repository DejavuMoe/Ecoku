# Smoji 表情包

::: info v0.3.0 起支持图片来源
「图片来源」允许清单与图片分别托管。v0.2.9 及更早版本仍要求二者同源；旧站点升级后默认保留同源规则。
:::

[Smoji](https://github.com/DejavuMoe/Smoji) 提供表情图库和清单导出工具。你可以在 [Smoji 工作台](https://smoji.zsh.moe/) 复制单张表情，也可以挑选分类或自选分组，导出供评论区选择器使用的清单。

Ecoku 把表情保存为纯文本标记，显示评论时才渲染成图片。Ecoku 服务端不内置、代理或缓存表情素材。

## 直接使用 Smoji {#quick-start}

使用 Smoji 现有图库时，不需要自己下载或托管素材：

1. 在后台「站点」中编辑站点，在「表情包」选择「启用」。
2. 在「Smoji 清单」填写公共清单地址，保存：

   ```text
   https://s3-cdn.zsh.moe/smoji/smoji.json
   ```

3. 打开评论页，点击「表情」选择图片；也可以去 [Smoji 工作台](https://smoji.zsh.moe/) 打开单张表情的详情，复制 **Markdown** 格式，粘贴到评论框：

   ```text
   ![smoji:挠脸](https://s3-cdn.zsh.moe/smoji/aodamiao/iclpknnbbcne.webp)
   ```

4. 点击「预览」检查图片，再发布评论。直接粘贴标记不需要先打开「表情」选择器。

请选择带 `![smoji:…](…)` 的 Markdown 格式。单独的图片 URL、HTML 或 BBCode 不会变成 Ecoku 表情；普通 Markdown 图片也不受支持。

直接复制的图片也要符合站点的来源限制。当前校验的是图片来源与标记格式，不要求该图片出现在选择器清单里。关闭「表情包」后，历史标记按原文显示，新的表情标记提交会被拒绝。

## 挑选表情并导出清单 {#custom-manifest}

如果只想在选择器里展示部分表情：

1. 在 [Smoji 工作台](https://smoji.zsh.moe/) 使用「按分类导出」勾选分类，或使用「自选分组」建立自己的分组并加入表情。
2. 选择 **Smoji** 格式（v1），点击「导出」，下载 `smoji-YYYYMMDD.json`。「分组备份」是工作台的备份文件，不能作为 Ecoku 清单。
3. 将导出的文件发布到可公开访问的 HTTPS 静态地址。可以改名为 `smoji.json`，也可以保留日期后缀，后台填写实际 URL。托管前先核对[清单与图片的来源要求](#hosting)。

**导出得到的是本地 JSON 文件，不包含图片，也不会自动上传或生成专属托管 URL。** 自选分组和选择结果保存在当前浏览器；更新选择后，需要重新导出并替换自己托管的文件。

例如，自选分组 `favorites` 可以包含来自 `aodamiao` 的两张图片：

```json
{
  "version": 1,
  "base": "https://s3-cdn.zsh.moe/smoji/{pack}/{id}.webp",
  "packs": [
    {
      "id": "favorites",
      "label": "常用",
      "items": [
        {
          "id": "iclpknnbbcne",
          "label": "挠脸",
          "src": "https://s3-cdn.zsh.moe/smoji/aodamiao/iclpknnbbcne.webp"
        },
        {
          "id": "lhbidblgecnj",
          "label": "坏笑",
          "src": "https://s3-cdn.zsh.moe/smoji/aodamiao/lhbidblgecnj.webp"
        }
      ]
    }
  ]
}
```

保留这些 `src`：它们指向图片的实际位置，并优先于 `base`。如果删除 `src`，模板会拼出 `/smoji/favorites/…`，而图片实际在 `/smoji/aodamiao/…`。

## 清单与图片的托管 {#hosting}

清单和图片可以分别托管。把上面的 JSON 原样放到 `https://example.com/smoji.json` 后，在后台「站点」的「表情包」中填写：

| 字段 | 填写内容 |
| --- | --- |
| 表情包 | 启用 |
| Smoji 清单 | `https://example.com/smoji.json` |
| 图片来源 | `https://s3-cdn.zsh.moe` |

保存后，浏览器从 `example.com` 读取清单，从 `s3-cdn.zsh.moe` 加载图片。不需要搬移图片或修改导出的 JSON。

「图片来源」是选填的单个来源，只含协议、域名和可选端口，不含路径、用户名密码、查询参数或片段，也不支持通配符。生产环境使用 HTTPS，回环地址可用 HTTP 开发。留空时沿用清单来源，旧站点无需修改；填写后仅允许指定来源，不会同时额外放行清单来源。

| 清单位置 | 图片位置 | 结果 |
| --- | --- | --- |
| Smoji 公共 CDN | 同一个 CDN | 可直接使用公共清单和复制的表情标记。 |
| 自己的网站 | Smoji 公共 CDN | 将「图片来源」设为 `https://s3-cdn.zsh.moe`。 |
| 自己的静态服务器或 CDN | 与清单同源 | 可使用自选清单；需要一并托管图片并更新图片地址。 |

图片来源由管理员明确保存；远程清单里的 `base` 和 `src` 不能自行增加受信任来源。相对路径仍按清单 URL 解析；分开托管时保留导出的绝对地址。如果选择自己托管图片，要确保目标路径实际提供图片文件，再更新清单里的 `base` 和所有绝对 `src`。

托管时还需满足：

- 清单地址必须是 HTTPS，不能带用户名密码、`?` 查询参数或 `#` 片段。只有 `localhost`、`127.0.0.1` 等回环地址可以用 HTTP，供本地开发使用。
- 清单和**评论所在页面**不同源时，清单服务器需要允许该页面来源的 CORS 请求。公开、无凭据的静态清单可使用 `Access-Control-Allow-Origin: *`。在 Ecoku 后台修改「允许来源」不能替代静态服务器的 CORS 配置。
- 返回 JSON 文件本身，`Content-Type` 为 `application/json` 或以 `+json` 结尾；不要返回下载说明页、登录页或 SPA 的 HTML。文件不超过 1 MiB，并须在 8 秒内下载完成。
- 如果网站设置了 CSP，让 `connect-src` 允许清单来源，`img-src` 允许图片来源。CORS 和 CSP 都不会改变 Ecoku 的图片来源校验。

## 加载与显示 {#how-it-works}

1. 访客第一次打开「表情」选择器时，浏览器直接请求清单，不带 Cookie 和 Referer。
2. 浏览器校验清单，解析 `base` 和 `src`，再从图片地址加载选择器里的图片。选中后，将完整图片 URL 写入评论标记。
3. 提交时，Ecoku 服务端校验站点开关、标记格式和图片来源；服务端不会下载清单或图片。
4. 预览、公开评论和后台评论按站点配置渲染合规标记，不需要先下载清单。邮件通知也使用相同的来源规则，Telegram 显示文字标签。图片从资源主机直接加载，不经过 Ecoku 服务端。

清单加载失败影响选择器，不会让已保存且符合来源规则的表情自动失效。图片文件仍需可访问。

::: warning 隐私
清单和图片由资源主机直接发给访客浏览器，该主机能看到访客的 IP 地址。使用 Smoji 公共 CDN 时，请求会发往该 CDN；图片请求设置了 `no-referrer`，但这不会隐藏访客 IP。
:::

## 清单格式 {#manifest-format}

| 字段 | 规则 |
| --- | --- |
| `version` | 固定为 `1`。 |
| `base` | 可选，见下文。 |
| `packs` | 分组列表，1～64 个。 |
| `packs[].id` | 分组 ID，字母或数字开头，可含字母、数字、`.`、`_`、`-`，最多 64 个字符，不能重复。 |
| `packs[].label` | 分组名称，显示在选择器的标签页上。规则同 `items[].label`。 |
| `packs[].items` | 表情列表，每组 1～600 个；整份清单合计不超过 6000 个。 |
| `items[].id` | 表情 ID，规则同分组 ID，组内不能重复。 |
| `items[].label` | 表情名称，去掉首尾空格后 1～40 个字符，不能包含 `]` 和换行等控制字符。它会写进评论标记，也用作图片的替代文字。 |
| `items[].src` | 图片地址。可以是完整地址，也可以是相对于清单的路径。 |

清单的整体要求：

- **每个对象只能包含上面列出的字段**，多出任何字段都会被拒绝。
- 所有图片地址解析后必须与配置的图片来源**同源**（协议、域名、有效端口相同），不能带用户名密码、`?` 或 `#`。图片来源留空时使用清单来源。
- 文件大小与响应要求见[托管说明](#hosting)。

## 精简写法：base {#base}

表情较多时，可以用 `base` 模板代替逐个填写 `src`：

```json
{
  "version": 1,
  "base": "https://stickers.example.com/smoji/{pack}/{id}.webp",
  "packs": [
    {
      "id": "douyin",
      "label": "抖音",
      "items": [
        { "id": "smile", "label": "微笑" },
        { "id": "cool", "label": "酷", "src": "https://stickers.example.com/smoji/extra/cool.png" }
      ]
    }
  ]
}
```

- `base` 必须同时包含 `{pack}` 和 `{id}`，分别替换为分组 ID 和表情 ID；展开后也必须符合图片来源设置。
- 没有 `src` 的表情使用模板生成地址；写了 `src` 的以 `src` 为准。
- 展开后的结果仍是完整地址，评论中保存的标记格式不变。

`base` 从 v0.2.1 开始支持。

## 更新表情素材 {#updates}

评论中保存的是**完整的图片地址**。更新素材时请注意：

- 保留旧图片的地址，或在原路径上放置兼容副本。只替换清单不会修复历史评论中已经失效的图片。
- 保持历史图片符合已配置的图片来源。明确设置来源后，移动清单不会改变图片的信任范围；留空时，更换清单来源会使旧来源的标记显示为文字。历史评论不会自动改写。
- 从自选清单移除一张表情，只会从选择器中移除它，不会删除历史评论里的标记，也不会禁止同源图片标记直接提交。
- 使用公共 CDN 时，图片是否持续可用取决于素材托管方。自行迁移素材时，同时检查 `base` 和每个显式 `src`；生产清单不要引用本地开发地址。

## 标记格式 {#markers}

```text
![smoji:名称](图片地址)
```

图片地址中的 `(` 和 `)` 会被编码为 `%28` 和 `%29`。公开接口的 `formConfig.smoji` 返回 `enabled`、`manifestUrl` 和可选的 `imageOrigin`，自定义前端可以据此实现自己的选择器和渲染，规则与上文相同。
