# Smoji 表情包

Smoji 让访客在纯文本评论中插入表情图片。表情以一段文本标记保存在评论正文里，显示时才变成图片，评论本身仍然是纯文本。

Ecoku 不内置、不代理、不缓存任何表情图片。你需要把一份 `smoji.json` 清单和图片托管在自己的静态服务器或 CDN 上，再在后台为站点填写清单地址。

## 工作方式

1. 访客第一次点击评论框的「表情」按钮时，浏览器加载清单（不带 Cookie 和 Referer）。
2. 选中一个表情，评论框里插入一段标记：

   ```text
   ![smoji:赞](https://stickers.example.com/paopao/thumbsup.png)
   ```

3. 提交时，服务端检查每个标记：站点已启用表情包，且图片地址与清单同源，才允许保存。
4. 显示评论时，符合同样条件的标记渲染为图片；其他情况一律按原文显示。

站点关闭表情包后，历史评论中的标记会以文字原样显示，不再加载图片。

::: warning 隐私
表情图片由托管它的服务器直接发给访客的浏览器，这台服务器能看到访客的 IP 地址。
:::

## 启用

在后台「站点管理」中编辑站点，勾选「启用表情包」，填写清单地址，保存。

- 清单地址必须是 HTTPS。只有 `localhost`、`127.0.0.1` 等回环地址可以用 HTTP，供本地开发使用。
- 地址中不能包含用户名密码、`?` 查询参数或 `#` 片段。
- 清单和评论页不在同一个域名时，托管清单的服务器需要允许评论页来源的跨域请求（CORS）。

## 清单格式

```json
{
  "version": 1,
  "packs": [
    {
      "id": "paopao",
      "label": "泡泡",
      "items": [
        { "id": "smile", "label": "微笑", "src": "https://stickers.example.com/paopao/smile.png" },
        { "id": "thumbsup", "label": "赞", "src": "thumbsup.png" }
      ]
    }
  ]
}
```

| 字段 | 规则 |
| --- | --- |
| `version` | 固定为 `1`。 |
| `base` | 可选，见下文。 |
| `packs` | 分组列表，1～64 个。 |
| `packs[].id` | 分组 ID，字母或数字开头，可含字母、数字、`.`、`_`、`-`，最多 64 个字符，不能重复。 |
| `packs[].label` | 分组名称，显示在选择器的标签页上。规则同 `items[].label`。 |
| `packs[].items` | 表情列表，每组 1～600 个；整份清单合计不超过 6000 个。 |
| `items[].id` | 表情 ID，规则同分组 ID，组内不能重复。 |
| `items[].label` | 表情名称，去掉首尾空格后 1～40 个字符，不能包含 `]` 和换行等控制字符。它会写进评论标记，也用作图片的替代文字。 |
| `items[].src` | 图片地址。可以是完整地址，也可以是相对于清单的路径。 |

清单的整体要求：

- **每个对象只能包含上面列出的字段**，多出任何字段都会被拒绝。
- 所有图片地址解析后必须与清单**同源**（协议、域名、端口都相同），不能带用户名密码、`?` 或 `#`。
- 文件不超过 1 MiB，响应的 `Content-Type` 为 `application/json` 或以 `+json` 结尾，8 秒内下载完成。

## 精简写法：base {#base}

表情较多时，可以用 `base` 模板代替逐个填写 `src`：

```json
{
  "version": 1,
  "base": "https://stickers.example.com/smoji/{pack}/{id}.webp",
  "packs": [
    {
      "id": "douyin",
      "label": "抖音",
      "items": [
        { "id": "smile", "label": "微笑" },
        { "id": "cool", "label": "酷", "src": "https://stickers.example.com/smoji/extra/cool.png" }
      ]
    }
  ]
}
```

- `base` 必须同时包含 `{pack}` 和 `{id}`，分别替换为分组 ID 和表情 ID；它本身也必须与清单同源。
- 没有 `src` 的表情使用模板生成地址；写了 `src` 的以 `src` 为准。
- 展开后的结果仍是完整地址，评论中保存的标记格式不变。

`base` 从 v0.2.1 开始支持。

## 更新表情素材

评论中保存的是**完整的图片地址**。更新素材时请注意：

- 保留旧图片的地址，或在原路径上放置兼容副本。只替换清单不会修复历史评论中已经失效的图片。
- 不要更换托管表情的域名。换了之后，旧标记与新清单不再同源，会全部显示为文字。
- 生产清单中不要出现 `localhost` 地址。使用素材工具导出时，把资源地址设置为你的 CDN，例如 `https://stickers.example.com/smoji/`。

## 标记格式

```text
![smoji:名称](图片地址)
```

图片地址中的 `(` 和 `)` 会被编码为 `%28` 和 `%29`。公开接口的 `formConfig.smoji` 返回站点是否启用及清单地址，自定义前端可以据此实现自己的选择器和渲染，规则与上文相同。
