# v0.6.1

- Release date: 2026-11-19
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.6.1`
- npm SDK: `ecoku@0.6.1`

## Changes {#changes}

- Twikoo preflight and import reject exports containing spam comments and report the count. Replies with only an `rid` now attach to the corresponding root comment. HTTP(S) homepage URLs without a path now import correctly.
- The admin comment list reads counts, page data and reply flags in one SQLite snapshot. A single query counts published and deleted comments. The public comment list reads comment relationships row by row to reduce allocations on cold requests.
- Trusted proxy validation rejects IPv4-mapped ranges that cover all IPv4 addresses.

## Compatibility {#compatibility}

- The schema stays at v12. When upgrading from v0.6.0, keep your existing data and configuration mounts, container user and healthcheck probe. The SDK uses the same runtime code as 0.6.0.
- A range in `site.trusted_proxies` that maps to all IPv4 addresses will prevent startup. Use the IP address or a limited range of your actual trusted proxies before upgrading. See the [reverse proxy guide](../reverse-proxy#trusted-proxies).
- When upgrading from v0.5.7 or an earlier release, read the [distroless migration notes](../upgrade#distroless) and update the old Compose probe.

## Upgrade {#upgrade}

Follow the [upgrade steps](../upgrade#steps) to stop the service and take a cold backup. Set the image to `ghcr.io/dejavumoe/ecoku:v0.6.1`, then pull it and recreate the container. Confirm the container is `healthy` and check admin sign-in, existing comments and submission of a new comment.

## Rollback {#rollback}

Stop the service, set the image back to `ghcr.io/dejavumoe/ecoku:v0.6.0`, then pull it and recreate the container. Both releases use schema v12. Keep your existing database and healthcheck probe.
