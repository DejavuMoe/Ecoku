- Git tag: [v0.2.7](https://github.com/DejavuMoe/Ecoku/tree/v0.2.7)

## Changes

- Notification emails use the same paper-and-ink colours as the comment section and the admin console, with dark mode support. Text uses the system's own Chinese and Latin sans-serif fonts, so Chinese text no longer falls back to SimSun in Windows mail clients.
- Email subjects include the post title, such as "您在 [站点名称] 上有新评论：[文章标题]" (You have a new comment on [site name]: [post title]). New-reply and visitor-reply emails also show the post title and time. Times follow the container's `TZ` with the UTC offset instead of always using UTC.
- Smoji in emails appear as images or as `[表情：标签]` ([Smoji: label]) instead of raw markers.
- Telegram notifications add the publication time and show the replied-to comment as a quote. The body limit is now 1000 characters.
- After a comment is deleted, pending notifications are not sent, and Telegram messages already sent are rewritten to "这条评论已被删除，通知内容已移除。" (This comment was deleted and the notification content has been removed.). Emails already sent cannot be recalled. See [After a comment is deleted](../notifications#after-deletion).
- Deliveries are no longer retried when the mailbox is rejected or the Telegram chat is unavailable. Finished notification records are removed automatically after 30 days.
- The documentation was checked against the source, with several corrections to the API, CLI, backup and restore, and FAQ pages.

## Compatibility

- Schema v9 rebuilds the notification queue table `notification_outbox` in place, adding new statuses, an event type, a message ID column and an index. Comments, sites and settings are unchanged, and every queue record keeps its ID. Failed records that already used all 8 attempts are marked as given up.
- Config keys, environment variables, Compose mounts, the admin API, the comment section and the SDK are unchanged.
- Telegram messages sent before the upgrade have no recorded message ID and cannot be rewritten if their comment is deleted later.

## Historical upgrade notes {#upgrade}

This version is archived, with no installation or downgrade instructions. Restoring across schemas requires a complete cold backup matching the target version; changing an image alone is insufficient.
