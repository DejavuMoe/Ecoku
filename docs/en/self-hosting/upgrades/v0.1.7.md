# v0.1.7

2026-08-26. Schema remains v6.

## Changes

This release updates the local-development, CI, container-build, and documentation-site workflows. The toolchain is pinned to Node.js 24.19.0, Go 1.27.0, and pnpm 11.24.0; the runtime image remains Alpine 3.24.1. The application runtime contract is unchanged.

## Upgrade

There are no new environment variables, configuration keys, or Compose mounts. The container still runs as UID/GID `10001:10001`, and the `/data`, config, and log mount paths are unchanged, so an existing `v0.1.6` instance does not need a permission change.

Do not replace the whole Compose file. Keep its existing resource limits and mounts, and change only the exact image tag to `git.via.moe/dejavu/ecoku:v0.1.7`. If the old file lacks the `logging` block, add the current repository block.

From `v0.1.6`:

1. Stop the service and take a cold backup of `data/`, `app/config.yaml`, `app/logs/`, `ecoku.env`, and the current Compose file.
2. Change the exact image tag to `v0.1.7`.
3. Run:

```bash
sudo docker compose config --quiet
sudo docker compose pull
sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail=200 ecoku
curl --fail http://127.0.0.1:12123/api/health
```

To roll back, pin `v0.1.6` again. Both versions use schema v6, so the database usually does not need replacement; if startup or validation fails, restore the pre-upgrade backup.
