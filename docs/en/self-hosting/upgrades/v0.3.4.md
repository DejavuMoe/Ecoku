# v0.3.4

- Released: 2026-10-05
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.3.4`
- npm SDK: `ecoku@0.3.4`

## Changes {#changes}

- Fixed an intermittent missing CAPTCHA on the admin sign-in page: an unauthenticated session check could cancel the verification configuration request. Submission is disabled while verification loads. If loading fails, click “Retry”; the entered username and password are kept, and retrying does not sign you in automatically.
- Comment submissions that encounter a network interruption, timeout, invalid response or server error keep the draft and report that the outcome is unconfirmed. They no longer incorrectly claim that nothing was submitted, and are not retried automatically.
- Optional identity storage no longer delays the initial comment list or successful submission feedback. A late identity restore does not overwrite edits. Public list and submission requests avoid duplicate site configuration queries, and blogger passphrase comparisons reject candidates that fail existing rules before hashing.
- CI now checks Go vulnerabilities, audits JavaScript lockfile dependencies and tests SDK storage in a real browser. Known vulnerabilities in the documentation toolchain and transitive `brace-expansion` dependencies are fixed.

## Compatibility {#compatibility}

- There is no database migration; the schema stays at v12. Compose mounts, configuration keys and environment variables are unchanged.
- Origin checks, configuration reads, CAPTCHA verification and comment writes share an 8-second processing budget. The SDK request timeout remains 10 seconds. Slow verification services can exhaust that budget; see [Submit a comment](../../reference/api#submit-comment).
- An unconfirmed submission may already have been saved. Refresh the comment list before deciding whether to retry manually, to avoid duplicate posts.
- Saving an identity remains optional. It is still encrypted in IndexedDB for 7 days, with no new browser storage location.

## Upgrade {#upgrade}

1. Stop the service and [cold-back up](../backup#cold-backup) the database, `ecoku-secrets.json`, Compose and configuration files.
2. Follow the [upgrade steps](../upgrade#steps), set the image to `ghcr.io/dejavumoe/ecoku:v0.3.4`, then run `sudo docker compose pull && sudo docker compose up -d`.
3. Check container health. Sign out of the admin console and reopen the sign-in page to confirm verification loads and sign-in works, then check comment loading and submission.
4. After npm publication succeeds, update separately installed SDKs with `pnpm add --save-exact ecoku@0.3.4` and rebuild the website. The bundled SDK updates with the container image. If you host static files yourself, replace the loader, SDK and stylesheet together.

## Rollback {#rollback}

The schema is unchanged. Stop the service, set the image back to `ghcr.io/dejavumoe/ecoku:v0.3.3`, then pull and start it. No database restore is needed; comments and settings changed after the upgrade are kept. Separately installed npm SDKs can be pinned back to `ecoku@0.3.3` before rebuilding the website. Rolling back removes this release's sign-in and comment submission fixes.
