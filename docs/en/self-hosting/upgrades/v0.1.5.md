## Changes

- CAPTCHA becomes an instance-wide choice of three modes: off, Cloudflare Turnstile, or self-hosted Cap. It protects both comment submission and admin sign-in.
- The browser submits a one-time `captchaToken`.
- New command-line commands `captcha status` and `captcha disable` restore sign-in when the verification settings are broken. See [Command line](../../reference/cli#captcha-disable).
- The admin console's CSP adapts to the current verification mode. Cap requires allowing the instance origin, WebAssembly, and Blob workers.

## Compatibility

Schema v6 renames the old `turnstile_settings` table to `captcha_settings`, keeps the on/off switch and the keys, sets Turnstile as the default verification mode, and adds fields for Cap.

If you switch to Cap, allow the origins of the admin console and all comment sites in the Cap key.
