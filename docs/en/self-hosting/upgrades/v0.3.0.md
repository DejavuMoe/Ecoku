# v0.3.0

- Release date: 2026-10-03
- Schema: v10 → v11
- Image: `ghcr.io/dejavumoe/ecoku:v0.3.0`
- npm SDK: `ecoku@0.3.0`

## Changes {#changes}

- Smoji adds the optional 「图片来源」 (image origin) field. Host exported JSON yourself while loading images from a selected CDN. Comments, previews, admin views and email share this origin rule.
- GitHub Actions publishes dual-architecture GHCR images, the npm SDK and a GitHub Release with the SDK archive and checksums. SDK versions match project tags. Woodpecker now publishes documentation only; use GHCR for images.
- Complete YAML templates bring defaults, allowed values and examples together. Compose explicitly sets `TZ: Asia/Shanghai`. Documentation retains its layout with the admin paper-and-ink colors, consistent code highlighting and inline spacing, and corrected default search translations.

## Compatibility {#compatibility}

- The migration adds `smoji_image_origin` to the existing `sites` table, defaulting to an empty string. Accounts, sites, comments, queues and notification settings remain. There is no down migration.
- Sites without an image origin keep the manifest-origin restriction. Setting it allows only that single image origin. Remote JSON cannot expand the allowed origins.
- Existing Compose, YAML and administrator credentials remain valid. Do not regenerate passwords or keys. Instances on v0.2.8 or earlier should still follow [legacy configuration migration](../upgrade#legacy-config).
- Adding GHCR publication does not change existing deployments' image sources. npm and images publish separately; confirm the relevant job succeeded before downloading.

## Upgrade {#upgrade}

1. Stop the service and take a [cold backup](../backup#cold-backup) of the database, sibling `ecoku-secrets.json`, Compose and configuration. Include `ecoku.env` if still used.
2. Follow the [upgrade steps](../upgrade#steps), setting the image to `ghcr.io/dejavumoe/ecoku:v0.3.0`, then run `sudo docker compose pull && sudo docker compose up -d`.
3. Check health, administrator login, historical comments and notifications. Confirm schema v11 migration succeeded.
4. For separate Smoji hosting, follow [manifest and image hosting](../../integration/smoji#hosting), set 「图片来源」 and test the picker, preview and rendered comments.
5. Websites using the npm SDK should install `ecoku@0.3.0` after npm publication succeeds and rebuild. Instance-hosted UMD integrations continue updating with the container.

## Rollback {#rollback}

v0.3.0 is the first public deployment release; no earlier public image is available for production rollback. Stop the service and follow [restore instructions](../backup#restore) using one complete backup and a supported version matching its schema. The internal v0.2.9 program cannot open schema v11; changing only the image tag is insufficient. Restoring loses comments and settings added after the backup.
