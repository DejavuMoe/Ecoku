## Changes {#changes}

- New deployments no longer supply a password hash or two keys. The first start creates `admin`, a random temporary password, and a persistent key file. The password appears in the startup log and must be replaced after sign-in; keeping the username `admin` is optional.
- Adds a persistent administrator account table and `admin reset-password`. A setup session can only inspect its session, sign out, or complete setup; completion opens the existing site creation flow.
- Fixes the admin favicon, Chrome field borders, notification validation layout, parent-comment sticker labels, deletion scrolling, jump highlights, repeated notifications, and session-expiry messages. Documentation homepages use the 「區」 seal.
- New Compose deployments require neither `ecoku.env` nor a log-directory mount. Logs default to standard output.

## Compatibility {#compatibility}

- Upgrading from v0.2.8 adds `admin_accounts` in the existing database and retains sites, comments, notification and CAPTCHA settings, the outbox, and released migration records. There is no downward migration.
- Keep the existing Compose file, YAML, and environment variables for the first upgrade. The existing username, bcrypt hash, and keys are imported into persistent state without forcing a password change.
- Legacy ports, database paths, static directories, file logs, YAML sites, and management keys retain compatibility paths. `admin.enabled: false` is ignored: the console is always enabled. The legacy session duration still accepts only 480 minutes or omission.
- `ecoku-secrets.json` lives beside the database, normally at `data/ecoku-secrets.json`. It must be a regular file with Linux mode 600. Do not lose or arbitrarily replace the notification encryption key.

## Historical upgrade notes {#upgrade}

This version is archived, with no installation or downgrade instructions. Restoring across schemas requires a complete cold backup matching the target version; changing an image alone is insufficient.
