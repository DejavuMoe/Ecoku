# v0.3.3

- Released: 2026-10-04
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.3.3`
- npm SDK: `ecoku@0.3.3`

## Changes {#changes}

- After [`admin reset-password`](../../reference/cli#admin-reset-password), the first sign-in setup page fills in the current username instead of always filling in `admin`. An administrator who renamed the account can reset the password and save without the name changing back to `admin`.
- The comment area no longer shows a 「回复」 (Reply) button on comments at depth 16. When the server rejects a reply that is too deep with `422`, the comment area shows 「回复层级已达上限，请回复较上层的评论。」 (Replies cannot nest any deeper here. Reply to a comment higher up.) instead of a generic submission error.
- The HTML loader supports [`data-i18n`](../../integration/html), so the embed code can set the comment language and override the site setting. The loader's own failure messages follow that language; without `data-i18n` they follow the page's `<html lang>`, and otherwise use Simplified Chinese.
- The documentation was checked against the source: it now covers the site 「评论区语言」 (Comment language) field and what `EcokuSite` site management credentials may do, and several descriptions that did not match the implementation are corrected.

## Compatibility {#compatibility}

- There is no database migration; the schema stays at v12. Compose, mounts, configuration keys and environment variables are unchanged.
- When signing in with a temporary password, the sign-in response and `GET /api/admin/session` carry an extra `username` field. Responses for normal sessions are unchanged.
- The loader's failure messages used to be always in Simplified Chinese. Websites whose `<html lang>` is English or Traditional Chinese now see messages in that language.
- Websites that host `ecoku-loader.js` themselves must replace `ecoku-loader.js` and `ecoku.umd.js` together for `data-i18n` and the new reply behavior to apply. Older loaders ignore `data-i18n`.

## Upgrade {#upgrade}

1. Stop the service and [cold-back up](../backup#cold-backup) the database, `ecoku-secrets.json`, Compose and configuration files.
2. Follow the [upgrade steps](../upgrade#steps), set the image to `ghcr.io/dejavumoe/ecoku:v0.3.3`, then run `sudo docker compose pull && sudo docker compose up -d`.
3. Check container health and admin sign-in, then open a post with comments and confirm the comment area loads.
4. After npm publication succeeds, update separately installed SDKs with `pnpm add --save-exact ecoku@0.3.3` and rebuild the website. The bundled SDK updates with the container image.

## Rollback {#rollback}

The schema is unchanged. Stop the service, set the image back to `ghcr.io/dejavumoe/ecoku:v0.3.2`, then pull and start it. No database restore is needed; comments and settings changed after the upgrade are kept. Older versions ignore any `data-i18n` you added to the embed code, and the comment area still loads.
