# v0.6.3

- Release date: 2026-11-24
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.6.3`
- npm SDK: `ecoku@0.6.3`

## Changes {#changes}

- The comment area shows "Powered by Ecoku" at the bottom right, with "Ecoku" linking to the documentation home in the comment area's language. It appears once the comment list has loaded, under the pager when there is one. The default style keeps it lighter than body text; adjust it with `.ecoku-powered-by`. See [Custom CSS](../../integration/custom-css).
- After sign-in, every admin page shows "Powered by Ecoku" and the running version centred at the bottom; the version links to its GitHub release. The sign-in page does not show the version.
- Admin session responses (`POST /api/admin/login`, `GET /api/admin/session`, `POST /api/admin/initial-setup`) gain a `version` field. See [HTTP API](../../reference/api).

## Compatibility {#compatibility}

- The schema stays at v12. When upgrading from v0.6.2, keep your existing data and configuration mounts, container user and healthcheck probe. Configuration keys are unchanged.
- The comment area gains a `.ecoku-powered-by` element after the comment list and pager. Blogs that use `ecoku.unstyled.css` or `data-css-url="none"` see an uncoloured credit line and can style it as needed.
- Images built from source without `ECOKU_VERSION` show `dev` in the admin.
- When upgrading from v0.5.7 or an earlier release, read the [distroless migration notes](../upgrade#distroless) and update the old Compose probe.

## Upgrade {#upgrade}

Follow the [upgrade steps](../upgrade#steps) to stop the service and take a cold backup. Set the image to `ghcr.io/dejavumoe/ecoku:v0.6.3`, then pull it and recreate the container. Confirm the container is `healthy`, sign in to the admin and check that the footer shows `v0.6.3`, then check existing comments and submission of a new comment. Sites that install the SDK from npm should update the dependency to `ecoku@0.6.3`.

## Rollback {#rollback}

Stop the service, set the image back to `ghcr.io/dejavumoe/ecoku:v0.6.2`, then pull it and recreate the container. Both releases use schema v12. Keep your existing database and healthcheck probe.
