# Upgrading to v0.2.3 (pending release)

Stop and verify a cold backup → set the exact image tag → `sudo docker compose pull && sudo docker compose up -d` → check health and application behavior, then roll back if needed.

Prepared on 2026-09-16. Await master CI acceptance and the subsequent tag release. Upgrade only after the image build is published.

## Fixes

- Saving site settings no longer grants blogger status retroactively. Passphrases are limited to 72 UTF-8 bytes; existing bcrypt hashes remain valid.
- SMTP has cancellation and time limits throughout delivery. Failed completion writes retry only the database operation. Telegram preserves complete links and HTML.
- Unordered Twikoo imports retain direct parents. Fixes cover Unicode input, admin cancellation, loader retries, Smoji URLs and keyboard use, and asynchronous widget cleanup.
- SPA hosts can call `setPageKey(pageKey, pageTitle)`; omitting the title clears the old one. Direct SDK hosts still load external CSS themselves.

## Compatibility

These audit fixes keep schema v7, mount paths, environment variables and bcrypt hashes unchanged; v0.2.2 can upgrade in place. No comments, configuration, WAL or backups are deleted. Saving site settings no longer backfills blogger flags; existing flags remain. Historical false flags cannot be distinguished automatically from verified comments and require separately reviewed, authorized correction. Notifications use at-least-once delivery: a completion-write failure retries the stored result without resending in the same process; a crash after sending but before persistence may cause a duplicate after restart.

## Upgrade steps

1. Follow [Backup and recovery](../backup): stop the service and verify an off-volume archive of `data/` (including WAL/SHM), `app/config.yaml`, `ecoku.env` and the original `compose.yaml`.
2. After image publication, set the Compose image to `git.via.moe/dejavu/ecoku:v0.2.3`. Keep configuration, environment variables and mounts unchanged.
3. Run the commands below, then check admin login, existing comments, blogger identity and notifications. Send real test notifications only as an explicit operator action.

```bash
sudo docker compose pull && sudo docker compose up -d
sudo docker compose logs --tail=100 ecoku
curl --fail --silent --show-error http://127.0.0.1:12123/api/health
```

## Rollback to v0.2.2

Both versions use schema v7. Normally, stop the service, restore image `git.via.moe/dejavu/ecoku:v0.2.2`, pull and start while retaining the current database and newer comments. This also restores the old audit defects. Restore the complete cold archive only when pre-upgrade data is needed: preserve the current state first and explicitly accept losing later writes. Never overwrite the database automatically.
