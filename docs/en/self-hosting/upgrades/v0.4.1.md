# v0.4.1

- Released: 2026-10-09
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.4.1`
- npm SDK: `ecoku@0.4.1`

## Changes {#changes}

- Remove global admin keyboard shortcuts and hints for comment navigation, opening original comments, deletion confirmation, refreshing and saving settings. Use the corresponding page buttons; basic keyboard operation of forms, menus and buttons remains available.
- Update the npm package README install example to `ecoku@0.4.1`, complete the SDK changelog and add release consistency checks.

## Compatibility {#compatibility}

- There is no database migration; the schema stays at v12. Admin URLs, HTTP APIs, sessions, configuration keys, environment variables, Compose mounts and container ports are unchanged.
- Existing comments, sites, admin accounts and settings are retained. Deletion confirmation and warnings before leaving unsaved settings remain in the existing interface.
- The comment SDK remains framework-free TypeScript, with runtime code unchanged from v0.4.0. Existing integration code needs no changes, and separately installed `ecoku@0.4.0` SDKs can still be used.

## Upgrade {#upgrade}

Follow the [upgrade steps](../upgrade#steps): stop the service, take a cold backup, change the image to `ghcr.io/dejavumoe/ecoku:v0.4.1`, then pull and start it.

Check container health, startup logs, comment loading and admin sign-in. Refresh the admin page and confirm that shortcut hints are gone and list and settings buttons are displayed normally. The bundled SDK updates with the image; separately installed SDKs can be pinned to `ecoku@0.4.1` after npm publication succeeds, followed by a website rebuild.

## Rollback {#rollback}

For an instance upgraded from v0.4.0, stop the service, change the image back to `ghcr.io/dejavumoe/ecoku:v0.4.0`, then pull and start it. The schema is unchanged, so no database restore is needed; comments and settings changed after the upgrade are kept. The old admin shortcuts and hints also return. Separately installed SDKs can be pinned back to `ecoku@0.4.0` before rebuilding the website.

If upgrading from an earlier version, first check that version's schema and rollback notes.
