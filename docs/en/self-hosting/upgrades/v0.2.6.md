## Changes

- The admin console uses the same paper-and-ink colours as the default comment styles (light and dark), with 6px / 3px corner radii. The UI font is now the operating system's own Chinese and Latin fonts; no web font is loaded.
- Site switching moves from the top bar to the top-left corner of **Comments** (评论管理). With only one site, the site name is shown directly. **Notifications** (通知设置) and **Security** (安全) no longer show a site selector.
- **Comments**: **View original comment** (查看原评论), **Tombstone delete** (墓碑删除) and **Permanent delete** (彻底删除) move to the top of the detail pane. A tombstone that still has replies shows 仍有回复，不能彻底删除 (it still has replies and cannot be permanently deleted). The delete confirmation names the target comment. The list gains loading and load-failure states, with a retry button on failure. The Up and Down arrow keys move between comments in the list.
- **Sites** (站点管理): the form is grouped into basic information, comment section, sticker pack and blogger identity. The save button stays fixed at the bottom; when validation fails, it shows how many fields need changes and moves focus to the first error.
- **Notifications**: encryption is now a choice between SSL/TLS and STARTTLS. A disabled channel collapses its fields. The always-checked **When a visitor gets a reply** (访客收到回复时) option is removed; visitor reply notifications still switch on and off with the email channel.
- The documentation site is rewritten from the source code. See the [upgrade guide](../upgrade) and the other pages.

## Compatibility

Config keys, environment variables, Compose mounts, the admin API and the database are all unchanged. You can upgrade in place from v0.2.5. The comment section and the SDK are not affected.

The admin page itself is not cached, so reloading after the upgrade shows the new interface. Admin tabs that are already open need to be reloaded once.

## Historical upgrade notes {#upgrade}

This version is archived, with no installation or downgrade instructions. Restoring across schemas requires a complete cold backup matching the target version; changing an image alone is insufficient.
