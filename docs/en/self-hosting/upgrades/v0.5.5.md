# v0.5.5

- Release date: 2026-11-09
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.5.5`
- npm SDK: `ecoku@0.5.5`

## Changes {#changes}

- Update `golang.org/x/net` to v0.62.0, fixing a quadratic complexity vulnerability that Twikoo import could trigger while parsing HTML (GO-2026-6860).
- Update build and test dependencies, including Happy DOM, the documentation dev server Vite and the SDK cleanup tool rimraf, to patched versions.
- Restructure internal state in the notification queue, admin session and SDK loader. External behavior is unchanged.

## Compatibility {#compatibility}

- There is no database migration; schema remains v12. HTTP APIs, configuration keys, environment variables, Compose mounts and container ports are unchanged. Records already in the notification queue are delivered as before.
- The security fix is in the server image, which needs to be updated. The SDK behaves the same as v0.5.4 and can be updated when convenient.
- When upgrading from a version older than v0.5.4, also read the [v0.5.4 compatibility notes](./v0.5.4#compatibility); for versions older than v0.5.2, also read the [v0.5.2 first sign-in notes](./v0.5.2#compatibility); for versions older than v0.5.0, also read the [origin conflict and existing data notes](./v0.5.0#compatibility).

## Upgrade {#upgrade}

Follow the [upgrade steps](../upgrade#steps): stop the service, make a cold backup, change the image to `ghcr.io/dejavumoe/ecoku:v0.5.5`, then follow the shared steps to pull the image, recreate the container and wait for health.

Check container health, startup logs, comment loading and submission, and admin sign-in. If notifications are enabled, post a test comment to confirm they still arrive. Upgrade each instance separately, including the server behind the documentation demo. Once npm publication succeeds, independently installed SDKs can be pinned to `ecoku@0.5.5` and their sites rebuilt; integrations using a pinned CDN version must also update their SDK URL.

## Rollback {#rollback}

For an instance upgraded from v0.5.4, stop the service, change the image back to `ghcr.io/dejavumoe/ecoku:v0.5.4`, pull and start it. The schema is unchanged, so no database restore is needed; new comments and settings are preserved. Pin the SDK back to `ecoku@0.5.4` and rebuild the site if needed. Rolling back reintroduces the dependency vulnerabilities fixed in this release; if upgrading from an older version, check its schema and rollback notes.
