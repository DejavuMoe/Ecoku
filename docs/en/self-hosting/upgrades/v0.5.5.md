# v0.5.5

This release's image did not pass the release gate, so there is no image to deploy. Keep using [v0.5.4](./v0.5.4) and do not change `image` to v0.5.5.

- Release date: 2026-11-09
- Schema: v12 (no migration)
- Image: not published
- npm SDK: `ecoku@0.5.5`

## Changes {#changes}

- Update `golang.org/x/net` to v0.62.0, fixing a quadratic complexity vulnerability that Twikoo import could trigger while parsing HTML (GO-2026-6860).
- Update build and test dependencies, including Happy DOM, the documentation dev server Vite and the SDK cleanup tool rimraf, to patched versions.
- Restructure internal state in the notification queue, admin session and SDK loader. External behavior is unchanged.

## Compatibility {#compatibility}

- There is no database migration; schema remains v12. HTTP APIs, configuration keys, environment variables, Compose mounts and container ports are unchanged.
- The image scan found high-severity vulnerabilities in musl and zlib in the runtime base system. No version tag was pushed, so `ghcr.io/dejavumoe/ecoku:v0.5.5` cannot be pulled.
- `ecoku@0.5.5` on npm behaves the same as `ecoku@0.5.4` and works with a v0.5.4 server. Sites pinned to `ecoku@0.5.4` need no change.

## Upgrade {#upgrade}

This release has no image upgrade path. Keep existing instances on v0.5.4 until the next fix release.

## Rollback {#rollback}

This release has no published container image, so no instance runs v0.5.5 and there is nothing to roll back. Sites that switched to `ecoku@0.5.5` can pin back to `ecoku@0.5.4` and rebuild.
