# v0.3.1

- Released: 2026-10-03
- Schema: v11 → v12
- Image: `ghcr.io/dejavumoe/ecoku:v0.3.1`
- npm SDK: `ecoku@0.3.1`

## Changes {#changes}

- The admin console and comment area support Simplified Chinese, Traditional Chinese and English. Set the admin language with `ECOKU_ADMIN_LOCALE`; each site stores its default comment language, which the SDK `i18n` option overrides.
- Documentation keeps these three languages and removes Japanese. The homepage selects a language from browser preferences, falling back to English. Demo comments follow manual theme changes.
- Article navigation and comment pagination no longer show a success notice. Page numbers remain announced to screen readers; posting confirmations and errors remain visible. Email branding and typography match the admin console.

## Compatibility {#compatibility}

- Adds `i18n_locale` to `sites`, defaulting existing sites to `zh-CN`. Comments, accounts, keys and notification settings are retained; no reinitialization is needed.
- The admin language defaults to `zh-CN`; alternatives are `zh-Hant` and `en`. Existing Compose files work without adding the variable.
- Comment language priority: SDK `i18n` → site setting → `zh-CN`. Custom text is preserved.
- There is no downward schema migration. v0.3.0 cannot open a database upgraded to v12.

## Upgrade {#upgrade}

1. Stop the service and [cold-back up](../backup#cold-backup) the database, `ecoku-secrets.json`, Compose and configuration files.
2. Follow the [upgrade steps](../upgrade#steps), set the image to `ghcr.io/dejavumoe/ecoku:v0.3.1`, then run `sudo docker compose pull && sudo docker compose up -d`.
3. Check container health, admin sign-in, existing comments, sites and notification settings; confirm migration to schema v12.
4. After npm publication succeeds, update separately installed SDKs with `pnpm add --save-exact ecoku@0.3.1` and rebuild the website. The bundled SDK updates with the container image.

## Rollback {#rollback}

Stop the service, set the image back to `ghcr.io/dejavumoe/ecoku:v0.3.0`, and [restore](../backup#restore) the database and persistent keys from the same pre-upgrade backup before restarting and checking the instance. Changing only the image tag is insufficient. Comments and configuration changes made after the backup will be lost.
