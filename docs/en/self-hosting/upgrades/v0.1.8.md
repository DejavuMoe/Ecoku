# v0.1.8

- Release date: 2026-08-27
- Schema: v6 → v7
- Image: `git.via.moe/dejavu/ecoku:v0.1.8`

## Changes

- A site can enable Smoji sticker packs with a remote v1 manifest URL. The manifest is loaded only when a visitor first opens the sticker picker. Sticker images are not bundled into the Ecoku image.
- In production, the manifest URL must use HTTPS, and sticker images must have the same origin as the manifest.
- A selected sticker is saved as plain text in the form `![smoji:name](full-image-url)`. When the feature is turned off, existing markers are displayed as they were written.

## Compatibility

Schema v7 adds two fields to the sites table, the Smoji switch and the manifest URL. Existing sites default to off. There are no new environment variables, config keys, mounts, or permission requirements.

## Upgrade

1. Stop the service and take a cold backup as described in [Backup and restore](../backup#cold-backup).
2. Follow the [upgrade steps](../upgrade#steps) and change the image to `git.via.moe/dejavu/ecoku:v0.1.8`. The database is migrated to v7 automatically on startup.
3. Check the comment section and the admin console.

## Rollback

Once the database has been migrated to v7, v0.1.7 cannot open it. To roll back, stop the service, [restore](../backup#restore) from the cold backup taken before the upgrade, and start v0.1.7. New data created after the backup is lost.
