# v0.5.0

- Release date: 2026-10-11
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.5.0`
- npm SDK: `ecoku@0.5.0`

## Changes {#changes}

- The comment composer updates preview and sticker controls and their accessibility labels to the site language. An explicit SDK language still takes precedence.
- After navigation in a single-page application, an old CAPTCHA result cannot submit a comment to the new article, and an old request cannot unlock a newer submission.
- Refreshing the same page, sorting, and pagination share request ordering, so stale responses cannot replace a newer list. Initial loading failures still show an error.
- While submitting, an open or delayed sticker picker cannot change the body being sent. Editing resumes after a failed submission.
- A loader executed before the DOM is ready retains its script address and loads the SDK from the same directory.
- Instance keys are written only after all key checks pass. Invalid initial settings or a failed signing-key rotation no longer write invalid state to the key file first.
- Twikoo imports retain valid descendants of orphaned or cyclic comments. The entire file must be one JSON array within 64 MiB, including trailing whitespace. HTML-to-text conversion preserves indentation, tabs, and internal blank lines inside `<pre>`. Imported content still appears as ordinary comment text, without code-block styling or syntax highlighting.
- Once SMTP confirms acceptance of the complete message, a failure to close the session no longer triggers another delivery. Saving and testing settings preserves leading and trailing password spaces; an empty password still keeps the stored value.
- Origin comparisons normalize default ports, leading zeros in ports, and equivalent IPv6 spellings, including previously stored origins. Startup checks for overlap between admin origins and every site's stored origins.
- A new database applies each YAML site seed's `i18n`, with schema creation, migrations, and seed writes in one transaction. Existing sites retain their stored language.
- Expired sessions during initial password setup or notification tests return to sign-in. Empty comment lists return to page 1. Retrying notification settings clears old errors while retaining errors from a partial failure in the current save.
- Tombstone deletion and repeated deletion return `has_children` based on actual direct replies, including deleted replies.
- The maintenance API smoke script logs in with a Cookie session and retries only explicit `429` responses, using bounded `Retry-After` waits.

## Compatibility {#compatibility}

- No database migration is added; the schema remains v12. The admin address, API paths, configuration keys, environment variables, Compose mounts, and container port are unchanged.
- Admin origins must be separate from every site's stored allowed origins. Before upgrading an instance with an overlap, correct the site origins in the existing console, or adjust the admin domain, origin configuration, and reverse proxy. The new version refuses startup on a conflict, and CLI subcommands that open the database also stop. See [applying configuration and origin checks](../../reference/configuration#reload).
- Existing comments, sites, administrator accounts, and settings are retained. Upgrading does not repair previously damaged key files, trimmed SMTP passwords, incorrect site languages, or imported reply relationships and text. Re-enter the correct SMTP password or change the site language in the console as needed. Check backups before planning a separate recovery of keys or imported data; do not delete keys or the database to retry an upgrade.
- Twikoo fixes apply only to future imports, which still require a site with no comments. Importing over existing comments is unsupported. Comment bodies remain plain text, without HTML or Markdown parsing.
- New site seeds take their language from YAML. Restarting or upgrading does not overwrite an existing site's language from YAML. Notifications still use at-least-once delivery: a crash after sending but before recording the result can still cause duplicates.
- Existing integration code remains compatible. The bundled SDK updates with the image; separately installed SDKs need an update and a website rebuild to receive the comment-section fixes.

## Upgrade {#upgrade}

Follow the [upgrade steps](../upgrade#steps): stop the service, make a cold backup, change the image to `ghcr.io/dejavumoe/ecoku:v0.5.0`, then run `sudo docker compose pull && sudo docker compose up -d`.

Check container health and startup logs, then verify comment loading, sorting, pagination, article navigation, and admin sign-in. If an SMTP password contains leading or trailing spaces, re-enter the complete password, save it, and send a test. Twikoo migration still requires a backup and a dry run before importing; see [the migration procedure](../twikoo).

After npm publication succeeds, pin a separately installed SDK to `ecoku@0.5.0` and rebuild the website. Update each instance's image separately, including the instance serving the documentation example.

## Rollback {#rollback}

For an instance upgraded from v0.4.1, stop the service, change the image back to `ghcr.io/dejavumoe/ecoku:v0.4.1`, pull, and start it. The schema is unchanged, so no database restore is needed and comments and settings added after the upgrade remain. Rolling back the program also removes these fixes. Separately installed SDKs can be pinned back to `ecoku@0.4.1` before rebuilding the website.

If upgrading from an earlier version, check its schema and the rollback instructions for that version first.
