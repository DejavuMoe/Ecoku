# Upgrading to v0.2.4 (pending release)

Stop and verify a cold backup → set the exact image tag → `sudo docker compose pull && sudo docker compose up -d` → health checks and rollback.

Prepared on 2026-09-16. CI acceptance and image publication are pending; this is not a deployment receipt.

CAPTCHA precedes blogger passphrase checks; logs contain route templates only; new level-17 replies are rejected; administrator sessions have a fixed eight-hour lifetime, survive reload/reopening and are revoked on logout.

## v0.2.4 compatibility (pending release)

Schema v8 adds `admin_sessions` and an expiry index without rewriting comments, settings or existing migration history. Previous logins expire and require a new login. Omit `admin.token_ttl_minutes` or set it to 480; other existing values prevent startup. Mounts, environment variables and password hashes remain unchanged. To roll back to v0.2.3 or earlier, stop the service, preserve the current state, then restore the complete pre-upgrade cold backup and original image. An old image alone cannot open a v8 database. Restoring a backup loses later writes and requires an explicit operator decision.

## Upgrade steps

1. Follow [Backup and recovery](../backup): stop the service and verify an off-volume archive containing `data/` (including WAL/SHM), `app/config.yaml`, `ecoku.env` and the original `compose.yaml`. Do not copy only a running SQLite main file.
2. Remove `admin.token_ttl_minutes` or set it to 480. Use HTTPS for production administration and preserve Origin and Cookie headers at the proxy. HTTP is limited to explicitly allowed loopback development origins.
3. After image publication, set the Compose image to `git.via.moe/dejavu/ecoku:v0.2.4` and run the commands below. Startup upgrades the existing database transactionally to v8; no manual SQL is needed.

```bash
sudo docker compose config --quiet
sudo docker compose pull && sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail=100 ecoku
curl --fail --silent --show-error http://127.0.0.1:12123/api/health
```

Health only confirms a responsive process. Check container health, existing comments, login restoration after reload/reopening and rejected access after logout. Do not generate attack requests or deep threads in production.
