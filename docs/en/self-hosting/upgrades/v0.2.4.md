This page preserves the tag, changes and historical upgrade notes. Public deployments start at v0.3.0; old images are no longer supported for deployment. Use the [current deployment guide](../docker).

- Release date: 2026-09-16
- Schema: v7 → v8
- Git tag: [v0.2.4](https://github.com/DejavuMoe/Ecoku/tree/v0.2.4)

## Changes

- Admin sign-in switches to an HttpOnly cookie plus a database session. A session lasts a fixed 8 hours after sign-in and survives reloads and closing and reopening the browser, but is not renewed. Signing out revokes the session on the server. The sign-in response no longer returns a token.
- CAPTCHA verification happens before the blogger passphrase is checked, so nobody can probe whether a passphrase is correct without passing verification.
- Access logs record only the route template and no longer write the actual path.
- New replies go at most 16 levels deep (a root comment is depth 0). Depth 17 is rejected. Existing deep comments are not affected.

## Compatibility

- Schema v8 only adds an admin sessions table and an expiry index. It does not change comments, config, or existing migration records.
- After upgrading, all admins need to sign in again.
- `admin.token_ttl_minutes` can only be omitted or set to `480`. Any other value in an old config causes startup to fail. Change it before upgrading.
- In production, the admin console must be accessed over HTTPS, and the reverse proxy must preserve the `Origin` request header and cookies. HTTP is allowed only for loopback development addresses.
- Mounts, environment variables, and the password hash are unchanged.

## Historical upgrade notes {#upgrade}

This version is archived, with no installation or downgrade instructions. Restoring across schemas requires a complete cold backup matching the target version; changing an image alone is insufficient.
