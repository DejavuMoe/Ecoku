- Release date: 2026-10-01
- Schema: v9 (unchanged when upgrading from v0.2.7)
- Git tag: [v0.2.8](https://github.com/DejavuMoe/Ecoku/tree/v0.2.8)

## Changes {#changes}

- The admin console groups comments by date and confirms deletion beside the comment. Settings use row-based fields, show the save bar only after an edit, and warn before leaving a page with unsaved changes. Keyboard shortcuts and bottom navigation on narrow screens are added. The admin console and documentation site use the 「區」 seal logo.
- Failed site saves keep unsaved drafts, including the name and blogger passphrase. When notification or security settings fail to load, the form is disabled and offers a retry.
- The official image supplies default paths for logs, comment assets, admin assets and SQLite, and enables the admin console by default. Omitted `*_env` fields use the standard environment variable names; omitted `admin.allowed_origins` uses the origin of `notifications.instance_public_url`. See [Configuration](../../reference/configuration) for the values.
- Deployment templates are shorter: `app/config.yaml` only needs `notifications.instance_public_url`; `ecoku.env` no longer repeats the image's `GIN_MODE`; Compose uses the Docker daemon's logging settings.

## Compatibility {#compatibility}

- Upgrading from v0.2.7 runs no database migration; the schema stays at v9. The comment section and SDK, HTTP API, Compose mounts and existing config keys are unchanged.
- Existing complete config files and Compose `logging` settings still work and do not need trimming. Explicit config takes priority over defaults. Keep the existing admin credentials, notification encryption key and data directory.
- The image's `ECOKU_RUNTIME=container` enables the container paths and default admin setting. Running from source keeps the previous path and admin defaults.
- v0.2.7 does not support the new minimal config. If you remove explicit settings during the upgrade, restore the complete config before rolling back.

## Historical upgrade notes {#upgrade}

This version is archived, with no installation or downgrade instructions. Restoring across schemas requires a complete cold backup matching the target version; changing an image alone is insufficient.
