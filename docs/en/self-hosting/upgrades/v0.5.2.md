# v0.5.2

- Release date: 2026-10-18
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.5.2`
- npm SDK: `ecoku@0.5.2`

## Changes {#changes}

- First startup no longer writes the administrator's temporary password to application logs. After initialization, stop the new instance and run `admin reset-password` to obtain a temporary password from the terminal, then start the service and set a permanent password on first sign-in.
- Add a security policy and private vulnerability reporting links. The dependency graph, Dependabot alerts and CodeQL are enabled; automatic dependency updates remain disabled.
- Release notes identify the image and npm SDK versions being published. Historical notes have been corrected to remove documentation SDK updates that were carried into the next release.

## Compatibility {#compatibility}

- There is no database migration; schema remains v12. APIs, configuration keys, environment variables, Compose mounts and container ports are unchanged.
- Administrators who already set a permanent password keep their account. Upgrading does not reset passwords or revoke existing sessions. SDK runtime code is unchanged from v0.5.1, and existing integrations remain compatible.
- First startup in v0.5.1 and earlier may have written a temporary password to logs. Upgrading alone does not invalidate it. If initial password setup is still incomplete, follow [obtain the temporary administrator password](../docker#temporary-password) to stop the service, reset the password and set a permanent one. Review access to log copies to avoid further credential exposure.
- When upgrading from a version older than v0.5.0, also read the [origin conflict and existing data notes](./v0.5.0#compatibility).

## Upgrade {#upgrade}

Follow the [upgrade steps](../upgrade#steps): stop the service, make a cold backup, change the image to `ghcr.io/dejavumoe/ecoku:v0.5.2`, then follow the shared steps to pull the image, recreate the container and wait for health.

Check container health, startup logs, comment loading and submission, and admin sign-in. Upgrade each instance separately, including the server behind the documentation demo. Once npm publication succeeds, independently installed SDKs can be pinned to `ecoku@0.5.2` and their sites rebuilt.

## Rollback {#rollback}

For an instance upgraded from v0.5.1, stop the service, change the image back to `ghcr.io/dejavumoe/ecoku:v0.5.1`, pull and start it. The schema is unchanged, so no database restore is needed; new comments, settings and reset passwords are preserved. Pin the SDK back to `ecoku@0.5.1` and rebuild the site if needed.

Rolling back restores the old startup behavior: a new database may again cause the initial password to be logged. Existing persistent accounts do not receive a new initial password on rollback. If upgrading from an older version, check its schema and rollback notes.
