# v0.6.2

- Release date: 2026-11-23
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.6.2`
- npm SDK: `ecoku@0.6.2`

## Changes {#changes}

- Replies in the default comment style now hang off tree connectors. Each reply at levels two to four joins its parent through a rounded elbow that turns into its own author line. The vertical line continues only while a later sibling reply follows, so the last reply ends on its elbow. Deeper replies still align with level four and name the comment they answer with "@nickname". The full-height guide line beside replies is removed.
- New `--ecoku-thread-*` variables adjust reply indentation and connectors. See [Custom CSS](../../integration/custom-css#variables).

## Compatibility {#compatibility}

- The schema stays at v12. When upgrading from v0.6.1, keep your existing data and configuration mounts, container user and healthcheck probe. Configuration keys, APIs and the comment DOM structure are unchanged.
- Only the default stylesheet `ecoku.css` changes. Blogs that use `ecoku.unstyled.css` or `data-css-url="none"` look the same.
- If your custom CSS overrides reply indentation or styles the old guide line (`.ecoku-comment-row::before`, `--ecoku-guide-offset`), check the comment area after upgrading.
- When upgrading from v0.5.7 or an earlier release, read the [distroless migration notes](../upgrade#distroless) and update the old Compose probe.

## Upgrade {#upgrade}

Follow the [upgrade steps](../upgrade#steps) to stop the service and take a cold backup. Set the image to `ghcr.io/dejavumoe/ecoku:v0.6.2`, then pull it and recreate the container. Confirm the container is `healthy` and check admin sign-in, existing comments and submission of a new comment. Sites that install the SDK from npm should update the dependency to `ecoku@0.6.2`.

## Rollback {#rollback}

Stop the service, set the image back to `ghcr.io/dejavumoe/ecoku:v0.6.1`, then pull it and recreate the container. Both releases use schema v12. Keep your existing database and healthcheck probe.
