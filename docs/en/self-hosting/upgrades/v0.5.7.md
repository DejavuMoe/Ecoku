# v0.5.7

- Release date: 2026-11-12
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.5.7`
- npm SDK: `ecoku@0.5.7`

## Changes {#changes}

- Public reads use a separate SQLite read-only connection pool and reuse list, site and challenge configuration results while the database is unchanged. Comment lists support `ETag` and conditional requests to reduce repeated reads.
- The HTML loader requests the SDK by its content hash and prefetches the first comment page while downloading the SDK.
- Fix lost drafts, restored old sort orders and missing new comments when sorting, pagination, same-page refreshes and reply submissions overlap. Same-page refreshes preserve collapsed comments, and clearing the editor also updates its preview.
- Admin timestamps and date groups use the instance `TZ`. When restoring a session, failed requests for language and time-zone configuration retry automatically.
- Update the SQLite driver and build/test toolchains. Fixed documentation diagrams use local SVGs, removing the Mermaid runtime and dependencies.

## Compatibility {#compatibility}

- There is no database migration; schema remains v12. Switching the SQLite driver does not change the database structure. Configuration keys, environment variables, Compose mounts and container ports are unchanged.
- `GET /api/admin/login-config` adds `timeZone`. The default remains `Asia/Shanghai`; instances configured with another `TZ` display admin timestamps and date groups in that time zone.
- When a reply has a draft, same-page refresh results wait until the reply closes, including refreshes after a root comment is posted. A successful submission replaces an older pending list request with a refresh that retains the pending page and sort selection.
- The image bundles the updated SDK. Sites integrating independently through npm or a pinned CDN version must also upgrade to `ecoku@0.5.7` to receive the client fixes. Existing HTML integration markup needs no change.
- When upgrading from a version older than v0.5.4, also read the [v0.5.4 compatibility notes](./v0.5.4#compatibility); for versions older than v0.5.2, read the [first sign-in notes](./v0.5.2#compatibility); for versions older than v0.5.0, also check the [origin conflict and existing data notes](./v0.5.0#compatibility).

## Upgrade {#upgrade}

Follow the [upgrade steps](../upgrade#steps): stop the service, make a cold backup, change the image to `ghcr.io/dejavumoe/ecoku:v0.5.7`, then pull the image, recreate the container and wait for health.

Check comment loading and submission, refreshing and changing sort while drafting a reply, admin sign-in and time display. If notifications are enabled, also confirm delivery. Upgrade every instance separately, including the server behind the documentation demo. Sites using the npm SDK independently should pin `ecoku@0.5.7` and rebuild; pinned CDN integrations should update their SDK URL.

## Rollback {#rollback}

For an instance upgraded from v0.5.6, stop the service, change the image back to `ghcr.io/dejavumoe/ecoku:v0.5.6`, pull and start it. The schema is unchanged, so no database restore is needed; new comments and settings are preserved. Independently installed SDKs can be pinned back to `ecoku@0.5.6` before rebuilding the site. Rolling back loses this release's race fixes, time-zone display and read optimizations. For upgrades from older versions, check their schema and rollback notes.
