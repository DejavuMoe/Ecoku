# v0.3.5

- Released: 2026-10-05
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.3.5`
- npm SDK: `ecoku@0.3.5`

## Changes {#changes}

- The admin console reserves scrollbar space when switching between Comments, Sites, Notifications and Security. This fixes horizontal page shifts caused by switching between short and long pages or loading data.

## Compatibility {#compatibility}

- There is no database migration; the schema stays at v12. Compose mounts, configuration keys and environment variables are unchanged.
- The fix affects only admin styles. HTTP APIs and the SDK runtime are unchanged from v0.3.4; separately installed `ecoku@0.3.4` SDKs can still be used.

## Upgrade {#upgrade}

1. Stop the service and [cold-back up](../backup#cold-backup) the database, `ecoku-secrets.json`, Compose and configuration files.
2. Follow the [upgrade steps](../upgrade#steps), set the image to `ghcr.io/dejavumoe/ecoku:v0.3.5`, then run `sudo docker compose pull && sudo docker compose up -d`.
3. Check container health. Refresh the admin console and switch between all four menus to confirm that the page no longer shifts horizontally when the scrollbar appears or disappears.
4. To keep SDK versions aligned, wait for npm publication to succeed, run `pnpm add --save-exact ecoku@0.3.5` and rebuild the website. The bundled SDK updates with the container image.

## Rollback {#rollback}

The schema is unchanged. Stop the service, set the image back to `ghcr.io/dejavumoe/ecoku:v0.3.4`, then pull and start it. No database restore is needed; comments and settings changed after the upgrade are kept. Rolling back removes this release's admin page shift fix. Separately installed npm SDKs can be pinned back to `ecoku@0.3.4` before rebuilding the website.
