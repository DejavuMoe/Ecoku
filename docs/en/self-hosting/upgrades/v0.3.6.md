# v0.3.6

- Released: 2026-10-06
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.3.6`
- npm SDK: `ecoku@0.3.6`

## Changes {#changes}

- Public comment lists skip empty child queries for leaf nodes, and admin lists reuse status counts while preserving sorting, pagination and read limits.
- Comment deletion is coordinated with final notification delivery, with state checked again before sending. Deleting a parent queues updates to already sent Telegram messages for direct replies, removing the parent quote while keeping the reply body.
- Login configuration, admin queries and the notification worker inherit cancellation. Cap IPv6 address checks are completed, and a failed key-file replacement preserves the previous file.
- Source runs listen on `127.0.0.1` by default. The development demo connects only to the local API.
- Docker stages and CI dependency installation are optimized. Base images are pinned by digest, and both release architectures receive runtime checks, an SBOM and vulnerability scanning.
- Vue is updated to `3.5.42` and `source-map-js` to `1.2.2` to fix high-severity vulnerabilities found by the dependency audit.

## Compatibility {#compatibility}

- There is no database migration; the schema stays at v12. Compose mounts, configuration keys, environment variables and container listening behavior are unchanged.
- Source mode no longer exposes the service to the local network by default. Container deployments keep their existing Compose ports and reverse proxy configuration.
- Deletion can wait for a notification already being sent to finish; each delivery has a 20-second deadline. Sent email cannot be recalled, and Telegram updates are asynchronous. See [After deleting a comment](../notifications#after-deletion) for the full limits.
- HTTP APIs and the production SDK remain compatible. Separately installed `ecoku@0.3.5` SDKs can still be used.

## Upgrade {#upgrade}

1. Stop the service and [cold-back up](../backup#cold-backup) the database, `ecoku-secrets.json`, Compose and configuration files.
2. Follow the [upgrade steps](../upgrade#steps), set the image to `ghcr.io/dejavumoe/ecoku:v0.3.6`, then run `sudo docker compose pull && sudo docker compose up -d`.
3. Check container health, startup logs, comment loading and admin sign-in. On instances with notifications configured, also check delivery and Telegram updates after deletion.
4. To keep SDK versions aligned, wait for npm publication to succeed, run `pnpm add --save-exact ecoku@0.3.6` and rebuild the website. The bundled SDK updates with the container image.

## Rollback {#rollback}

The schema is unchanged. Stop the service, set the image back to `ghcr.io/dejavumoe/ecoku:v0.3.5`, then pull and start it. No database restore is needed; comments and settings changed after the upgrade are kept. Separately installed npm SDKs can be pinned back to `ecoku@0.3.5` before rebuilding the website.

Rolling back removes this release's performance and security fixes. The older version cancels unfinished quote refresh tasks for replies that still exist. Before rolling back, confirm that any Telegram parent quotes you need removed have already been updated.
