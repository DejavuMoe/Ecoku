# v0.5.3

- Release date: 2026-10-19
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.5.3`
- npm SDK: `ecoku@0.5.3`

## Changes {#changes}

- The admin console is polished with no change in function: desktop navigation is centred; comments are grouped by full date without the weekday (October 18, 2026 in the English console). Deletion is confirmed on a card under the comment and can be cancelled with Esc; the CAPTCHA provider is chosen from three cards side by side; the remove button of each list item sits inside its input.
- The comment pagination buttons in the English and Traditional Chinese consoles no longer show Simplified Chinese.
- Test and documentation build dependencies are updated to fix known vulnerabilities; the operations, integration and first sign-in documentation in all three languages is corrected against the source.

## Compatibility {#compatibility}

- There is no database migration; schema remains v12. APIs, configuration keys, environment variables, Compose mounts and container ports are unchanged.
- Server and SDK runtime code is unchanged from v0.5.2, and existing integrations remain compatible. The admin changes are visual only; administrator accounts, sessions and settings are unaffected.
- When upgrading from a version older than v0.5.2, also read the [v0.5.2 first sign-in notes](./v0.5.2#compatibility); for versions older than v0.5.0, also read the [origin conflict and existing data notes](./v0.5.0#compatibility).

## Upgrade {#upgrade}

Follow the [upgrade steps](../upgrade#steps): stop the service, make a cold backup, change the image to `ghcr.io/dejavumoe/ecoku:v0.5.3`, then follow the shared steps to pull the image, recreate the container and wait for health.

Check container health, startup logs, comment loading and submission, and admin sign-in. Upgrade each instance separately, including the server behind the documentation demo. Once npm publication succeeds, independently installed SDKs can be pinned to `ecoku@0.5.3` and their sites rebuilt.

## Rollback {#rollback}

For an instance upgraded from v0.5.2, stop the service, change the image back to `ghcr.io/dejavumoe/ecoku:v0.5.2`, pull and start it. The schema is unchanged, so no database restore is needed; new comments and settings are preserved. Pin the SDK back to `ecoku@0.5.2` and rebuild the site if needed. If upgrading from an older version, check its schema and rollback notes.
