# v0.2.1

Stop and take a cold backup → change the exact image tag → `sudo docker compose pull && sudo docker compose up -d` → health and business checks.

## Upgrade impact

- SQLite remains at **schema v7**; no database migration.
- Environment variables, Compose mounts, ports, and container permissions are unchanged.
- Smoji limits are now 64 packs, 600 items per pack, 6,000 total items, and 1 MiB UTF-8; optional `base` templates are supported. Legacy manifests remain compatible.

## Upgrade

1. Stop the service and back up `data/`, `app/config.yaml`, `ecoku.env`, and the original `compose.yaml`.
2. Change the image to `git.via.moe/dejavu/ecoku:v0.2.1`.
3. Run `sudo docker compose config --quiet && sudo docker compose pull && sudo docker compose up -d`, then check logs, the health endpoint, and comments.

## Roll back to v0.2.0

Stop the service, restore the exact `v0.2.0` image tag, pull, and start. Both versions use schema v7, so the database normally need not be restored.
