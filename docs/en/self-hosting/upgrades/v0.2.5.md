# v0.2.5

- Release date: 2026-09-26
- Schema: v8, no migration
- Image: `git.via.moe/dejavu/ecoku:v0.2.5`

## Changes

- The default comment styles change to "paper and ink": identity fields are underlined fill-in lines, and the body is written directly on the posting card. Only one solid primary button remains; stickers, preview, cancel, and sort become text buttons. Corner radii are 6px / 3px. Times, collapse buttons, character counts, and page numbers use a monospace font. The blogger badge, link hover, and form errors use vermilion. The Cap widget keeps its official 260×58px size, and its frame radius follows the Ecoku variable.
- The default `--ecoku-*` variables are now declared with zero specificity. Set a variable with the same name on `.ecoku-comments` to override it; you no longer need to raise selector specificity. New variables for accent color, error color, radius, shadow, monospace font, and font size are added. See [Custom styles](../../integration/custom-css).
- `data-theme="auto"` no longer pins `color-scheme` and inherits it from the page instead. When a blog switches light/dark manually and it differs from the system setting, the comment section no longer shows inverted colors.
- On touch devices, input font size is at least 16px, so iOS does not zoom the page on focus.
- When Turnstile server-side verification receives an HTTP redirect, it is treated as the verification service being unavailable, and the request is rejected.

## Compatibility

Config keys, environment variables, Compose mounts, and the password hash are all unchanged. You can upgrade in place from v0.2.4. The comment section's DOM class names and text, and the SDK and loader interfaces, are unchanged.

Watch for these changes in appearance:

- On sites that use the default injected styles or `/client/ecoku.css`, the comment section's appearance changes with the image. Your existing override CSS may stack on top of the new defaults, so after upgrading, check it once in light mode and once in dark mode. High-specificity rules you wrote earlier to beat the default styles can be replaced with variables declared on `.ecoku-comments`.
- On sites where `data-css-url` points to their own stylesheet or is set to `none`, the appearance does not change.
- Files under `/client/` are cached for one hour, so some visitors may still see the old styles for a short time after the upgrade.

## Upgrade

Follow the [upgrade steps](../upgrade#steps) and change the image to `git.via.moe/dejavu/ecoku:v0.2.5`. After startup, open a few posts and check the comment section, reply box, and verification widget in both light and dark mode.

## Roll back to v0.2.4

Both releases use schema v8. Stop the service, change the image back to `git.via.moe/dejavu/ecoku:v0.2.4`, then pull and start. The existing database and comments posted after the upgrade are kept. The style changes and the Turnstile redirect fix are rolled back along with it.
