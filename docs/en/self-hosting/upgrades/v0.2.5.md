# Upgrading to v0.2.5

Stop and verify a cold backup → set the exact image tag → `sudo docker compose pull && sudo docker compose up -d` → check health, then roll back if needed.

Released on 2026-09-26.

The default comment style becomes "paper and ink", default `--ecoku-*` variables can be overridden directly by the host, `data-theme="auto"` follows the host's light/dark mode, and Turnstile server-side verification rejects HTTP redirects.

## Changes

- Default comment style: identity fields are ruled lines and the body is written directly on the composer card; there is a single solid primary button, while stickers, preview, cancel and sorting are text buttons; corner radii are 6px / 3px; timestamps, fold toggles, the character count and page status use a monospace font; the blogger badge, link hovers and form errors use a cinnabar accent. Cap keeps its official 260×58px geometry, and its frame radius follows the Ecoku variables.
- Default `--ecoku-*` variables are declared at zero specificity, so setting the same variable on `.ecoku-comments` overrides them. New variables cover the accent, errors, radii, shadow, monospace font and type sizes; see [Custom CSS](../../integration/custom-css).
- `data-theme="auto"` no longer pins `color-scheme`, so the comment area no longer inverts when a site's manual light/dark toggle differs from the system setting.
- Comment inputs on touch devices stay at 16px or larger so iOS does not zoom the page on focus.
- Turnstile Siteverify treats an HTTP redirect as an unavailable verification service and still fails closed.

## Compatibility

Schema stays at v8 with no new migration. Configuration keys, environment variables, Compose mounts and password hashes are unchanged, so v0.2.4 can upgrade in place. Comment DOM class names, copy, and the SDK and loader interfaces are unchanged.

For embedding sites:

- Sites using the injected default styles or `/client/ecoku.css` get the new look with the image. Existing override CSS may stack on top of the new defaults; check the comment area in light and dark mode after upgrading. High-specificity rules written only to beat the old defaults can become variable declarations on `.ecoku-comments`.
- Sites whose `data-css-url` points at their own stylesheet or is set to `none` keep their current look.
- `/client/` assets are cached for one hour, so browsers may briefly keep the old styles after the upgrade.

## Upgrade steps

1. Follow [Backup and recovery](../backup): stop the service and verify an off-volume archive of `data/` (including WAL/SHM), `app/config.yaml`, `ecoku.env` and the original `compose.yaml`.
2. Set the Compose image to `git.via.moe/dejavu/ecoku:v0.2.5` and run:

```bash
sudo docker compose config --quiet
sudo docker compose pull && sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail=100 ecoku
curl --fail --silent --show-error http://127.0.0.1:12123/api/health
```

3. Open an article on each embedding site and confirm the comment area, reply composer and verification widget in light and dark mode.

## Rollback to v0.2.4

Both versions use schema v8. Normally, stop the service, set the image back to `git.via.moe/dejavu/ecoku:v0.2.4`, pull and start while keeping the current database and newer comments; the comment styles and the Turnstile redirect fix revert with it. Restore the complete cold archive only when pre-upgrade data is needed: preserve the current state first and explicitly accept losing later writes. Never overwrite the database automatically.
