# v0.3.2

- Released: 2026-10-04
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.3.2`
- npm SDK: `ecoku@0.3.2`

## Changes {#changes}

- Site, notification and security settings in the admin console use boxed inputs, with fewer rules and underlines. Allowed origins, notification recipients and Telegram targets are edited one item per input: Enter adds the next item and several lines can be pasted at once. An item with a problem shows a note under it; an origin without a scheme or with a path can be corrected with one click, and duplicates are merged on save.
- The notification email header uses the 區 seal. The seal travels inside the email as an inline image and is not loaded from the network.
- The SDK `i18n` option now sets the comment text, the `lang` attribute and the Cap widget language, and is no longer overridden by the site language. English and Traditional Chinese comment areas show a matching message when CAPTCHA is not completed.
- The admin console keeps the `ECOKU_ADMIN_LOCALE` language after a reload, and previously untranslated English and Traditional Chinese copy is filled in. No focus ring appears when the console opens.

## Compatibility {#compatibility}

- There is no database migration; the schema stays at v12. Compose, mounts, configuration keys and environment variables are unchanged.
- The site API `i18n` field accepts only `zh-CN`, `zh-Hant` and `en` (plus regional forms such as `zh-TW` and `en-US`); other values return `400`. Previously they were changed to `zh-CN`. If scripts call the admin API, check the values they send.
- An invalid `ECOKU_ADMIN_LOCALE` still starts normally: the admin console uses `zh-CN` and the startup log says so.
- The HTML part of notification emails becomes `multipart/related`, and each email carries a 2.5 KB inline PNG. The plain-text version is unchanged.
- For websites that pass `i18n` when embedding, the comment area's `lang` attribute and the Cap widget language follow that option.

## Upgrade {#upgrade}

1. Stop the service and [cold-back up](../backup#cold-backup) the database, `ecoku-secrets.json`, Compose and configuration files.
2. Follow the [upgrade steps](../upgrade#steps), set the image to `ghcr.io/dejavumoe/ecoku:v0.3.2`, then run `sudo docker compose pull && sudo docker compose up -d`.
3. Check container health, admin sign-in, sites and notification settings. Send a test email and confirm the header seal is shown.
4. After npm publication succeeds, update separately installed SDKs with `pnpm add --save-exact ecoku@0.3.2` and rebuild the website. The bundled SDK updates with the container image.

## Rollback {#rollback}

The schema is unchanged. Stop the service, set the image back to `ghcr.io/dejavumoe/ecoku:v0.3.1`, then pull and start it. No database restore is needed; comments and settings changed after the upgrade are kept.
