# v0.2.0

Stop and take a cold backup → change the exact image tag → `sudo docker compose pull && sudo docker compose up -d` → health and business checks.

This release primarily corrects and expands documentation, integration examples, and API references (2026-09-12).

## Upgrade impact

- SQLite remains at **schema v7**; no database migration is added.
- Environment variables, Compose mounts, ports, container permissions, and runtime data formats are unchanged.
- Documentation for public comment-list budgets, cursor pagination, read limiting, and status codes is aligned with the v0.1.9 implementation.

## Upgrade

1. Check pages, comment lists, replies, and the admin console in an isolated environment.
2. Stop the service and back up `data/`, `app/config.yaml`, `ecoku.env`, and the original `compose.yaml`.
3. Change `compose.yaml` to the exact image `git.via.moe/dejavu/ecoku:v0.2.0`; preserve other settings.
4. Run:

   ```bash
   sudo docker compose config --quiet
   sudo docker compose pull && sudo docker compose up -d
   sudo docker compose ps
   sudo docker compose logs --tail=100 ecoku
   curl --fail --silent --show-error http://127.0.0.1:12123/api/health
   ```

5. Confirm the health endpoint, real comment lists, sorting, pagination, replies, and admin console.

## Roll back to v0.1.9

Stop the service, restore the exact `v0.1.9` image tag, pull, and start. Both versions use schema v7, so the database normally need not be restored; restore the full cold backup only for confirmed data problems.
