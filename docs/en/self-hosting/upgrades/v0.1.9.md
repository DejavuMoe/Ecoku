This page preserves the tag, changes and historical upgrade notes. Public deployments start at v0.3.0; old images are no longer supported for deployment. Use the [current deployment guide](../docker).

- Release date: 2026-08-31
- Schema: v7, no migration
- Git tag: [v0.1.9](https://github.com/DejavuMoe/Ecoku/tree/v0.1.9)

## Changes

This release fixes resource exhaustion in the public comment list (CWE-400):

- A single list request returns at most 200 comments, 16 levels of replies, and 1 MiB of JSON. When counting, at most 10,000 comments on the same page are checked. Exceeding any of these returns `422` instead of truncated data. Existing comment sections show that loading failed and do not switch to another read method automatically.
- New level-by-level reads: pass `parentId` / `afterId` to get one level of direct replies at a time, so custom frontends can load on demand. See [REST API](../../reference/api#cursor).
- List handling runs at most 4 requests at a time, and each database read is limited to 2 seconds. When busy or timed out, it returns `503`.
- New `rate_limit.comment_list`, defaulting to 60 requests per IP per 60 seconds. Exceeding it returns `429`. Browser preflight requests and requests with rejected origins also count.
- Each rate limiter tracks at most 10,000 IPs. When full, it rejects new IPs instead of evicting existing entries.
- After a SQLite connection is re-established, foreign keys, the synchronous level, and the busy timeout are enabled again. This is not a database migration.

## Compatibility

- Compose mounts, UID/GID, ports, logs, environment variables, and secrets are unchanged. You can upgrade in place from v0.1.8.
- If `rate_limit.comment_list` is not set, the default of 60 is used, so old configs start as they are.
- Lowering the number of root comments per page does not help when a single thread is too large or too deep, or when a page's total comment count exceeds the counting limit.
- If `trusted_proxies` is not configured correctly, all visitors behind the reverse proxy share one read quota. See [Reverse proxy](../reverse-proxy#trusted-proxies) to check.

## Historical upgrade notes {#upgrade}

Historical limitation: v0.1.8 does not recognize `rate_limit.comment_list`. Although both versions use schema v7, the older program rejects that unknown field at startup and lacks the public-list reading budgets introduced here.

This version is archived, with no installation or downgrade instructions. Restoring across schemas requires a complete cold backup matching the target version; changing an image alone is insufficient.
