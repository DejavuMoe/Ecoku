# v0.5.4

- Release date: 2026-10-23
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.5.4`
- npm SDK: `ecoku@0.5.4`

## Changes {#changes}

- If deletions remove the current last page, reloading the SDK loads the last valid page; deleting all comments resets the page to 1. Responses from requests made before navigation or destruction cannot overwrite the current page.
- `setPageKey()` handles article titles in the same way as initialization: it trims surrounding whitespace and keeps the first 200 UTF-16 code units, preventing an overlong title from causing submission to fail after navigation.
- When a JavaScript call omits `siteId`, the SDK reports an error before mounting or making a request.
- Fix the data race between initial administrator setup and concurrent reads of credentials and instance keys, with a corresponding race regression check.
- Update Vite, DOMPurify and the Go build toolchain to patched versions.

## Compatibility {#compatibility}

- There is no database migration; schema remains v12. HTTP APIs, configuration keys, environment variables, Compose mounts and container ports are unchanged, as are the storage formats for administrator accounts, instance keys and comments.
- The three frontend fixes require an SDK update; the initial setup concurrency fix requires a server image update. JavaScript integrations must provide a valid `siteId`; omitting it now produces an immediate error.
- When upgrading from a version older than v0.5.2, also read the [v0.5.2 first sign-in notes](./v0.5.2#compatibility); for versions older than v0.5.0, also read the [origin conflict and existing data notes](./v0.5.0#compatibility).

## Upgrade {#upgrade}

Follow the [upgrade steps](../upgrade#steps): stop the service, make a cold backup, change the image to `ghcr.io/dejavumoe/ecoku:v0.5.4`, then follow the shared steps to pull the image, recreate the container and wait for health.

Check container health, startup logs, comment loading and submission, and admin sign-in. Upgrade each instance separately, including the server behind the documentation demo. Once npm publication succeeds, independently installed SDKs can be pinned to `ecoku@0.5.4` and their sites rebuilt; integrations using a pinned CDN version must also update their SDK URL.

## Rollback {#rollback}

For an instance upgraded from v0.5.3, stop the service, change the image back to `ghcr.io/dejavumoe/ecoku:v0.5.3`, pull and start it. The schema is unchanged, so no database restore is needed; new comments and settings are preserved. Pin the SDK back to `ecoku@0.5.3` and rebuild the site if needed. Rolling back restores the behavior from before these fixes; if upgrading from an older version, check its schema and rollback notes.
