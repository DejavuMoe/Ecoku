# v0.5.1

- Release date: 2026-10-16
- Schema: v12 (no migration)
- Image: `ghcr.io/dejavumoe/ecoku:v0.5.1`
- npm SDK: `ecoku@0.5.1`

## Changes {#changes}

- Remove unused server configuration helpers, an unread log-path marker, and duplicate constant aliases while preserving existing configuration compatibility.
- Install only the Chromium headless shell for SDK browser tests in CI, retaining system dependency installation, browser tests, and all other verification steps.
- Use server-address and site-ID placeholders consistently in the integration documentation, and add Astro static-page and client-side routing examples.

## Compatibility {#compatibility}

- No database migration is added; the schema remains v12. APIs, configuration keys, environment variables, Compose mounts, the container port, and log-path behavior are unchanged.
- The SDK version follows the server release; its runtime code is unchanged from v0.5.0. Existing integrations remain compatible, with no application UI or site-setting changes required for this update.
- If upgrading from a version before v0.5.0, read the [v0.5.0 compatibility notes](./v0.5.0#compatibility), especially the requirements for admin and site origin conflicts and existing data.

## Upgrade {#upgrade}

Follow the [upgrade steps](../upgrade#steps): stop the service, make a cold backup, change the image to `ghcr.io/dejavumoe/ecoku:v0.5.1`, then run `sudo docker compose pull && sudo docker compose up -d`.

Check container health and startup logs, then verify comment loading, submission, and admin sign-in. Update each instance's image separately, including the instance serving the documentation example.

After npm publication succeeds, a separately installed SDK can be pinned to `ecoku@0.5.1` before rebuilding the website. The v0.5.0 SDK also remains compatible.

## Rollback {#rollback}

For an instance upgraded from v0.5.0, stop the service, change the image back to `ghcr.io/dejavumoe/ecoku:v0.5.0`, pull, and start it. The schema is unchanged, so no database restore is needed and comments and settings added after the upgrade remain. Separately installed SDKs can be pinned back to `ecoku@0.5.0` before rebuilding the website.

If upgrading from an earlier version, check its schema and the rollback instructions for that version first.
