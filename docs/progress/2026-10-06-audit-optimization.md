## P1：公共列表消融与构建边界 {#priority-one}

公共列表复用同一事务中已建立的父子关系，跳过已知叶节点的后代查询。仍保留逐父节点索引查询、排序、分页、删除占位、公共 DTO、10,000 个计数节点、200 个响应节点、16 层深度、1 MiB 响应、2 秒截止和 4 个准入槽位。没有新增缓存、批量排序或 schema。

固定时间戳与合成数据，采用 A1 → B → A2：A 为优化前列表实现，B 为复用关系的实现，三个阶段使用同一基准入口与工具链。每阶段、每种形状执行 5 组，每组 200 次，总计 12,000 次请求。表内耗时为各组 `ns/op` 的中位数，不是请求 P50。

| 合成数据 | A1（ms/op） | B（ms/op） | A2（ms/op） | 查询次数 A → B | 耗时下降范围 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 100 个叶节点，取 100 条 | 2.913 | 0.765 | 2.891 | 105 → 5 | 73.5%–73.7% |
| 1,000 个叶节点，取 100 条 | 3.504 | 1.413 | 3.616 | 105 → 5 | 59.7%–60.9% |
| 10,000 个叶节点，取 100 条 | 9.838 | 8.057 | 10.150 | 105 → 5 | 18.1%–20.6% |
| 1 个根加 199 个直接回复 | 5.673 | 1.489 | 5.837 | 205 → 6 | 73.7%–74.5% |

四种形状的响应 SHA-256 在 A1/B/A2 的全部样本中一致，观测请求全部成功；每请求分配量约下降 29.5%–77.0%。所有样本的数据库连接等待增量为 0。逐组耗时、P50/P95/P99、查询数、分配量及响应哈希保存在 [原始测量数据](./2026-10-06-public-list-ablation.csv)。小规模、单并发、临时 SQLite 夹具不能证明生产 P99、吞吐或 WAL 改善；本轮未据此扩大连接池。

可复用的基准命令在 `server/` 内运行：

```sh
go test -run '^$' -bench BenchmarkPublicList -benchtime=200x -count=5 ./handle/comment
```

Docker 将 Go 模块保存在可导出的普通依赖层，编译缓存仍使用 cache mount；避免新 builder 的空模块挂载遮住已恢复依赖。前端采用一个共享依赖阶段和两个同级 client/admin 构建阶段，减少源码变化相互失效。此处尚未得到新 builder 的缓存传输量或构建耗时对照，不作构建提速百分比承诺。

发布流程在每个架构按 digest 推送后，拉取同一 digest，运行容器契约检查、CycloneDX SBOM 和固定版本 Trivy 扫描，成功才导出 digest。失败阻止正式 tag manifest 和 GitHub Release；已经推送的按摘要镜像、并行 npm 发布不回滚。

- 已配置站点自动化密钥的回归覆盖同站点允许、跨站点拒绝、私有读取拒绝、永久删除拒绝和设置拒绝。
- Git 与 Docker 上下文排除嵌套环境、配置、密钥、数据库和备份；SDK 包契约检查通过。
- npm 恢复发布仅从 `master` 运行可信工作流，先核对 tag 不可变提交和原发布来源，再执行所选提交脚本。实际 verifier 由内存 GitHub 响应进行正反例测试。
- 文档发布拒绝嵌套文件链接、目录链接、悬空链接和特殊文件，保留锁、原子切换、旧流水线拒绝和上一版本。
- 密钥替换失败保留旧文件和有效密钥，取消“删旧文件后重试”路径。
- 空密码、超长密码和已取消请求在 bcrypt 前退出；格式正常的未知用户名仍执行密码比较。
- 未注册公共 API 在数据库 CORS 查询前拒绝；OPTIONS 保留原处理语义。
- source 模式默认监听 `127.0.0.1`；容器维持原监听契约。Cap 文档区分宿主 loopback 端口与反向代理公开管理入口。

这些项目作为可靠性或纵深防御改进，不因缺少最佳实践而升级为已证实漏洞。

## 实际构建与检查 {#validation}

本次遵从用户明确要求，在隔离环境内执行最终构建。Windows 保持唯一源码与 Git；Linux runner 仅启动可信监督程序，再由 Docker 沙箱执行目标代码。源代码、工具链和已有依赖只读，构建使用一次性副本；环境从空 allowlist 创建，网络关闭，HOME、临时文件和缓存均位于 scratch。未复制 `.git` 到构建副本。
