# 首次登录 v1（待审）

入口：[first-login-v1.html](./first-login-v1.html)。沿用已批准 v15 的登录布局、纸墨 token、系统字体和「區」标识。只扩展首次登录，不改变现有评论、站点、通知和安全页面；v15 仍是生产基线。

## 流程与状态

1. 启动后，以 `admin` 和日志中的临时密码登录。
2. 登录成功后必须设置新密码，用户名可以保留 `admin`。没有跳过按钮；未完成时不进入站点或评论管理。
3. 保存完成后临时密码失效，进入已有的创建站点流程。

原型场景覆盖输入校验、提交中、保存失败（保留输入）、会话过期（清空密码并返回登录）、完成。用户名上限沿用 80 字符；新密码提议至少 12 字符、最多 72 UTF-8 字节，不能等于临时密码，两次输入需相同。触屏输入至少 16px，键盘提交及错误聚焦可用。

原型使用内存中的模拟状态，不连接 API，不生成或保存真实凭据。密码不进入浏览器存储、URL 或控制台。原型场景与外观控制器不属于生产界面。首次登录时可用任意非空示例值演示跳转，生产必须核验密码。

## 后续实现边界（尚未实现）

- 仅全新实例生成随机临时密码，管理员名为 `admin`；日志只在生成时打印一次。数据库仅保存 bcrypt 哈希和必须改密的标记，不保存明文临时密码。
- 首次认证只能取得用于改密和退出的受限会话。所有管理 API 在服务端拦截未改密会话，不能只隐藏菜单。改密在一个事务内更新身份、撤销旧会话并换发正常会话；继续使用既有 Origin 检查、Cookie 属性和限流。
- 会话签名密钥与凭据加密主密钥自动生成一次，写入数据目录内仅容器用户可读写的文件；重启复用，备份包含整个目录。已有凭据却缺少主密钥时拒绝启动，不能自动生成新密钥替换。
- 现有实例导入原管理员凭据和原主密钥，不打印密码、不触发新建初始化。移除环境变量前，必须确认凭据已成功持久化且重启正常。
- 临时密码遗失时提供本机 CLI 重置入口，生成新的临时密码并撤销旧会话；不提供未认证的远程重置入口。
- 站点、博主、SMTP、Telegram 和人机验证继续在现有后台配置。实例公网地址和直连代理白名单仍需显式设置；不从不可信 Host 或转发头推断信任关系。
- 账号持久化需要新增顺序迁移，旧的 schema v9 与已发布迁移不改写。正式升级页需补充账号和密钥导入、备份及回滚要求；当前配置消融本身不改变 schema。

## 验收范围

布局：1440px、390px、320px，浅色与深色，键盘、窄屏和放大后的表单可达性。

交互：空输入、短密码、UTF-8 字节上限、确认不一致、临时密码复用、提交禁用、失败重试、过期返回登录、完成后创建站点。所有新增界面文案与流程均待审，未改变生产鉴权。

浏览器检查脚本为 `first-login-v1.test.mjs`，需要 Python 3、`playwright-core` 与已安装的 Chromium。在仓库根目录运行 `node designs/admin-moderation/first-login-v1.test.mjs`；默认截图写入被忽略的 `tmp/first-login-shots/`。可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定现有浏览器。脚本在本机回环地址启动临时预览，结束时关闭浏览器和预览服务。
